DATA-GUARD (памятка сессии). Любая работа с цифрами (дашборды, сверки, деньги, CRM, реклама, API, cron): сначала скилл `data-guard`.
Классы прошлых переделок, которые ловим до сдачи, а не правкой заказчика:
К1 метрика определена после кода · К2 числитель и знаменатель из разных популяций (>100%) · К3 период/TZ · К4 двойной учёт (разнесение, добор, дубли) · К5 сверка сама с собой · К6 API/поле не проверено до кода · К7 пропуск = 0, fail-open, перезапись окна · К8 бизнес-контекст не спрошен · К9 логика в копиях, правка HTML вместо билдера · К10 утверждение сильнее данных · К11 мерж без go ФЕНИКСА · К12 git/cron/снимки · К13 PII и мутации кабинета · К14 статистика.
Правила: до кода pre-mortem + вопросы заказчику с вариантом (рекомендую); спека метрики с подписью; probe источника; инварианты в билдере; «сошлось» только с двумя цифрами из разных семейств источников; слияние после go ФЕНИКСА; в конце задачи ретро в knowledge/errors/registry.jsonl.
Хуки data-guard предупреждают, не блокируют. Переопределение: DG_OVERRIDE="причина" в команде.
