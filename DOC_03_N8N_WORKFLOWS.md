## 1. Гуру-аналитик - `jroI8G9I3jicbqqE`

Вебхук: `POST /webhook/gengroup-ozon-analyst`

### Контракт запроса
```json
{
  "question": "сравни начало июня к маю, все направления",
  "sessionId": "hub-1718000000000-x7q2af",
  "curFrom": "2026-04-01", "curTo": "2026-04-30",
  "cmpFrom": "2026-03-01", "cmpTo": "2026-03-31"
}
```
- `question` - обязателен. Период парсится из текста, если явные диапазоны не заданы.
- `sessionId` - для памяти диалога (по умолчанию `default`).
- `curFrom/curTo/cmpFrom/cmpTo` - опциональны; если заданы, перекрывают парсер.

### Контракт ответа
```json
{
  "analysis": "1) ВЕРДИКТ ...",
  "period": "начало июн к началу май",
  "curFrom": "2026-06-01", "curTo": "2026-06-04",
  "data": { "cur": {...}, "cmp": {...} }
}
```

### Структура (8 нод)
```
Запрос аналитики (webhook)
  -> Параметры (Set: креды Seller+Performance, question, диапазоны, sessionId)
  -> Сбор оперативки (Code: парсер периода + авто-режим + живой сбор + сборка фактов)
  -> Guru (Agent V3) [подноды: Модель аналитика (lmChatOpenAi gpt-4o), Memory (memoryBufferWindow)]
  -> Сборка ответа (Set)
  -> Ответ (respondToWebhook)
```

### Что делает Code-нода "Сбор оперативки"
1. Парсит период из текста: "вчера", названия месяцев, модификаторы начало/середина/конец, конструкция "X к Y", дефолт - последние 7 дней против предыдущих 7. Окна делает равной длины, клампит снизу к `2026-02-01`, сверху к вчера.
2. Авто-режим: `fullMonth()` проверяет, совпадает ли текущее окно с целым закрытым месяцем (фев/мар/апр). Если да - строка РЕЖИМ "ЗАКРЫТЫЙ МЕСЯЦ" с чистой прибылью из карты CLOSED. Иначе - "ОПЕРАТИВНЫЙ" с запретом на прибыль.
3. Живой сбор: `analytics/data` по дню (тоталы) и по SKU (линии) для текущего и сравнительного окна; реклама Performance за объединённый диапазон, агрегируется по обоим окнам.
4. Собирает текст фактов: воронка с дельтами, реклама и ДРР, продажи по линиям, строка РЕЖИМ, блок сверки закрытых месяцев, вопрос пользователя.

### Память и авто-режим
- Память: `memoryBufferWindow` v1.3, `sessionIdType:"customKey"`, `sessionKey` из `Параметры.sessionId`, окно 10. Работает в пределах сессии.
- Авто-режим доказан: запрос "разбери апрель" -> режим P&L, чистая прибыль 3.84М `[ДАННЫЕ]`; "что по зеркалам за неделю" -> оперативный режим, прибыль не называется.

## 2. Товары (live SKU) - `pBZUSUqaBp2wUuaL`

Вебхук: `POST /webhook/gengroup-ozon-skus`

### Контракт запроса
```json
{ "days": 30 }
```
или
```json
{ "dateFrom": "2026-05-01", "dateTo": "2026-05-31" }
```

### Контракт ответа
```json
{
  "dateFrom": "...", "dateTo": "...", "generated_at": "...",
  "totals": { "rev","units","ret","canc","views","sk","oos","ad_spend","ad_drr" },
  "by_line": [ { "line","rev","units","ret","sk","ad_spend","ad_drr" } ],
  "sku_table": [ {
    "sku","name","line","rev","units","views","cart","deliv","ret","canc",
    "convCart","convOrd","retp","aov","offer","stock","pidx","pcol","oos"
  } ]
}
```

### Структура (4 ноды)
```
Запрос (webhook) -> Параметры (Set) -> Сбор SKU (Code) -> Ответ (respondToWebhook)
```

### Что делает Code-нода "Сбор SKU"
1. `analytics/data` с `dimension:["sku"]` -> на каждый SKU: оборот, штуки, показы, корзина, доставки, возвраты, отмены, конверсии, возврат %, AOV. Группировка по линиям.
2. Реклама Performance -> агрегат расхода/выручки по линиям и тоталу (ДРР по линиям ненадёжен, суммарный достоверен).
3. Склады (`/v4/product/info/stocks`) -> карта `sku -> offer_id` и остаток `present - reserved`.
4. Цены (`/v5/product/info/prices`) -> индекс цены `pidx` и цвет `pcol` по offer_id.
5. Обогащение каждого SKU полями `offer`, `stock`, `pidx`, `pcol`, `oos` (флаг "продаётся при складе 0"). Счётчик `totals.oos`.

## 5. Критичные паттерны n8n SDK (грабли, на которые уже наступали)

Эти правила нарушать нельзя - каждое стоило отладки.

1. **Имя ноды AI-агента - только ASCII.** Agent V3 строит ключ метаданных `response_<имя ноды в нижнем регистре>` и проверяет его на `A-Za-z0-9_`. Кириллическое имя ("Гуру") даёт runtime-ошибку `Custom date key can only contain characters`. Имя ноды агента должно быть латиницей (`Guru`). Остальные ноды могут быть кириллицей. Правило применять заново при каждом обновлении, потому что черновик кода легко возвращает кириллицу.

2. **jsCode внутри бэктиков - без бэктиков и без `${...}`.** Тело Code-ноды оборачивается в шаблонный литерал. Внутри не должно быть ни одного обратного апострофа и ни одной подстановки `${}`. Перевод строки делать через `String.fromCharCode(10)`, а не литералом.

3. **Регулярки с обратным слешем.** Чтобы в runtime получить `\s`, в исходнике писать `\\s` (два слеша). Ошибка в количестве слешей чаще всего безвредна (как в `num()`), но лучше держать `\\s`.

4. **Креденшл OpenAI разрешается автоматически.** В проекте заведён единственный openAiApi-креденшл. Он подхватывается в runtime нодой `lmChatOpenAi`, даже если в ответе обновления `autoAssignedCredentials` пустой и креденшл не виден в JSON ноды. Перезапись ноды через SDK не ломает привязку.

5. **Нет ключей Anthropic/Gemini.** Смена бренда модели на Claude/Gemini невозможна, пока в n8n не добавлен соответствующий ключ. После добавления - подмена ноды модели занимает пару минут.

6. **Предупреждения валидатора.**
   - `SET_CREDENTIAL_FIELD` на поле `apiKey` в Set-ноде - косметика (секрет в Set вместо креденшла), игнорируется, но это технический долг.
   - `INVALID_EXPRESSION_PATH` - валидатор видит только объявленный `output:[{...}]` ноды. Если нода в runtime возвращает поле, которого нет в объявленном образце, валидатор предупреждает. Лечится добавлением всех используемых полей в `output` (например, `sessionId` в Параметрах, иначе ругается Memory).

7. **Порядок развёртывания:** `validate_workflow` -> `update_workflow` (или `create_workflow_from_code`) -> `publish_workflow` -> тест боевого вебхука. Активная версия не меняется, пока не сделан publish.

## 6. Чек-лист переразвёртывания воркфлоу

1. Отредактировать `.ts` исходник ноды.
2. `validate_workflow` - убедиться `valid: true` (предупреждение по `apiKey` допустимо).
3. Проверить, что имя ноды агента латиницей (`Guru`).
4. `update_workflow` с тем же `workflowId`.
5. `publish_workflow`.
6. Тест: `curl` боевого вебхука с реальным телом, проверить ключевые поля ответа.
7. Для агента - проверить обе оси: авто-режим (закрытый месяц против оперативного) и память (два запроса с одним `sessionId`).
