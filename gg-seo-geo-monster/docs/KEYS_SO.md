# keys.so - интеграция

Аккаунт: тариф **Профессиональный**, лимит **3000 доменов/фраз в сутки**, оплачен
до 10.10.2026. keys.so закрыт из web-контейнера Claude (прокси режет), поэтому
живой сбор идёт в **GitHub Actions** с ключом-секретом. Паттерн как у Wordstat/OZON.

## Что делает интеграция

Скрипт `scripts/keyso.mjs` по списку доменов (`data/keyso-targets.json`) тянет из
keys.so и складывает в `data/keyso/<домен>/*.json`:

- **dashboard** - сводка домена (видимость, число запросов, трафик);
- **organic_keywords** - по каким запросам домен в топе;
- **competitors** - кто конкуренты домена по органике;
- **ads_keywords** - по каким словам домен крутит рекламу (Директ/РСЯ).

Для genglass.ru тянем все четыре; для конкурентов - сводку и органику. Данные
кормят SEO/GEO Монстра: находим упущенные запросы, конкурентов, чужую рекламу.

## Подключение (по шагам)

1. **Активировать REST API.** В кабинете keys.so («Данные и подписка») нажать
   **«Активировать REST API»** - появится ключ. Сейчас он не активирован.
2. **Скопировать ключ.**
3. **Секрет в GitHub.** Repo → Settings → Secrets and variables → Actions → New
   repository secret: имя `KEYSO_TOKEN`, значение - ключ из шага 2.
4. **Запуск.** Actions → «keys.so collect» → Run workflow:
   - сначала `dry_run = 1` (проверка коннекта, ничего не коммитит);
   - затем `dry_run = 0` - живой сбор, коммит в `data/keyso/`.
5. **Заполнить конкурентов.** В `data/keyso-targets.json` заменить слоты
   `ЗАПОЛНИТЬ-домен-…` на реальные домены конкурентов (Семён).

## Аутентификация

Ключ REST API кладётся в два заголовка: `X-Keyso-TOKEN` и `auth-token` (так делает
референс keyso-mcp). Скрипт это делает сам, значение берёт из `KEYSO_TOKEN`.

## Лимит и дисциплина

- Тариф даёт **3000 строк/сутки**. Сбор гоняем пачками, `per` (строк на отчёт)
  по умолчанию 100. Не гонять без нужды - лимит общий на аккаунт.
- При исчерпании лимита keys.so вернёт ошибку (402/403) - скрипт остановит цель,
  не зациклится.
- Цифры keys.so (частоты, позиции) - это `[ДАННЫЕ]` с датой замера и источником
  keys.so. Прогноз трафика из них - `[ГИПОТЕЗА]` (Protocol 9).

## Точность API (честно)

`apidoc.keys.so` закрыт для нашего робота, поэтому точные пути/параметры отчётов
(`/report/simple/domain_dashboard` и др.) и код региона (`base=msk`) сверяются на
первом живом 200. Всё это вынесено в один блок `REPORTS` в `keyso.mjs` и правится
env-переменными (`KEYSO_EP_*`, `KEYSO_DB`) без переписывания логики. DRY-режим
печатает точный URL - удобно сверить с апидоком после активации.

## Связь с «Трекером ИИ» keys.so и нашим AI Citation Tracker

В кабинете есть встроенный **«Трекер ИИ»** (видимость в ИИ-выдаче). Он - источник
данных для нашего модуля **AI Citation Tracker**: метрики (Prompt Win Rate, Share
of Model и др.) считаем по нашему канону (`knowledge/geo-intel-intake.md`), а
keys.so даёт по ним сырьё и позиции конкурентов. На след. шаге добавим отдельный
отчёт `ai_tracker`, когда сверим его эндпоинт.

## Wordstat vs keys.so

keys.so мощнее Wordstat (не только частота слова, а конкуренты, их страницы,
реклама, позиции, ИИ-видимость). Сборщик Wordstat (`scripts/wordstat.mjs`)
оставляем как дешёвый источник чистой частотности; keys.so - основной по конкурентам
и семантике. Оба льют в один проект.
