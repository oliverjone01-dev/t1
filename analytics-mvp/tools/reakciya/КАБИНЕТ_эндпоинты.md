# Снятие данных из кабинета Ozon

Всё, что ниже, выполняется в **активной вкладке** `seller.ozon.ru` в Chrome,
под живой сессией продавца. Своего API-ключа у нас нет, кабинет отдаёт данные
только по кукам, поэтому ни GitHub Pages, ни сервер сами это забрать не могут.

`company_id` берётся из куки `sc_company_id` (сейчас `3971004`).

## Жёсткие правила

- Кабинет только на чтение. Никаких изменений цен, ставок, кампаний, настроек.
- Всплывашку «Потеряли с вами связь» **не трогать**: ни «Продолжить», ни
  «Удалить черновик». Убирать узел из DOM через JS.
- Раздел `/app/advertisement/*` рендерится только когда вкладка **активна**
  (`document.visibilityState === 'visible'`). В фоновой вкладке `#__performanceApp`
  не монтируется и запросы не уходят. Подмена visibility после загрузки не помогает,
  проверка выполняется на монтировании.
- `charts/v3`: максимум 4 параллельных потока. В сентябре 387 быстрых запросов
  словили 403 на полчаса, и воронка встала на 09.09.
- Перед переходом на другую страницу состояние `window.__*` теряется. Складывать
  промежуточный результат в `localStorage`.
- Вынимать данные наружу: писать текст в `<pre>` на `seller.ozon.ru/robots.txt`
  (тот же origin) и читать оттуда.

## Эндпоинты

### Лог действий по рекламе
`POST /api/composer-api.bx/_action/performance/history/getAdLogEntities`
Отдаёт только 20 последних кампаний, параметры игнорирует.

`POST .../getActions` с `{entityType}` возвращает допустимый набор действий для вкладки.

`POST .../getAdLogHistory`
```json
{"dateFrom":"...","dateTo":"...","entityId":"...","entityType":"...",
 "actions":[...],"order":"AD_LOG_HISTORY_ORDER_ASC","page":1,"pageSize":100,"currentTab":1}
```
Окно дат режется примерно по 88 дней.

| что | entityId | entityType | actions | currentTab |
|---|---|---|---|---|
| оплата за клик | id кампании | `CAMPAIGN_SKU` | из `getActions` | 1 |
| оплата за заказ, все товары | `28753239` | `CAMPAIGN_ALL_SKU_PROMO` | `ALL_SKU_PROMO_ENABLED`, `ALL_SKU_PROMO_BID_CHANGE` | 2 |
| оплата за заказ, выбранные | `22421802` | `CAMPAIGN_SEARCH_PROMO` | `BID_CHANGE`, `ADD_PRODUCT_CAMPAIGN` | 2 |

Имена действий идут с префиксом `AD_LOG_ACTION_`.

### Товары и цены
`POST /api/v1/products/list-by-filter`
`{"company_id":<число>,"filter":{"visibility":"ALL"},"limit":100,"offset":0,"cursor":...}`
`company_id` здесь **в теле**. Отдаёт 515 item_id.

`POST /api/pricing-bff-service/v3/get-common-prices`
`{"company_id":<число>,"item_ids":[<не больше 50>]}`

`GET /api/v3/prices-history-get?item_id=&date_from=&date_to=&sort_dir=DESC&company_id=`
`company_id` здесь **в query**.

### Воронка
`POST /api/site/seller-analytics/charts/v3`
Метрик не больше 2, SKU не больше 4 за запрос. `company_id` **в теле не передавать**,
он идёт заголовком `x-o3-company-id`. Больше 4 потоков - 403 на полчаса.

## Что считается из чего

- Соинвест = (предельная цена − цена на витрине) / предельная цена.
  `marketing_seller_price` предельная, `marketing_price` витрина, `marketing_oa_price` с картой Ozon.
- Списание за заказ = ставка × предельная цена. Проверено на трёх днях списаний.
- Эффект действия = метрика затронутых SKU за 7 дней до против +1/+3/+7 после,
  минус такое же изменение по магазину за те же дни. Позиция и соинвест медианой
  в пунктах, показы, карточка и заказы суммой в процентах.
  Для действий по всему магазину контроля нет, ставится флаг `nc:1` и пометка «без контроля».
