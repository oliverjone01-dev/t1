# Целостность сборщиков OZON, 21.10.2026

Область согласована Иваном: «проверь все ли выгрузки правильно работают», затем «делай».
Определения денег, gross/net, даты операций, модели атрибуции и округления не меняются.
Это исправление доставки существующих метрик, а не новая метрика.

Pre-mortem: E027/К7 (fail-open), E018/К6 (лимиты), К12 (данные бота только main).
До кода изолированными прогонами настоящих сборщиков воспроизведены:
- ad-sku: HTTP 503 удаляет единственную старую строку и продвигает state, exit 0;
- acq и pnl: ошибка второго дня заменяет двухдневный файл однодневным, exit 0;
- sku-views: ошибка 19.10 и успех 20.10 оставляют дыру, следующий прогон её не запрашивает.
Доказательства сохранены локально в ozon-refresh-2026-10-21/collector-failure-probes.json.

Контракт исправления:
1. Ошибка запроса/статуса/скачивания/формата не равна валидному пустому CSV.
2. Неуспешная кампания не получает новый checkpoint; её старые строки сохраняются.
3. Async-отчёты последовательны, окно максимум 60 дней; бюджет переносит очередь.
4. Атрибуция: checkpoint по кампании, первичная проверка последних 55 дней,
   затем повтор последних 7 дней для поздних поправок. Ошибка не двигает checkpoint.
5. Дневная аналитика: восстанавливать отсутствующие даты и повторять последние 7 дней;
   успешный пустой день хранить отдельно от отсутствующего. Запись после всех запросов.
6. Финансовые файлы разных гранулярностей составляют полный пересбор с 06.02.2026;
   короткий FROM запрещён, ошибка любого дня/справочника оставляет все файлы прежними.
7. Непустой старый срез не заменять пустым без отдельного исследования ответа.
8. Данные вне заявленного окна сохраняются; JSON строгий, ключи уникальны, числа конечны.
9. CPO без SKU API не входит в знаменатель покрытия CPC; неизвестная ошибка не считается CPO.
10. Снимок CPO от 17.09 не доказывает ноль позиций сегодня. Ручные CPO и доставка
    показывают фактическую последнюю дату, без обещания автоматического восстановления.

Эталон регрессии: две старые строки 19/20.10 + сбой 20.10 -> обе остаются побайтно;
кампания A успешна, B неуспешна -> checkpoint B прежний, повтор включает B;
повтор успешного окна -> прежнее число уникальных ключей; пустой сломанный CSV -> ошибка.
Проверка целостности не является независимой финансовой сверкой с банком/документом.
Перед слиянием обязательны тесты, self-check 25 и независимый ФЕНИКС на хеш изменений.
