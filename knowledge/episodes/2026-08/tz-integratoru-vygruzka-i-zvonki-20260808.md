# ТЗ интегратору: регулярная выгрузка диалогов и транскрибация звонков

**Дата:** 08.08.2026
**Основание:** решения Ивана от 08.08.2026, вопросы 14 и 15.
**Сроки от Ивана:** автоматическая выгрузка диалогов к **11.08.2026**, ТЗ на транскрибацию звонков к **13.08.2026**.
**Заказчик:** Иван Раюшкин. **Исполнитель:** интегратор Bitrix24.
**Зачем:** сейчас разбор качества работы с клиентами держится на ручной выгрузке xlsx. Ручной шаг в регулярном процессе умирает на третьей неделе, и вместе с ним умирает вся аналитика поверх него.

---

## Часть 1. Регулярная выгрузка диалогов, срок 11.08.2026

### Что есть сейчас

Разовая выгрузка `deals.xlsx`: 37 095 строк сообщений по 689 сделкам воронки C49 за 01.04.2026 - 31.07.2026. Сделана руками, повторить в том же виде нельзя.

Три дефекта этой выгрузки, которые надо закрыть в автоматической:

| Дефект | Что это стоило | Что нужно |
|---|---|---|
| Направление сообщения не выражено полем | Восстанавливали по маркерам Wazzup «Отправлено»/«Принято» и по совпадению имени с ростером. 2 985 сообщений (8%) остались в корзине `unknown` | Явное поле `direction` со значениями `in` / `out` |
| Отправитель не выражен полем | Автор восстанавливается из текста комментария ленты. Самопредставление «меня зовут X» в чужой сделке не разбирается вообще | Явное поле `sender_id` (ID пользователя Bitrix) на каждое сообщение |
| Контакт сделки отсутствует | `CONTACT_ID` и `COMPANY_ID` в снимке пустые, клиента опознаём по названию сделки. Прокси покрывает 9% сделок | `CONTACT_ID`, `COMPANY_ID` в выгрузке сделки |

### Контракт данных

Одна строка на сообщение, JSONL или CSV в UTF-8:

| Поле | Тип | Обязательно | Комментарий |
|---|---|---|---|
| `deal_id` | int | да | ID сделки Bitrix |
| `msg_id` | string | да | Уникальный ID сообщения, для дедупликации между прогонами |
| `at` | ISO 8601 с таймзоной | да | Время сообщения. Сейчас таймзона нигде не проставлена |
| `direction` | `in` \| `out` | да | Не выводить из текста. Поле обязательное |
| `sender_id` | int | да для `out` | ID пользователя Bitrix, а не имя строкой |
| `channel` | `wazzup` \| `email` \| `call` \| `comment` | да | Сейчас каналы перемешаны в одной ленте |
| `text` | string | да | Пустая строка допустима, если сообщение это только вложение |
| `attachments` | int | да | Число вложений. 3 155 исходящих из 12 607 были вложениями без текста, и без этого поля они портили знаменатель всех текстовых метрик |
| `call_duration` | int, секунды | для `channel=call` | |
| `call_recording_url` | string | для `channel=call` | Ссылка на запись, см. часть 2 |

Выгрузка сделок отдельным файлом, поля: `deal_id`, `category_id`, `stage_id`, `assigned_by_id`, `contact_id`, `company_id`, `opportunity`, `date_create`, `closedate`, `is_lost`, `lost_reason`.

### Регламент

- Ежедневно, ночью, инкрементально по `msg_id`.
- Полный перезалив по запросу за произвольный период.
- Складывать туда же, где живут снимки Bitrix (`b24-snapshots.yml`, ветка `rop-dashboard-v1`), в том же формате доставки.
- Ошибка выгрузки видна: пустой или укороченный файл не должен молча заменять предыдущий.

### Критерий приёмки

1. Прогон за любые три дня даёт файл, в котором доля `direction=unknown` равна нулю.
2. `sender_id` заполнен у 100% исходящих.
3. Повторный прогон за тот же период не создаёт дублей по `msg_id`.
4. Скрипт `dialogs-normalize.py` отрабатывает без эвристик восстановления направления, они удаляются из кода после приёмки.

## Часть 2. Транскрибация звонков, ТЗ к 13.08.2026

### Почему это отдельная работа

За период в выгрузке **193 звонка**, и по ним есть только длительность и номер. Значительная часть работы отдела происходит голосом и в разбор не попадает вообще. Любой вывод вида «менеджер не отработал возражение» сегодня опровергается фразой «я это проговорил по телефону», и опровергается справедливо.

Пока звонков нет в разборе, в каждом кабинете стоит явная оговорка «система не видит звонков». Снять её можно только транскрибацией.

### Что нужно решить в ТЗ

| Вопрос | Варианты | Кто решает |
|---|---|---|
| Где хранятся записи | Bitrix телефония, внешняя АТС, оба источника | Интегратор, фактом |
| Провайдер распознавания | Yandex SpeechKit, Salute Speech, self-hosted Whisper | Иван по цене и по требованию не выпускать записи за периметр |
| Диаризация | Нужно разделение реплик менеджера и клиента | Требование: нужно. Без ролей транскрипт нельзя разобрать теми же детекторами |
| Правовое основание | Уведомление клиента о записи, согласие сотрудника | Юрист, тот же, кто визирует правовой раздел платформы |
| Объём | 193 звонка за 4 месяца это оценка снизу, реальный поток надо померить | Интегратор, фактом за неделю |

### Контракт транскрипта

| Поле | Комментарий |
|---|---|
| `call_id`, `deal_id`, `at`, `duration` | Связь со сделкой обязательна, иначе транскрипт не соединяется с разбором |
| `speaker` | `manager` \| `client` на каждую реплику |
| `text` | Реплика |
| `confidence` | Уверенность распознавания. Реплики ниже порога не идут в детекторы |

### Критерий приёмки

1. Ручная сверка 20 звонков: смысловые ошибки распознавания не меняют вывод детектора.
2. Роли разделены верно не менее чем в 18 случаях из 20.
3. Транскрипт соединяется со сделкой автоматически, без ручного шага.

### Порядок работ

Транскрибация ставится **после** приёмки части 1. Причина: без регулярной выгрузки текстовых диалогов транскрипты некуда складывать, а связка «звонок плюс переписка по одной сделке» это и есть весь смысл работы.

## Что этим не закрывается

- Калибровка порогов детекторов на исходах сделок. Это наша работа, не интегратора.
- Ручная проверка 23 детекторов по 30 случаев каждый. Тоже наша.
- Поля «Дата решения клиента» и «Дата следующего контакта» в карточке сделки. Отдельная задача интегратору, без них стадия «Принимают решение» не может работать по правилу «нет даты, нет стадии».

## Открытые риски

- **Срок 11.08 при выдаче ТЗ 08.08** оставляет интегратору три дня, из них один выходной. Если приёмка по критериям не проходит, честнее сдвинуть дату, чем принять выгрузку с `direction=unknown` и вернуться к эвристикам.
- **Правовое основание транскрибации** может оказаться дольше техники. Начинать разговор с юристом стоит одновременно с ТЗ, а не после сдачи.
