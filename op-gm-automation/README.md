# Автоматизация ОП ГМ

Проект автоматизации отдела продаж ГМ. Живёт в отдельной ветке `op-gm-automation-v1`
и публикуется на отдельный URL, не задевая остальной сайт GENGROUP.

## URL

- Бой: `https://oliverjone01-dev.github.io/t1/op-gm/`

## Как устроена публикация

По образцу `/rop/`, `/prod/` и `/office/` (см. `.github/workflows/deploy-pages.yml`):

1. Контент проекта лежит в этой ветке (`op-gm-automation-v1`), папка `op-gm-automation/public/`.
2. Шаг `Build OP-GM automation (isolated, /op-gm/)` в `deploy-pages.yml` (в main) забирает
   ветку через `git fetch` + `git worktree` и копирует `public/` в `_site/op-gm/`.
3. Шаг обёрнут в `continue-on-error: true` - поломка проекта не валит остальной сайт.

Деплой срабатывает при каждом запуске `deploy-pages.yml` (push в main, ночные синки,
ручной workflow_dispatch). Чтобы выкатить свежие правки этой ветки без ожидания -
Actions → "Deploy to GitHub Pages" → Run workflow.

## Структура

```
op-gm-automation/
  README.md          - этот файл
  public/
    index.html       - сайт: открытая оболочка (код, стили) + зашифрованные данные
  src/               - исходники сборки (без данных и без пароля)
    build_av.py      - слой данных из выгрузок Авито API: чаты, сообщения, детекторы проблем
    av.app.js        - разделы на данных API: Сегодня, Пульс ОП, аналитика, диалоги
    av.css           - стили этих разделов
    build.cjs        - сборка: вставляет код в оболочку, сжимает и шифрует данные
```

## Разделы (v4, сентябрь 2026)

Навигация спроектирована СПАРТАКОМ под две роли:

- **Сегодня** - очередь менеджера: кому ответить в первую очередь (не ответили, клиент написал последним,
  спросили цену без суммы). Крупный шрифт, одна колонка, кнопка «Открыть в Авито».
- **Пульс ОП** - экран РОПа: скорость первого ответа, неотвеченные, брошенные, цена, звонки,
  гарантия, матрица «объявление x проблема». Каждая цифра открывает список диалогов.
- **Аналитика Авито** - скорость (по месяцам, распределение, тепловая карта час x день недели),
  типовые проблемы с правилом поиска, объявления, звонки, холодная рассылка.
- **Все диалоги** - фильтры: кабинет, период, тип, объявление, проблема, отметки, поиск; переписка целиком.
- **Откуда цифры** - источники, сверка JSON и CSV, правила детекторов, что исправлено против скриншотов.
- **Архив** - разделы v3 по 561 скриншоту июля, оставлены для сравнения с плашкой «устарело».

Вложенность сущностей: Кабинет › Период › Объявление › Диалог › Сообщение или звонок.
Сквозные: тип диалога, проблема, клиент.

Кабинеты: **OLD-G** - старый аккаунт «GLASS MEMORY», **NEW-B** - новый аккаунт «Glass Memory».

## Как пересобрать с новой выгрузкой

1. Положить свежие `*-raw-*.json` и CSV обоих кабинетов, поправить пути в `src/build_av.py`, запустить его.
2. `OPGM_PW=<пароль> node src/build.cjs` - пароль передаётся только через переменную окружения
   и в репозиторий не попадает.
3. Перед публикацией: сверка цифр с независимым пересчётом и Step 12.5 (ФЕНИКС).

Данные в открытом виде (выгрузки, `av.json`) в репозиторий не коммитятся: там имена и телефоны клиентов.

## Правила

- Вся разработка проекта - в ветке `op-gm-automation-v1`, не в main.
- Статика self-contained: без внешних CDN, данные запекать в HTML или класть рядом в `public/`.
- Перед публикацией содержательных артефактов - Step 12.5 (ФЕНИКС), как для любого критического деливерабла.
