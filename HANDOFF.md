# HANDOFF - передача проекта коллеге (памятка-чеклист)

Пошаговая инструкция, как передать проект другому человеку в **его собственный
GitHub-репозиторий** так, чтобы он развивал его **своим Claude** и всё работало
автономно (сбор данных, сборка сайта, публикация) - без участия исходного владельца.

Язык - простой, по шагам. Идти сверху вниз, ставить галочки.

---

## ⚠️ Прочитать первым - про ключи
**GitHub НЕ показывает значения уже введённых секретов - даже владельцу.**
Их можно только перезаписать, но не «скачать» и не «скопировать».

Поэтому «передать со всеми ключами» автоматически нельзя. Нужны **исходные
значения** ключей (из кабинетов OZON, Яндекса, банка и т.д.):
- если они где-то записаны - просто введёте их заново у коллеги;
- если лежат **только** в GitHub - их придётся **перевыпустить** в кабинетах
  сервисов (в кабинете «сгенерировать новый ключ» - обычно 1 минута).

---

## ⚠️ Прочитать вторым - про объём передачи (важно!)
Этот репозиторий вырос и хостит **много разных дашбордов** (OZON-аналитика,
Яндекс.Директ, РОП/продажи из Bitrix24, SEO, банк «Точка», Экономика сделок,
GG Sales Academy и др.). В нём есть и **чувствительные разделы** - в частности,
запечатанные (зашифрованные) кабинеты менеджеров с персональными данными
(`gg-sales-academy/sealed/`).

Реши заранее, **что именно передаёшь**:
- **(A) Весь репозиторий целиком** - коллега получает всё, включая чужие
  дашборды и запечатанные персданные. Требует согласования (это ПД сотрудников).
- **(B) Только OZON-аналитику** (папка `analytics-mvp/` + её воркфлоу) -
  чистая передача только твоего дашборда, без чужих данных. **Рекомендуется**,
  если коллеге нужен именно OZON-дашборд.

Ниже инструкция подходит для обоих; отличия помечены **[A]** / **[B]**.

---

## Из чего состоит «передать проект» (3 части)
1. **Код** - лежит в GitHub, копируется целиком.
2. **Ключи** - хранятся отдельно, в «сейфе» GitHub (Secrets), вводятся заново вручную.
3. **Включатели** - Actions (робот-будильник для сбора данных) и Pages (витрина сайта).

Claude - только помощник-мастер. Проект он не хранит. Коллега подключит
**свой** Claude к **своему** репозиторию.

---

## Шаги

### ☐ Шаг 1. У коллеги есть аккаунт GitHub
Если нет - завести на github.com (бесплатно). Нужна и **своя подписка Claude**,
чтобы его Claude имел доступ к его репозиторию.

### ☐ Шаг 2. Скопировать проект к коллеге
**[A] Весь репозиторий - способ «Import»:**
1. Открыть **github.com/new/import**
2. В «старый адрес» вставить: `https://github.com/oliverjone01-dev/t1`
3. Придумать имя нового репозитория, выбрать **Private** (приватный).
4. «Begin import» - GitHub скопирует весь код с историей (пара минут).

**[B] Только OZON - способ «чистая копия папки»** (делает исходный владелец
или технический человек, разово):
1. Коллега создаёт пустой репозиторий (Private).
2. Из папки `analytics-mvp/` и нужных воркфлоу (`ozon-snapshots.yml`,
   `deploy-pages.yml`) собирается отдельный проект и заливается в его репо.
   (Это одноразовая ручная операция - попроси помочь того, кто ведёт проект.)

### ☐ Шаг 3. Включить «робота» (Actions)
В новом репозитории: **Settings → Actions → General → Allow all actions → Save.**

### ☐ Шаг 4. Внести ключи (сейф)
**Settings → Secrets and variables → Actions → New repository secret.**
Добавлять **по одному**: слева имя, справа значение → Add. Список - в конце памятки.

### ☐ Шаг 5. Включить «витрину» (Pages)
**Settings → Pages → Source: GitHub Actions → Save.**
Новый адрес сайта: `https://<логин-коллеги>.github.io/<имя-репо>/`

### ☐ Шаг 6. Заменить личные ссылки владельца
В проекте есть ссылки на **Google-таблицы** исходного владельца (конкуренты,
склейки карточек). Коллеге нужно либо получить к ним доступ, либо подставить
свои. Где именно - подскажет Claude, когда дойдёте.

### ☐ Шаг 7. Первый запуск - проверка ключей
**Actions → «OZON snapshots» → Run workflow.** Через ~15 мин смотрите лог:
верные ключи → данные соберутся; неверные → в логе видно, какой ключ не подошёл.
Потом так же запустить **«Deploy to GitHub Pages»**.

### ☐ Шаг 8. Подключить Claude коллеги
Коллега в своём Claude (claude.ai/code) → «подключить GitHub» → выбирает свой
новый репозиторий. Дальше развивает проект своим Claude.

## Список ключей (Шаг 4) - сгруппировано по сервисам

**Минимум для OZON-дашборда (группа OZON):**
- `OZON_SELLER_CLIENT_ID`
- `OZON_SELLER_API_KEY`
- `OZON_PERF_CLIENT_ID`
- `OZON_PERF_SECRET`
- `OZON_PERF_CLIENT_SECRET`

**Остальные (нужны только если передаёте соответствующие дашборды):**
- Яндекс: `YANDEX_DIRECT_LOGIN`, `YANDEX_DIRECT_TOKEN`, `YD_LOGIN`, `YD_TOKEN`,
  `YANDEX_METRIKA_TOKEN`, `YANDEX_METRIKA_COUNTER`, `YM_TOKEN`,
  `YANDEX_OAUTH_TOKEN`, `YANDEX_SEARCH_API_KEY`, `YANDEX_FOLDER_ID`
- Keys.so (SEO): `KEYSO_TOKEN`, `KEYSSO_API_KEY`
- Bitrix24 (РОП): `B24_WEBHOOK_URL`
- Банк «Точка»: `TOCHKA_CLIENT_ID`, `TOCHKA_CLIENT_SECRET`, `TOCHKA_TOKEN`,
  `TOCHKA_REFRESH_TOKEN`, `TOCHKA_CUSTOMER_CODE`, `TOCHKA_ACCOUNT_FILTER`
- Telegram (уведомления): `TG_BOT_TOKEN`, `TG_CHAT_ID`, `TG_THREAD_ID`
- Пароли на дашборды: `HUB_PASS`, `ACADEMY_PASS`

⛔ `GITHUB_TOKEN` - **не трогать**, GitHub даёт его сам.

> Если передаёте **только OZON [B]** - достаточно группы OZON. Остальные
> дашборды без своих ключей просто не будут обновляться (не сломаются;
> лишние воркфлоу можно отключить в Actions).

---

## Подводные камни (честно)
- **Ключи не читаются из GitHub** - нужны исходники или перевыпуск. Главное ограничение.
- **Передавай значения ключей безопасно** - не открытым сообщением в мессенджере;
  лучше вводить сразу в GitHub Secrets или через защищённый канал.
- **Адрес сайта сменится** (новый логин/репо) - старые ссылки на копию не ведут.
- **Персональные данные [A]** - репозиторий содержит запечатанные кабинеты
  сотрудников. Передавать весь репозиторий можно только по согласованию.
- **Google-таблицы владельца** - дать доступ или заменить на свои.
- **Одни и те же OZON-ключи** работают из любого репозитория (они привязаны к
  аккаунту продавца, а не к репозиторию). Если нужна изоляция - заводите
  отдельные ключи в кабинете OZON.

## Альтернатива - переезд на свой сервер (Timeweb)
Если коллега хочет уйти и с GitHub на собственный сервер (крон + nginx, всё под
его контролем) - это тоже возможно. Отдельная процедура, спрашивай отдельно.
