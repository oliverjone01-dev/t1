# Архитектура

## Принцип

Данные и вёрстка разведены полностью. Дашборд это функция от одного JSON-файла.
Обновление данных не требует ни одной правки в разметке, и наоборот.

```
gg-seo-geo-monster/data/{genglass,glass-memory}/*.json   живые выгрузки соседнего проекта
                    |
                    v
        tools/build_data.py        собирает и заворачивает каждую цифру в конверт
                    |
                    v
            data/kontur.json       единственный источник для интерфейса
                    |
                    v
             src/build.py          вшивает данные в страницу
                    |
                    v
          public/index.html        самодостаточный файл, работает и с диска
```

Параллельно `tools/snapshot.py` дописывает дневную точку в
`data/history/positions.ndjson`, и `build_data.py` подмешивает её в ряд.

## Почему данные вшиваются, а не тянутся запросом

Страница должна одинаково открываться на GitHub Pages, как артефакт Claude и
просто с диска. Запрос за соседним файлом с диска браузер блокирует, а на Pages
он добавляет точку отказа. Вшивание убирает и то и другое ценой пересборки при
каждом обновлении данных, что и так происходит.

## Модули интерфейса

Каждый модуль это Python-файл с одной строковой константой. `src/build.py`
склеивает их в один блок JavaScript. Разделение чисто редакторское: так правки
не превращаются в конфликты в одном файле на четыре тысячи строк.

| Модуль | За что отвечает |
|---|---|
| `head.py` | шапка документа и короткий локальный слой раскладки на токенах; токены и кит вставляет сборка |
| `core.py` | цвет ссылками на токены, формат чисел, конверт Протокола 9, периоды и динамика |
| `widgets.py` | прежние имена виджетов поверх кита: `mini` это `KS.tile`, `card` это `KS.card` и так далее |
| `nav.py` | дерево меню для `KS.nav`, бейджи разделов по проекту, состояние проекта и экрана |
| `scr_a.py` | обзор и раздел «Деньги» |
| `scr_dyn.py` | раздел «Динамика» |
| `scr_b.py` | органика, семантика, позиции, GEO |
| `scr_c.py` | реклама, ссылки, Метрика, Директ, контент, сравнение |
| `scr_d.py` | регламент и страница собственнику |
| `meth.py` | карточка «Метод и его границы» для каждого экрана |
| `read.py` | карточка «Что смотреть»: три правила чтения на экран |
| `draw.py` | все графики пресетами `KS.charts` (ApexCharts 3.54.1) |
| `app.py` | оболочка по `kontur-ds/templates/starter.html`: отрисовка, сегмент проектов, период, палитра команд, плотность, тема, адрес; `appStart()`; шифруется вместе с данными |
| `shell.py` | разметка каркаса и окно пароля: единственный код, который читается без пароля |

## Вид из Контур DS 1.5

С 23.09.2026 страница собирается на пакете Контур DS 1.5; с 25.09.2026 это своя копия `kontur-dashboard/kontur-ds/` (в корне репозитория теперь общий дом Контура с новыми версиями).
`src/build.py` вставляет в `<head>` токены (`tokens/tokens.css`) и компоненты
(`kit/kit.css`) как есть, а скрипты кита (`brand.js`, `icons.js`, `kit.js`,
`charts.js`) кладёт в основной блок `app-js` перед модулями. Стили открыты: в них
нет данных. Кит шифруется вместе с приложением, поэтому вне шифра остаются только
ApexCharts с CDN и окно пароля (это проверяет `tools/seal_page.mjs`).

Экраны почти не переписывались: прежние функции виджетов стали тонкими обёртками
над китом, утилиты Tailwind в разметке экранов заменены классами кита (`ks-muted`,
`ks-mono`) и коротким локальным слоем раскладки в `head.py`, где все значения
берутся из токенов. Своих цветов у дашборда больше нет.

## Внешние зависимости

Две, обе с разрешённых CDN:

- `cdnjs.cloudflare.com/ajax/libs/apexcharts/3.54.1` - графики
- `fonts.googleapis.com` - Golos Text (на Mac и iPhone системный SF)

Ничего больше подключать нельзя: остальные хосты блокируются политикой артефактов.
