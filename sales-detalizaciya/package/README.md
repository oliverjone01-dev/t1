# Glass Memory · раздел «Детализация» + Контур DS 1.4

Архив для общего проекта Glass Memory. Внутри три вещи:

1. **Контур DS 1.3** из макета «Разбор недели» один в один, разложенный по файлам так же, как в ките.
2. **Расширение DS 1.4 (kx)** с доработками, которые появились при сборке «Детализации». Что изменилось, описано в `CHANGELOG-DS.md`.
3. **Раздел «Детализация»**: семь подразделов, стартовая страница «Обстановка».

Откройте `index.html` с диска. Так раздел должен выглядеть и вести себя в общем проекте.

## Как добавить в общий проект Glass Memory

**1. Подключить DS в `<head>` в таком порядке**

Если Контур DS 1.3 уже стоит в проекте, базовые файлы не трогайте, добавьте только `kx.css` и `kx.js`.

```html
<link rel="stylesheet" href="ds/tokens.css">
<link rel="stylesheet" href="ds/kit.css">
<link rel="stylesheet" href="ds/kx.css">          <!-- 1.4 -->
<script src="ds/brand.js"></script>
<script src="ds/icons.js"></script>
<script src="ds/kit.js"></script>
<script src="ds/charts.js"></script>
<script src="ds/kx.js"></script>                  <!-- 1.4, строго после kit.js -->
```

**2. Добавить класс `kx` на корень приложения**

Компоненты kx работают только внутри `.kx`. Короткие имена (`.card`, `.b`, `.seg`) не заденут остальные страницы проекта. Проще всего так: `<div class="ks-app kx">`. Слои поверх (подсказка, панель, палитра) `kx.js` создаёт сам в конце `body`.

**3. Поставить контейнер раздела и переключатель кабинета**

```html
<div class="ks-topbar-tools" id="detal-cab"></div>   <!-- в верхней панели -->
<main class="hx" id="detal"></main>                   <!-- тело раздела -->
<script src="sections/detalizaciya/data.js"></script>
<script src="sections/detalizaciya/detalizaciya.js"></script>
```

**4. Меню и стартовая страница**

«Детализация» идёт в меню **первой**, стартовый пункт `detal-sit` («Обстановка»):

```js
const NAV = [ GM_DETAL.NAV_GROUP, /* ...остальные разделы проекта... */ ];
$('nav').innerHTML = KS.nav(NAV, GM_DETAL.START);      // START = 'detal-sit'
const app = GM_DETAL.mount(window.DETAL_DATA, {
  root: $('detal'), cab: $('detal-cab'), nav: $('nav'), start: GM_DETAL.START
});
KS.navWire($('nav'), id => app.go(id) || router.open(id)); // своё: переход в другие разделы
```

- Если в проекте роутер, маршрут по умолчанию `/` ведёт на «Детализацию».
- Прямые ссылки на подразделы работают через `#detal-flow`, `#detal-todo` и т.д.
- `mount` возвращает `{ render, cabSet, go }`.

**5. Тема**

Раздел рассчитан на тёмную тему по умолчанию: `KS.theme.set('dark', { persist:false })`, если человек не выбрал тему сам. Светлая тема тоже проверена.

## Данные

- `data.js` собирает `drafts/build_package.py` из выгрузок Авито в репозитории `t1/sales-detalizaciya`. Для новой недели нужно перезапустить сборку.
- В файле ID диалогов и обезличенные итоги переписки: имена и телефоны заменены на `[имя]`. **Не выкладывайте `data.js` в открытый доступ.** В публичном репозитории этот раздел идёт только в зашифрованном виде (`index.html` с паролем в `t1/sales-detalizaciya`).
- `[ДАННЫЕ]` означает числа из переписки: скорость, цена, дожим, телефон, воронка по обращениям.
- `[ГИПОТЕЗА]` означает смысловую разметку 1 355 диалогов: стадии, причины, возражения, реакция на цену. «+44 клиента» от дожима тоже гипотеза: это допущение, что вернутся 20% молчащих, оно не проверено.
- Нормы 70 / 85 / 30 / 20% черновые и ждут подтверждения CMO.

## Ограничения, о которых стоит знать

- Причины потерь, реакция на цену и возражения посчитаны по двум кабинетам вместе. При выборе одного кабинета интерфейс так и пишет: «оба кабинета».
- Сделки, ушедшие в телефон, в чате не видны. Воронка до договора точна только после связки с Bitrix24.
- `kx.js` перехватывает ⌘K, чтобы не открывалась вторая палитра из `kit.js` (`KS.cmdk`). Подробнее в `CHANGELOG-DS.md`.
