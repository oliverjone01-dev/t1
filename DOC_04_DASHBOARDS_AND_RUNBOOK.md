## 1. Дашборды

Все файлы держатся в одной папке - ссылки между ними относительные (`./GENGLASS_*.html`). Открываются как локальные HTML в браузере.

### 1.1 `GENGLASS_Analytics_v5_hub.html` - командный центр
- Сверху: оперативка LIVE за выбранный период (оборот, заказы, воронка) и реклама Performance.
- Ниже: блок "Сверка - бухгалтерская правда (фев-апр)", помечен как не оперативный слой.
- Выезжающая панель Гуру-аналитика: вопрос своими словами, переключатель периода, память диалога (`sessionId` на загрузку страницы).
- Карточки навигации: Финансы (P&L кокпит), Товары (живые SKU), Команда (ролевые срезы).
- Источники: вебхуки live, ads, analyst. Модельный sales_skus из навигации отцеплён.

### 1.2 `GENGLASS_live_skus.html` - живые SKU
- Таблица всех SKU с продажами, сортировка по любому столбцу.
- Колонки: Товар, Оборот, Шт, Ср.чек, Показы, Конверсия в заказ, Возврат %, Индекс цены (с цветом супер/ок/дорого), Склад, Линия.
- KPI: оборот, заказано, SKU с продажами, ДРР, возвраты, склад 0 при продажах (OOS).
- Линия VIOLUR помечена "не для МП".
- Источник: вебхук skus.

### 1.3 `GENGLASS_personas.html` - 5 ролевых экранов
- **Богдан (директор):** чистая прибыль и сверка по закрытым месяцам, накопленный итог, оперативный оборот как индикатор момента.
- **Иван (CMO):** ДРР канала, расход, активные кампании, ДРР по линиям рекламы, доля выручки по линиям, срез позиционирования по цене (сколько SKU дешевле/дороже/вровень с рынком).
- **Оля (РОП):** воронка показ-заказ-отмены-возвраты, возвраты по товарам, карта OOS как упущенные заказы.
- **Катя-продакт:** трафик есть - заказов мало (кандидаты на переделку карточек), высокие возвраты, самый дорогой чек, "дороже рынка - снизить цену", "склад 0 (OOS)", "дешевле рынка - можно поднять".
- **Катя-OZON:** ДРР, слив бюджета, активные кампании, кампании на отключение, топ по расходу, оценка возврата денег от отключения сливов `[ГИПОТЕЗА]`.
- Источники: вебхуки skus + ads.

### 1.4 `GENGLASS_finance_cockpit.html` - сверенный P&L
- Реализация, вклад, чистая прибыль, водопад затрат, симулятор "что если", юнит-экономика по закрытым месяцам.
- Источник: финансовые транзакции (исторический срез).

### 1.5 `GENGLASS_sales_skus.html` - DEPRECATED
- Почти весь модельный (себестоимость по производственной модели, дневные сплиты). Не живой API.
- Шапка честно помечена "фев-июнь 2026" с предупреждением о модельных данных. От навигации хаба отцеплён.
- Под снос. В теле осталось около 81 длинного тире (нарушение типографики) - чистить нет смысла, файл удаляется при пересборке.

## 2. Эксплуатация (Runbook)

### 2.1 Где что менять
- Поведение дашборда - в соответствующем `.html` (инлайн `<script>`).
- Логика данных и агента - в `.ts` исходниках воркфлоу, затем переразвёртывание (см. `DOC_03`, раздел 6).
- Опорные числа сверки (закрытые месяцы) - карта `CLOSED` в Code-ноде агента и массив `RECON` в `personas.html`. Обновлять при закрытии нового месяца.

### 2.2 Закрылся новый месяц - что сделать
1. Получить из подписанного Акта чистую прибыль и реализацию за месяц.
2. Добавить запись в карту `CLOSED` Code-ноды агента (`jroI8G9I3jicbqqE`), переразвернуть.
3. Добавить запись в `RECON` в `personas.html`, перевыложить файл.
4. Проверить: запрос агенту "разбери <месяц>" должен называть чистую прибыль как `[ДАННЫЕ]`.

### 2.3 Типовые сбои и лечение

| Симптом | Причина | Лечение |
|---|---|---|
| Агент падает с `Custom date key can only contain characters "response_..."` | Имя ноды агента кириллицей | Переименовать ноду агента в латиницу (`Guru`), переразвернуть |
| Реклама = 0 везде | Использован хост `performance.ozon.ru` | Перейти на `api-performance.ozon.ru` |
| Рекламные суммы абсурдны | Не распарсена десятичная запятая в `moneySpent` | Заменять запятую на точку перед парсингом |
| Данные за январь/декабрь пустые | Ниже пола данных (фев 2026) | Это ожидаемо, клампить запрос к `2026-02-01` |
| Память агента не работает | Не передаётся `sessionId` или разные id между запросами | Слать стабильный `sessionId`; в хабе он генерится на загрузку |
| Дашборд "Не загрузилось" | CORS, воркфлоу не опубликован, или таймаут на тяжёлом запросе | Проверить publish и доступность вебхука; уменьшить период; повторить |
| Валидатор ругается `INVALID_EXPRESSION_PATH` | Поле не объявлено в `output` ноды | Добавить поле в `output:[{...}]` |

### 2.4 Тайминги
- Гуру-аналитик: 15-20 с (тянет два окна аналитики + рекламу).
- Товары / LIVE: 5-10 с.
- Реклама: до 20 с (Performance API не быстрый, батчи по 25 кампаний).

## 3. Журнал решений и ограничений (ADR + Limitations)

### Решения
1. **Живой вызов OZON вместо своей БД.** Свежесть и нулевое хранение в обмен на латентность и отсутствие истории. Сознательно для быстрого запуска.
2. **Логика в Code-нодах n8n.** Быстрая итерация в обмен на отсутствие Git-версионирования и тестов кода.
3. **Статические HTML-дашборды.** Ноль билда в обмен на отсутствие компонентов и авторизации.
4. **Два слоя данных раздельно.** Оперативка и сверенная прибыль не смешиваются - защита от ложной точности.
5. **Авто-режим агента.** Закрытый месяц -> P&L; незакрытый -> только оперативка. Прибыль не выдумывается.
6. **Память агента - буфер по sessionId.** Просто и работает в сессии.

### Ограничения (честно)
1. Данные с февраля 2026; истории раньше нет.
2. Закрыты по прибыли только фев/мар/апр; май-июнь - оперативка без прибыли.
3. ДРР по линиям из рекламы ненадёжен (таксономии), достоверен суммарный.
4. Секреты в нодах - технический долг.
5. Один провайдер модели (OpenAI).
6. Память не персистентна между перезапусками воркфлоу.
7. `sales_skus.html` - модельный, под снос; в нём осталось длинное тире.
8. Нет авторизации и ролевого доступа на уровне системы (ролевые экраны - это представления, а не контроль доступа).
9. Нет автотестов и регрессии на ответы агента (golden set запланирован).
10. Косметика: при ручном выборе окна через переключатель "трактовка периода" в шапке фактов агента может быть пустой - на корректность ответа не влияет.
