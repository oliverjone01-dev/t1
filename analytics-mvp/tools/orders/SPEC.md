# Блок «Аналитика по заказам» (в разрезе заказа) - спецификация

Статус: **формируется** (18.09.2026). Начат по просьбе Ивана: «такой же аналитики, но в разрезе заказа».
Отдельный блок на странице «Деньги» (OZON), рядом с «Аналитика по артикулам».

## Идея
Та же экономика, что в таблице по артикулам, но строка = **заказ (posting)**, а не артикул.
Колонки те же: Реализовано(шт), Начислено, Комиссия, Логистика, Эквайринг, Хранение, Прочие,
Реклама, Наша доставка, Доставка покупателя, Всего сборов, К выплате, СС произв., Валовая, АДМ 30%,
Налоги 15%, Чистая, Рентаб.

## Ключевой факт: офлайн не собрать
Проверено 18.09: офлайн-источники по заказу НЕ стыкуются и не содержат сборов.
- CPO-файлы (`tools/cpo/raw/`) дают по заказу выручку, рекламу, артикул - но только по заказам с CPO
  (819 заказов) и формат «Номер заказа» без суффикса отправки.
- Ведомость доставки (`tools/delivery/raw/`) даёт по заказу нашу/клиентскую доставку (1047 заказов),
  но формат номера с суффиксом отправки `-N`.
- Пересечение двух источников по номеру: **2 заказа из ~1800** - форматы номеров разные.
- Ни в одном офлайн-источнике нет комиссии/логистики/хранения/к-выплате по заказу.

Вывод: **backbone блока - данные OZON по заказу** (постинги + начисления). Офлайн CPO/ведомость -
только досбор рекламы и доставки поверх этого backbone.

## Источник по каждой колонке (per posting)
| Колонка | Источник |
|---|---|
| Реализовано (шт), Начислено (выручка) | постинги OZON: `/v2/posting/fbo/list` + `/v3/posting/fbs/list` с `with.financial_data`/products (SKU, qty, price) |
| Комиссия, Логистика, Эквайринг, Хранение, Прочие, К выплате | `/v1/finance/accrual/postings` по номеру заказа (per-posting сборы по type_id; бакеты - как в `accrual-buckets.ts`) |
| Реклама | CPO-файлы (per-order, `data/cpo_sku_daily.ndjson` расширить номером заказа) + CPC-атрибуция где есть |
| Наша доставка, Доставка покупателя | ведомость (`data/delivery_sku_daily.ndjson` расширить номером заказа); джойн по нормализованному номеру (снять суффикс `-N`) |
| СС произв. | лист СС по SKU заказа × qty |
| Валовая / АДМ / Налоги / Чистая / Рентаб. | те же формулы, что в anCells (Валовая = К выплате − СС − Наша доставка + Доставка покупателя) |

## Пайплайн (нужен прогон с кредами OZON, в ночном синке)
1. `postingNumbers(from,to)` уже есть; расширить до `postings(from,to)` - вернуть по каждому постингу
   products: {sku, offer, qty, price, status, order_date}.
2. `accrualPostings(numbers[])` уже есть - сборы по type_id на постинг → бакеты.
3. Собрать `data/orders_daily.ndjson`: {order, d, sku, offer, units, revenue, commission, delivery,
   acquiring, storage, other, payout}. Досыпать рекламу (CPO по номеру) и доставку (ведомость по
   нормализованному номеру).
4. Только ЗАКРЫТЫЕ месяцы (как везде); текущий не трогаем.

## §15 - сверка (обязательна до деливери)
- Σ по заказам (К выплате) за период = Σ по артикулам (К выплате) = P&L канала. До рубля.
- Σ Реклама/Наша доставка/Доставка покупателя по заказам = те же ИТОГО в таблице по артикулам.
- Покрытие: % заказов/оборота с полными данными; заказы без начислений (не рассчитаны) - отдельной
  строкой/бейджем, не как нули.

## Рендер
Переиспользовать `anCells` (та же строка колонок). Группировка: по заказу; при большом числе -
свёртка по категории/дню сверху, раскрытие в заказы. Клиентский период - общий фильтр дашборда.
