## Blocker

Успешный свежий семидневный отчёт без корректировок перезаписывает весь список `sku[cid].reports`. Поэтому ранее сохранённая историческая корректировка исчезает, хотя её диапазон не обновлён. Пропадает и существующее предупреждение sourceHealth.

Доказательство: изолированный вызов реального `ad-sku-daily.main`, два CPC, сеть запрещена. До запуска сохранены строка 01.08, state 19.10 и корректировка -25 за 22.08-15.10. Fake API возвращает свежие данные обеих кампаний, затем исторический download даёт 503. После запуска:

- обе свежие строки 22.10 и старая строка 01.08 сохранены;
- полный checkpoint остался 19.10;
- исторические corrections: 1 → 0;
- предупреждение sourceHealth: true → false.

Причина: `ad-sku-daily.ts:65,87-88` начинает accumulator с пустого объекта, а `attribution-report.ts:12` заменяет metadata целой кампании. Это регрессия после перехода к отдельной записи свежего диапазона. В действующем файле metadata уже есть непустые исторические корректировки. Денежная формула ими не меняется, но сведения об источнике и предупреждение теряются.

Доработка: сохранять непересобранные окна. Заменять metadata только при доказанном покрытии принятого отчётного окна, включая объединение свежего и исторического диапазонов. Недатированную сумму не распределять между частями. Нужны регрессии сохранения при 503, полного покрытия, пустой корректировки и повтора без дублей.
