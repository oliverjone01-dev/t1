## 1. Ответ на три вопроса автора, коротко

**1. Четвёртый путь тихой порчи есть, и он не гипотетический.** Его создала сама дельта. `--rebuild` удаляет месяц из накопленного файла в тот момент, когда пересобрать его нечем, и печатает при этом «месяц не трогаю». Воспроизведено на живых данных: 177 строк и 4 месяца превращаются в 134 строки и 3 месяца, 2026-02 на 1 259 030 ₽ исчезает. Класс новый: раньше портил ошибочный ВЫВОД (ключ чистки, месяцы из ответа, самоотменяющийся признак), теперь портит правильный вывод при неудачном ВВОДЕ. Пересбор безусловно удаляет старое и условно записывает новое.

**2. Пересбор создал ровно те риски, о которых вы спрашивали, и ещё один.** Потеря собранных строк при NO_DATA - да. Взаимодействие с бюджетом и лимитом Маркета - хуже, чем потеря одного месяца: `break outer` при исчерпании бюджета выбрасывает из цикла ВСЕХ месяцев, а строки всех запрошенных месяцев уже выброшены из аккумулятора до первого запроса. Пересбор месяца, которого нет в состоянии, безопасен. Плюс не спрошенное: `--rebuild` без аргумента месяца молча берёт [предыдущий, текущий] и стирает 2026-08 на 952 805 ₽.

**3. Исключения гейт не ослабили - они его выключили на двух файлах из четырёх.** `aggregate` обнуляет сравнение для `sku_views` целиком: сегодня 4504 строки из 4504 несут этот флаг, потеря 90% строк даёт «аномалий нет». `growOn` снимает детектор роста с реализации: задвоение закрытого месяца 2026-02 (1 259 030 -> 2 518 060 ₽) даёт exit 0, хотя в iter3 тот же файл на той же фикстуре давал exit 1. Это единственная регрессия обнаружения в дельте.

## 2. P0-1. `--rebuild` удаляет месяц и сообщает обратное

`reports.ts:145-153` пропускает строки запрошенных месяцев при засеве аккумулятора. Дальше месяц зависит только от того, что вернёт Маркет. Если не вернёт ничего, страховка `reports.ts:216` печатает «месяц не трогаю» и делает `continue`, но запись на `:222-224` безусловна и идёт по `byMonth`, где месяц остался пустым объектом. Строки месяца не сохраняются, а исчезают.

Живой прогон РЕАЛЬНОГО CLI на копии `data-ym` (сеть до Маркета закрыта allowlist'ом, ключ фиктивный, репозиторий не тронут):

```
$ YM_DATA_DIR=<копия>/data-ym YM_API_KEY=dummy npx tsx src/scripts/ym/reports.ts realization 2026-02 --rebuild
::warning::ключ 1 (мебель): список кампаний не прочитан - HTTP 403
realization: ПЕРЕСБОР месяцев 2026-02 с нуля - накопленные строки этих месяцев отброшены, пары открыты
::warning::realization 2026-02: ни один отчёт не разобран - месяц не трогаю
realization: всего 134 строк (3 мес), пар месяц/кампания 31/0
```

Контроль на второй копии, та же команда без флага: `realization 2026-02: SKU 43 ... всего 177 строк (4 мес)`. Причина ровно одна - флаг.

Второй прогон, без аргумента месяца:

```
$ ... npx tsx src/scripts/ym/reports.ts realization --rebuild
realization: ПЕРЕСБОР месяцев 2026-08, 2026-09 с нуля
::warning::realization 2026-08: ни один отчёт не разобран - месяц не трогаю
::warning::realization 2026-09: ни один отчёт не разобран - месяц не трогаю
всего 133 строк (3 мес)     # в файле остались 2026-02, 2026-03, 2026-04
```

Ветки, ведущие в пустой месяц, все штатные и все сегодняшние:

| Вход | Код | Что сегодня в данных |
|---|---|---|
| список кампаний не прочитан (ключ ротирован, 403/5xx после 5 ретраев, сбой Маркета) | `common.ts:88-90` глотает ошибку в warning и возвращает пустые targets | воспроизведено выше |
| все магазины NO_DATA | `reports.ts:174-178` | 2026-08: 5 из 7 магазинов «УПД не выпущен» по самопроверке автора |
| API кампании отключён | `reports.ts:169-171` закрывает пару НАВСЕГДА и без строк | три кампании 1023124 отдают API_DISABLED по самопроверке автора |
| бюджет отчётов исчерпан | `reports.ts:176` `break outer` выходит из цикла ВСЕХ месяцев | BUDGET=10, кампаний 14, пар в состоянии 38 |
| лимит генерации и дедлайн | `stopOnRateLimit` -> `break outer` | 1 отчёт / 2 мин на кабинет, дедлайн 95 мин |
| нет продаж в `orders.ndjson` за пару | `reports.ts:161` закрывает пару без запроса | зависит от перетяжки хвоста заказов |

Строка про бюджет самая опасная: при пересборе трёх месяцев подряд первый может собраться, а второй и третий будут стёрты не потому, что данных нет, а потому что кончился бюджет.

**Почему гейт это не ловит.** Ловит, но не там. В CI гейт видит потерю месяца:

```
$ npx tsx src/scripts/ym/validate-facts.ts <файл после пересбора> data-ym/realization_monthly.ndjson --month-key=ym --sum=amount
FACTS INVALID: 2026-02: строк было 43, стало 0 (потеря)     exit=1
```

Но `--rebuild` по замыслу автора - команда оператора на локальной машине (`reports.ts:125`), а локального гейта нет: `grep validate-facts analytics-mvp/package.json` пусто, npm-скрипта нет. Оператор стирает месяц локально, коммитит, и следующий ночной прогон снимает базовый слепок с уже испорченного файла (`ym-snapshots.yml:86-95`). База сравнения отравлена, потеря становится новой нормой. Это и есть четвёртый путь: не ошибка в выводе, а разрыв между тем, где живёт разрушительная команда, и тем, где живёт защита.

## 3. P0-2. Объявленное падение `base()` не срабатывает

Автор пишет: «`base()` теперь ПАДАЕТ, если файл в `data-ym` есть, а слепка нет». Проверено в точной форме вызова из workflow (`ym-snapshots.yml:170-176`, вызов на `:177-180`):

```
$ bash repro.sh     # base() дословно из workflow, слепка нет, data-ym/netting.ndjson есть
ARGV:::error::слепка нет, а data-ym/netting.ndjson существует - гейт остался бы без базы сравнения
 [data-ym/netting.ndjson] [--month-key=d] [--sum=amount] [--by=business]
СТРОКА ГЕЙТА ВЫПОЛНИЛАСЬ, шаг продолжается
СЛЕДУЮЩАЯ СТРОКА ГЕЙТА ТОЖЕ ВЫПОЛНИТСЯ
ИТОГОВЫЙ EXIT ШАГА = 0
```

`exit 1` внутри `$( )` убивает подоболочку подстановки, а не шаг. `set -euo pipefail` не помогает: статус подстановки в позиции аргумента не проверяется. Аргумент базы просто исчезает из argv (пустая строка съедается разбиением на слова), `validate-facts` получает `data-ym/netting.ndjson --month-key=d ...`, не находит файла базы и печатает «прошлого снимка нет - сравнивать не с чем», exit 0. Все четыре строки гейта отрабатывают вхолостую.

Практическая вероятность отсутствия слепка при существующем файле низкая (шаг слепка и шаг гейта на одном раннере, `cp` без `|| true` уронит шаг сам). Но защита, которая не может сработать, стоит ноль, а заявление, что она срабатывает, стоит меньше нуля: оно закрывает вопрос для следующего читателя. Это третий круг подряд, когда утверждение автора о безопасности опровергается одной live-пробой (iter2 «гейт читает слепок», iter3 «задвоения не будет», iter4 «base() падает»). Шаблон устойчивый: проверяется наличие сообщения, а не остановка прогона.

Починка - одна строка, `base` в переменную до вызова:
`B=$(base netting.ndjson) || exit 1` либо `set -o errexit` плюс присваивание отдельным оператором.

## 4. Исключения гейта: `aggregate` и `growOn`

**4.1 `aggregate` выключил гейт на `sku_views` целиком.** `validate-facts.ts:54` пропускает такие строки при агрегации по обеим сторонам сравнения.

```
$ wc -l data-ym/sku_views.ndjson         -> 4504
$ grep -c '"aggregate":true' ...         -> 4504          # 100% строк
$ npx tsx validate-facts.ts <450 строк из 4504> data-ym/sku_views.ndjson --month-key=date --sum=views --by=business
facts-gate ...: строк 4504 -> 450, месяцев 0 -> 0, аномалий нет      exit=0
```

«месяцев 0 -> 0» - это и есть диагноз: обе стороны схлопнулись в пустоту. Любая потеря показов на этом файле проходит молча, включая обнуление файла. Тест `validate-facts.test.ts:70-74` закрепляет поведение как правильное: 3916 строк против 500 обязаны дать exit 0. Ложное срабатывание, которое я назвал в iter3, устранено ценой отключения детектора, и теперь это зафиксировано зелёным тестом.

Ложное срабатывание было настоящей проблемой, лечение выбрано не то. Правильный ключ сравнения для окна-агрегата - не «месяц», а «окно»: сравнивать надо агрегат текущего окна с агрегатом прошлого окна (сумма показов, число SKU), а не выбрасывать строки из рассмотрения.

**4.2 `growOn` снял детектор роста с реализации.** `validate-facts.ts:51` и `:83`.

```
$ npx tsx validate-facts.ts <2026-02 удвоен: 1 259 030 -> 2 518 060 ₽> data-ym/realization_monthly.ndjson --month-key=ym --sum=amount
facts-gate ...: строк 177 -> 177, месяцев 4 -> 4, аномалий нет      exit=0
```

В iter3 та же фикстура на том же файле давала `FACTS INVALID ... вырос на 100%`, exit=1. Это единственная регрессия обнаружения в дельте, и она приходится ровно на файл, в котором три итерации подряд находили пути задвоения. Аргумент автора «задвоение исключено по построению» - тот же аргумент, что звучал в итерациях 1, 2 и 3, и трижды оказался неверным. Детектор нужен не против известного пути, а против неизвестного четвёртого; я его сегодня и нашёл, только он оказался вычитающим, а не складывающим.

Довод автора про законный добор УПД верен по сути и не требует снятия детектора: добор идёт по магазинам, которых в месяце ещё не было, и отличается от задвоения тем, что растёт число строк-SKU, а не суммы при неизменном числе строк. Порог на сумму при неизменном `n` - это ровно сигнатура задвоения, и она отделима.

**4.3 Легальный выключатель сужен, но не убран.** Верхняя граница 2.0 включительно.

```
$ YM_FACTS_GROW_GATE=2 npx tsx validate-facts.ts <netting, месяц 2026-05 удвоен> data-ym/netting.ndjson --month-key=d --sum=amount --by=business
facts-gate: строк 15164 -> 17544, месяцев 18 -> 18, аномалий нет     exit=0
$ YM_FACTS_GROW_GATE=2.0000001 ...   FACTS INVALID: не число в диапазоне (0, 2]     exit=1
```

То есть одна переменная окружения по-прежнему пропускает ровное задвоение любого месяца. Тест `validate-facts.test.ts:57-59` пиннит только значение 20. Порог, при котором детектор ещё детектирует, - строго меньше 1.0.

## 10. Kill criteria, обратимость, что делать

5.90 выше 5.0: по §9 останавливается deliver (слияние в main), а не вся работа по ветке. Пока ветка не в main, `on: schedule` её не запускает - окно на правку бесплатное.

Обратимость новых дефектов: стёртый пересбором месяц восстановим двумя путями - `git checkout` файла (он в git) или повторный успешный прогон (пары месяца при пересборе удалены из состояния, я это видел: 38 -> 31 -> 23). Но для 2026-08 второй путь не работает: 5 из 7 магазинов ждут выпуска УПД, отчётов пока нет физически.

Блокирующие для снятия вето, все четыре малы:
1. `base()` - вынести в переменную и проверить статус (`B=$(base f) || exit 1`), иначе объявленное падение остаётся текстом.
2. `--rebuild` - собирать месяц в теневой аккумулятор и заменять накопленное ТОЛЬКО при `ok > 0` для всех ожидаемых магазинов; при `break outer` по бюджету или лимиту не записывать запрошенные месяцы вовсе. Плюс требовать явный месяц: без аргумента флаг должен падать, а не брать [prev, cur].
3. `sku_views` - сравнивать агрегат окна с агрегатом прошлого окна (сумма показов и число SKU), а не выбрасывать `aggregate` из сравнения. Тест `validate-facts.test.ts:70-74` переписать: он сейчас требует молчания при потере 87% строк.
4. Реализация - вернуть детектор задвоения по сигнатуре «сумма выросла при неизменном числе строк» (добор УПД растит число строк, задвоение - нет), вместо полного `growOn = byBiz`.

Не блокирующие, но в ту же итерацию: `YM_FACTS_GROW_GATE` с потолком <1.0; npm-скрипт локального гейта, чтобы оператор мог проверить файл до коммита; кавычки вокруг `${{ github.event.inputs.realization_months }}`.
