# GENGROUP · Холст задач


## Режим хранения

В «Вид и настройки» (иконка солнца) кнопка «Google Таблица» / «Firestore» открывает общий переключатель. Личный режим рассчитан на одного редактора (владелец rayivan001@gmail.com) и просмотр коллегами без входа. В нём Firebase SDK не инициализируется, задачи читаются анонимным CSV export самой уже открытой по ссылке таблицы каждые 30 секунд; вход владельца использует Google Identity Services и drive.file, запись идёт напрямую в Sheets API. CSV сохраняет пустые строки и смешанные типы; Visualization queries для задач не используются из-за удаления пустых строк и инференса типов. Запись проверяет текущий режим перед отправкой, использует прежний трёхсторонний merge и локальные конфликты. Атомарной защиты одновременных записей одной ячейки и общей истории Firestore в личном режиме нет. Права на исходную таблицу переключатель не меняет.

Командный режим сохраняет Firestore-транзакции, общую историю, ACL и конфликты. Его бесплатные квоты остаются; включение требует успешного импорта и сверки таблицы перед открытием редактирования.

Настройка действует для всех устройств: защищённые служебные Q2 (запрос владельца) и R2 (подтверждение обработчика) содержат JSON schema1 с mode/epoch/at. Они не занимают строки задач. Приватный Apps Script с единственным ScriptLock проверяет запрос раз в минуту. При уходе в личный режим он закрывает старым Firestore-клиентам запись, затем подтверждает переключение. Обычный личный тик делает только одно чтение служебных ячеек Sheets, без Firestore. При возврате сначала выполняет обычный версионный обмен, потом открывает Firestore-запись и подтверждает epoch. Клиент ожидает подтверждения, сохраняет выбор и перезагружается в нужный движок; ожидание можно отменить кнопкой возврата в текущий режим. Ошибка квоты не подтверждает незавершённый переход.

Копии/очереди/черновики двух режимов изолированы разными ключами; история Firestore и состав редакторов не удаляются. Переключатель не отправляет запрос, пока в текущем движке остаются неотправленные операции. Сохраняйте их или скачайте копию до смены режима. Редактирование со старой вкладки командного режима при storageMode=sheets запрещено правилами сервера, даже если клиент игнорирует новый интерфейс. Редактирование нового прямого Sheet-клиента блокируется при незавершённом запросе режима. Настройки вида остаются общими.

Командная доска задач: равные квадраты с внутренней прокруткой и разворотом, дорожки ответственных и сроков на холсте с зумом и сеткой 24 px. Статический ES modules frontend с React/Motion-компонентом планирования; исходники UI собираются через esbuild и Tailwind. Общие задачи и история хранятся в Google Firestore, таблица синхронизируется двусторонне; вход выполняется через Google OAuth и Picker с ограниченным публичным ключом.

## Запуск

Из папки `task-canvas`: `python3 -m http.server 4175 --directory public --bind 127.0.0.1`, затем открыть http://127.0.0.1:4175. Требуются Python 3 и современный браузер. Для работы самого приложения Node не нужен; `npm test` запускает проверки модели на Node 22+.

Общий Pages workflow копирует `public/` в `/tasks/` при публикации из main. Из рабочей ветки этот workflow не публикует новую доску. Уже существующие проекты не изменяются.

## Просмотр по ссылке

По умолчанию страница открывает актуальную общую доску без Google-входа и подписывается на `taskBoardViews/{board}`. Отдельная Firebase-сессия не авторизована, использует только память и не получает токен редактора. Доступны все виды, фильтры, масштаб и подробности карточек; изменение, импорт, переносы и отмена требуют Google-входа. Поля карточки и статусы в просмотре недоступны для ввода. Запрет записи проверяется правилами Firestore, включая прямой API-вызов.

Публичное представление содержит только текущие неархивированные задачи, номер ревизии, дорожки и обезличенный статус источника. История, исходные альтернативы конфликтов, операции, участники доступа, исходные контрольные копии Sheet и архив остаются в закрытой структуре `taskBoards`. Любой со ссылкой может читать и копировать опубликованные карточки; для редактирования отдельно проверяется список команды. Страница помечена noindex, что не заменяет права доступа.

Обновление карточки и публичного представления проходит в одной транзакции. Архивирование удаляет только общедоступную проекцию; оригинал и история сохраняются. Правила отклоняют устаревшую публикацию, лишние поля и запись в каноническую задачу без соответствующей публичной версии. Создание истории и идемпотентные квитанции работают как прежде.

Кэш просмотра в `gengroup.task-canvas.public-view.v1` отделён от личной копии редактора и IndexedDB-очереди. Просмотр не подмешивает неотправленные правки, не удаляет черновики и не включает их в свой JSON-экспорт. При отсутствии сети показана последняя копия с явной пометкой; после восстановления подписка возвращает живые данные. Google-вход сохраняет обычную проверку очереди, а отключение возвращает публичный просмотр. Прямые правки Google Sheet поступают по мосту через подключённого владельца; сам гость не пишет в Sheet и не запускает импорт.

Первоначальное включение публичной проекции (уже выполнено): сначала совместимые правила при закрытом (`ready:false`) корне публичной проекции, затем frontend; после публикации строгие правила, согласованное заполнение проекции по текущим updateTime и включение `ready:true`. До включения не показывать гостям предварительный снимок. Аренда моста и квитанции новых операций используют protocol:3; старые страницы не могут продлевать аренду и блокировать обновление источника. Старые редакторы без двойной транзакционной записи должны обновить страницу; их неотправленные операции остаются в очереди.

## Фоновый обмен с таблицей

Приватный Google Apps Script может обслуживать первую вкладку без открытого браузера и входа владельца на доске. Нормальный интервал — пять минут; при медленном Google или исчерпании квоты повтор откладывается. Клиент показывает режим только после подтверждённой активации в корне базы. До активации сохраняется прежний мост через браузер.

Реализация, установка, разрешения, ограничения и восстановление: [background/README.md](background/README.md). Сборка: `npm run build:background`. Скрипт связывается с существующим GCP-проектом и выбранным файлом через ограниченный drive.file; платный тариф не включается. Требуется одноразовое разрешение владельца в Google. Скрипт использует те же версии, историю, квитанции и конфликты; на тёплом кэше читает только изменённые задачи. Правила не дают старой странице вернуть браузерный мост после активации фона.

## Редакторы команды и новая матрица

Просмотр по ссылке остаётся общедоступным. Сервер допускает к каноническим данным и записи только подтверждённый Google-вход владельца `ownerEmail` или адрес из `members`. Режим `google-link` и прежний реестр администраторов не дают права редактирования. Владелец управляет редакторами через «Доступ»; его адрес неизменяем. Изменения списка проходят транзакцией с `accessRevision` и неизменяемым `accessEvents`-журналом. Повтор одного ID не добавляет запись второй раз; разные устройства изменяют отдельные адреса поверх текущего списка. Отзыв права закрывает запись даже с ранее выданным токеном; локальная очередь и черновики сохраняются.

При первом включении IAM-администратор условно дополняет только корень доски: `ownerEmail`, `members`, `accessRevision`, `sharingMode:members`. Публичная проекция остаётся включённой. После frontend публикуются приложенные строгие правила; старые страницы должны обновиться. Задачи и рабочие строки этой миграцией не переписываются.

Редактору команды достаточно Google-входа и записи в списке, доступ к самому Sheet не требуется. До активации фонового обработчика мост Sheet запускает подключённая сессия владельца. После активации Google Apps Script работает независимо от вкладок и Google-сессии на доске. Служебный R3 обновляется до «Позиции · команда v3», чтобы старые браузеры не затёрли новый порядок.

Квадраты не увеличиваются от количества задач: 2×2 одинаковые панели с внутренней прокруткой; на низком экране прокручивается обзор фиксированных панелей, на мобильном панели идут друг под другом. Разворот показывает один квадрат на доступную область. Во всех размерах карточки сохраняют читаемый размер. Сетка карточек заполняется без сохранённых пустот.

Порядок `positions.priority.order` использует fractional indexing с детерминированными неявными ключами старых координат. Перенос изменяет только выбранные задачи, не переписывает соседей. При одновременной перестановке одной задачи действует существующее сравнение версий и выбор конфликта. Выделение: галочки, Ctrl/Cmd-клик, Shift-диапазон, выбрать квадрат, Ctrl/Cmd+A внутри доски; перенос группы за ручку, начало/конец, другой квадрат, «Готово» или «Отменено». Выделение локальное. Массовые операции сохраняются отдельными версионируемыми намерениями; конфликт отдельной задачи не скрывается общим успехом группы.

Используются целые MIT-компоненты Kokonut UI SmoothTab и LiquidGlassCard; стеклянная оболочка без SVG-преломления текста. Исходники и лицензии: `ui/vendor/`, подробнее `ui/vendor/NOTICE.md`. `npm ci --ignore-scripts && npm run build` обновляет закоммиченные `public/board-ui.mjs`/`.css`. CI проверяет воспроизводимость сборки и серверные правила через Firestore emulator.

## Компактная панель и обзор

Статус «Просмотр» / «Сохранено» рядом с поиском открывает подробности источника, времени последней проверки, входа и ошибок. Настройки хранения и доступа находятся в «Вид и настройки». Постоянного информационного баннера нет; ошибки и неподтверждённые правки остаются видны в статусе.

В приоритетах есть два режима. «Карточки» сохраняет равные квадраты с внутренней прокруткой, изменение очередности, выделение и массовые действия. Кнопка ползунков меняет размер карточек от 80 до 120% и сохраняет настройку только на этом устройстве. «Обзор» показывает все семь зон на отдельном холсте и открывается на вкладке «Задачи»: в ней работают перенос за ручку, очередь по линии вставки, выделение и массовые операции. Дроп сохраняет идентификатор соседа через тот же `onMove`/`reorderTasks`, что и рабочая сетка. Карточки и цели переноса находятся в координатах экрана: масштаб камеры не искажает коллизии. Клавиатура: пробел поднимает/подтверждает, вверх/вниз меняют очередь, влево/вправо или Alt+вверх/вниз выбирают соседнюю зону, Escape отменяет. «Сводка» сохраняет обзор нагрузки по людям и срокам. Название приближает зону внутри обзора. Колесо прокручивает список под курсором, на фоне перемещает камеру; рука и Ctrl/Cmd + колесо сохраняют прежний смысл. Кнопка с углами или F при фокусе на холсте вписывает доску. Размеры зон не зависят от количества задач. Масштабирование и перемещение обзора не меняют задачи и не запускают синхронизацию. На телефоне обзор перестраивается в две колонки.

Kokonut SmoothTab использует короткий переход выбранной плашки без пружины; стекло применяется только к всплывающим панелям, без SVG-преломления. Уменьшение движения, прозрачности и системный высокий контраст учитываются. Приоритетные акценты взяты из `ZNANIYA_UI_UX_referensy_2026-09-23.md` (§§0, 3.1, 3.8, 5, 7): синий `#3561C9` для важности и фиолетовый `#7B3BC4` для срочности, адаптированные значения для тёмной темы, тон 4-7%, подписи и иконки. Цвета успеха/отмены остаются статусными. Рамки не используются как постоянное украшение. Подробности проверки: `docs/compact-board-acceptance.md` и `docs/overview-drag-acceptance.md`.

## Четыре представления одной доски

- **Приоритеты:** входящие и четыре квадрата «важно × срочно». Перенос меняет приоритет и порядок.
- **Команда:** дорожки по одному назначенному ответственному. Перенос меняет ответственного. Новые дорожки добавляются кнопкой. Формулировка из исходной таблицы остаётся в контексте карточки.
- **Сроки:** просрочено, сегодня, до конца недели, следующая неделя, позже, без срока. Перенос в другую дорожку назначает указанную в ней дату (для «Позже» - понедельник после следующей недели). Перемещение внутри своей дорожки сохраняет точную дату. В просроченную дорожку нельзя назначить задачу переносом: прошедшую дату можно указать явно в редакторе.

Во всех трёх видах холста справа добавлены отдельные зоны **Готово** и **Отменено**. Статус имеет приоритет над распределением по квадратам, людям и срокам: каждая завершённая/отменённая карточка находится в своей итоговой зоне, сохраняя остальные поля. Перенос туда меняет статус. Возврат в рабочую зону ставит «В работе» и меняет соответствующий приоритет, ответственного или срок. Между итоговыми зонами меняется только статус и положение. Статусы синхронизируются с колонкой I исходной таблицы.

В приоритетах доступны вкладки «Готово» и «Отменено» со счётчиками, в дорожках - кнопки над холстом. Они переводят обзор к зоне, а также принимают перетаскиваемые карточки, чтобы завершить задачу без поиска дальнего блока. По умолчанию отображаются все задачи; фильтр «Скрыть готовые и отменённые» включает пользователь. Счётчики учитывают остальные фильтры, но сохраняют количество скрытых итоговых карточек; переход в зону снова показывает их. Смена вида начинает обзор с активной задачи, если она есть.

Позиции сохраняются отдельно для каждого вида. При пересечении карточка получает свободное место, чтобы задачи не скрывались друг под другом. Колесо/трекпад перемещают холст, Ctrl/Cmd+колесо масштабирует под курсором, пробел+перетаскивание включает руку, F показывает все отфильтрованные карточки. Список «К дорожке…» переводит обзор к нужному человеку или периоду. Двойной клик или Enter открывает карточку; формы доступны с клавиатуры. Кнопки +/− и 100% управляют зумом.

Список даёт читаемый просмотр без зума, показывает ответственного, точную дату и статус, который можно изменить в строке. На узком экране колонки превращаются в подписи и значения. Зоны статусов доступны и здесь через кнопки над списком.

Cmd/Ctrl+K открывает команды и поиск задач; работает физическая клавиша K, включая русскую раскладку. Поиск сопоставляет слова в любом порядке по полям карточки, приравнивает ё к е. Светлая, тёмная и системная темы, а также обычная/компактная плотность настраиваются в «Вид и настройки». На телефоне фильтры открываются отдельной кнопкой; цели остаются 44 px и в компактной плотности.

## Черновики и восстановление

Ввод в редакторе сохраняется отдельно для каждой карточки на этом устройстве. Закрытие и Escape оставляют черновик, перезагрузка его восстанавливает. Блок над доской позволяет продолжить или удалить черновик. При возобновлении обновлённой задачи нетронутые поля берутся из текущего состояния, а конфликтующие тексты можно сравнить и выбрать по полю. Убранная в другом месте задача не создаётся заново при обычном сохранении: копия создаётся только отдельной кнопкой.

При недоступном хранилище черновик остаётся в памяти страницы, о чём показана ошибка; повторное открытие его сохраняет, уход со страницы вызывает предупреждение. Резервный JSON включает доступные черновики отдельным полем `drafts` для восстановления текста вручную; обычный импорт восстанавливает задачи, а не автоматически применяет черновики. Две вкладки, редактирующие один и тот же черновик в точности одновременно, не имеют транзакционной блокировки.

## Данные

Импорт: JSON-экспорт доски, CSV или вставка TSV из Google Sheets вместе с заголовками первой вкладки. Строки без задачи и направления пропускаются. Если текст задачи отсутствует, используется направление. Приоритеты не угадываются. Простой одиночный исполнитель переносится из источника; составные формулировки остаются в заметке и требуют явного назначения. Исходные сроки сохраняются текстом, однозначные даты распознаются; год для даты без года - текущий локальный год пользователя. При переносе доски между годами предпочтителен JSON с точными датами.

По умолчанию импорт добавляет новые ID и пропускает существующие, сохраняя пользовательские изменения. Первое нажатие «Проверить импорт» показывает число добавлений, изменений и убираемых задач. Применение требует второго нажатия; при удалении текущих задач дополнительно требуется явная отметка последствий. Изменение данных или текста после просмотра требует нового расчёта. Опция «Заменить текущие задачи» восстанавливает импортированную копию; это можно отменить в текущей сессии. Пустые дорожки ответственных тоже сохраняются в JSON.

Рабочие задачи и переписка не включены в репозиторий. Локальная копия хранится в localStorage текущего origin браузера; экспорт JSON остаётся резервной копией. После подключения общая версия хранится в первой вкладке «ЕМО - Раюшкин 2026» и загружается на другом устройстве после входа в Google. Другая вкладка того же origin предупреждает о конфликте локального хранилища и блокирует перезапись до обновления.

Демонстрация открывается по `?demo=1`, использует ключ `gengroup.task-canvas.demo.v1` и запрещает подключение/запись Google на уровне движка. Рабочий ключ `gengroup.task-canvas.v1` сохранён для совместимости. Примеры не заменяют рабочую доску. Настройки вида хранятся в отдельном ключе, OAuth-токен не сохраняется ни в одном из них.

## Командная синхронизация

Google Auth использует `openid email profile` для участника и `drive.file` для выбранного файла. Токены Google и Firebase остаются в оперативной памяти (`inMemoryPersistence`), Firestore SDK использует memoryLocalCache. Публичные настройки клиента в team-config.json не являются серверными ключами. Приложение не передаёт задачи в OpenAI или GitHub.

Основная база: Google Cloud Firestore проекта `my-project-1539119750357`, база `(default)`, eur3, бесплатный Spark без платёжного аккаунта. Доска фиксирована ID исходного файла. Редактирование требует подтверждённый Google-аккаунт владельца или участника из members. Права файла Sheet и Firestore независимы. Реестр прежних администраторов не обходит список команды.

Каждая задача хранит ревизию и отдельные версии групп полей. Назначение/срок/приоритет объединены с позицией соответствующего представления. Разные группы сливаются, конкурирующие значения одной группы сохраняются в документах conflicts. Сравнение основано на версии, поэтому замечается и изменение с возвратом прежнего текста. В диалоге нет выбора по умолчанию; сохранение сверяет именно версию, которую показывали при открытии. Изменение во время сравнения обновляет диалог. Архивирование одновременно с правкой также требует выбора.

Новая задача, её история до/после и квитанция операции записываются одной серверной транзакцией. История, квитанции и исходные альтернативы конфликтов неизменяемы для клиентов. Постоянный ID и SHA256 содержимого делают повтор после потерянного ответа идемпотентным. Долговременная очередь в IndexedDB пополняется атомарно; вкладки захватывают отдельные операции, а последовательные офлайн-правки ссылаются на версии предыдущих операций. Сбой записи очереди оставляет текст в редакторе. Отмена меняет только поля исходного действия и тоже проверяет версию.

Реальные изменения базы приходят через onSnapshot. Без сети показана копия и очередь; после входа/возвращения сети отправка повторяется. Кэш в localStorage не используется для арбитража между вкладками. Каждая страница пишет свой слот черновика, предыдущие варианты доступны после перезагрузки. Демо сохраняет старый изолированный локальный режим.

В резервном браузерном режиме Sheets обслуживает одна вкладка владельца с арендой 120 секунд. После активации фонового режима браузерные аренды и контрольные записи блокируются правилами; единственный обработчик Apps Script использует протокол аренды 4 и блокировку запуска. Он импортирует внешние правки по версиям последней наблюдаемой таблицы, затем проецирует командную базу. Опрос примерно раз в 30 секунд и после подтверждённой правки. При неизменной таблице статус источника публикуется раз в пять минут; реальные изменения публикуются сразу. Отказы resource-exhausted сохраняют очередь и увеличивают интервал повтора от минуты до пяти минут. Если токен Sheets истёк, работа команды в Firestore продолжается, а интерфейс просит вход для обновления таблицы. В резервном браузерном режиме при закрытых браузерах проекция приостанавливается; активный Apps Script работает независимо от браузеров. Пустой опрос не перечитывает всю Firestore-базу; при исчерпании квоты операции остаются в очереди. Для большого объёма/круглосуточной команды нужно оценить квоты до включения платного тарифа; платёжный аккаунт этой доработкой не подключается.

Служебные колонки Q:V и metadata R1 сохраняются. Заголовок R3 `Позиции · команда v3` останавливает старые клиенты прямой записи: новая версия принимает исходный заголовок, v2 и v3. Старую страницу нужно обновить. Строки не удаляются физически, архив хранится в T.

Граница защиты: одновременные правки **на доске** проходят транзакции Firestore. Прямая ручная правка/сортировка Google Sheet во время записи проекции не обладает атомарностью Sheets API. Все намерения с доски остаются в истории Firestore, но для строгой защиты ручных изменений источника используйте доску или отдельный управляемый редактор. Это ограничение не следует скрывать статусом «всё сохранено».

Backend развёрнут отдельно от GitHub Pages: firestore.rules публикуются владельцем проекта после emulator tests. Публикация фронтенда сама не меняет правила. Рабочая миграция не включена в репозиторий; она переносит живой источник с постоянными ID и исходной контрольной копией. Повторная миграция поверх существующей базы запрещена. Правила и frontend версионируются; откат frontend на прямую Sheets-запись без снятия ограждения R3 запрещён.

## Проверка

На 6 ноября 2026: 81 автоматических тестов, включая 55 прежних; собственный небольшой сторож дизайна проверяет токены/шрифт/движение/viewport и отвергает 8 намеренно испорченных вариантов. Это не внешние `check_ds.py`/`tamper_ds.py` из референса. `npm test` запускает всё без установки браузера.

В текущей приёмке кликами проверены черновик после reload/Escape, ошибки назначения и квоты, предварительный импорт с отказом без подтверждения и отменой, фильтры телефона, поиск ё/е, командная палитра и перетаскивание в итоговые зоны. Локальный макет API проверяет запись/чтение, внешние обновления, новые метки и отсутствие подсветки собственных записей. Его результат не считается реальным Google round trip. Замеры DOM выполнены на 360/390/768/1024/1440 в обеих темах: контраст текста 4,5+, заголовков 7+, мобильные цели 44 px, без горизонтального переполнения страницы. На холсте при уменьшении зума используется обзор; читаемая альтернатива - список и масштаб 100%.

Физические iPhone/Android, полноценное исследование с диктором и системные forced-colors/reduced-motion в данной приёмке не эмулировались; их CSS-ветки проверены структурно. Строго одновременные записи одной ячейки Google Sheets остаются ограничением архитектуры, а не устранённым дефектом.


`npm test` проверяет переносы, границы недель и года, привязку к сетке, CSV с многострочными полями, пропуск пустых строк, сохранение формулировок, распознавание дат и валидацию JSON.

Кликами в локальном браузере проверены открытие/правка карточки, перенос между квадратами, назначение ответственного и срока переносом, отмена/повтор, импорт рабочего снимка и сохранение после обновления. Мобильная компоновка проверяется отдельно; ограничения одновременной работы описаны выше. Шрифт Golos Text загружается с Google Fonts с системным fallback.

Приёмочные проверки включают восстановление снятого исполнителя, пустой JSON, лимит объединённого импорта, отрицательные пробы хранилища (квота, конфликт вкладок, удалённое/повреждённое состояние), точное попадание в нижние квадраты, отсутствие перекрытий и полный обзор 47 карточек.

Проверки синхронизации покрывают объединение полей и конфликты, офлайн-очередь после перезапуска, правку во время запроса, потерянный ответ без дубликатов, истёкший вход, защиту формул и dropdown, постоянные ID и архив. Реальный round trip проверяется на отдельной тестовой карточке без правки рабочих задач.

Подсветка дополнительно проверяется на отсутствие ложных уведомлений от собственных записей и повторных опросов, сохранение непросмотренных отметок после перезагрузки, слияние нескольких обновлений одной карточки, удаление, конфликт и внешнее изменение во время записи.

Связанные CSS/ES modules используют одну версию `rev` в URL, чтобы новая HTML-страница не смешивалась с ранее закэшированными зависимостями. При изменении графа ресурсов обновляйте значение `application-version` и все локальные `rev` вместе; целостность проверяет тест.

На телефоне ошибки связи, истёкший вход и конфликт дополнительно показаны текстом рядом с источником; полное объяснение доступно в диалоге Google. Цвет точки не является единственным сообщением о проблеме.

Командные проверки: `npm ci --ignore-scripts`, `npm test`; затем Java 21 и `npx firebase-tools@15.35.0 emulators:exec --only firestore --project demo-task-canvas --config firebase.json "npm run test:team"`. Это отдельная demo-база без рабочих данных. Интеграция проверяет 50 конкурирующих вариантов, разные поля, историю, потерянный ответ, устаревший выбор, права и мост Sheets.

## Ежедневная работа и календарь

- «В фокусе» в фильтрах: сегодня, просрочено, 7 календарных дней (включая сегодня), без срока/исполнителя, ожидание, непросмотренное, избранное. Дата относится к сроку задачи, не ко времени встречи.
- «Мои виды» сохраняет поиск, фильтры, сортировку и вид доски в этом браузере. Избранное также личное; эти данные не синхронизируются через таблицу.
- В списке доступны сортировка и массовая правка выбранных. В квадратах/обзоре — «Изменить» в панели выделения. По умолчанию поля не меняются; перед применением есть предпросмотр.
- В карточке: ссылка, избранное, быстрые сроки, переход между задачами выбранной выборки, «Сохранить и далее», создание по образцу. Новая копия не наследует срок, комментарий, ID и ссылку исходной строки.
- «Добавить списком» в фильтрах: до 50 строк, проверка названий, исключение совпадений по умолчанию, стабильные ID при повторе сохранения.
- Календарь: день, неделя с понедельника, месяц, обзор 12 месяцев. На телефоне месяц показывает количество задач; день открывает читаемый список. Задачи без даты доступны рядом. Фильтры применяются ко всем периодам. Редактор может создать задачу на выбранный день.

Имена и фото маркетинга/ПТО собирает `tools/fetch-directory.mjs` в шаге публикации Pages, используя существующий `B24_WEBHOOK_URL` только на runner. Методы: `department.get`, `user.get` (первичные спецификации: https://apidocs.bitrix24.com/api-reference/departments/department-get.html и https://apidocs.bitrix24.com/api-reference/user/user-get.html). Публичная проекция включает только имя/фамилию, отдел, ID и локальную картинку; контакты/сырой ответ/API URL не публикуются. Фотографии HTTPS только разрешённых доменов Bitrix, с проверкой типа/размера/сигнатуры. Неоднозначное имя не сопоставляется; оригинальное имя остаётся. Отображение полного имени не переписывает строку; редактор может явно принять полное имя в карточке. Если Bitrix недоступен, доска продолжает работать с исходными именами. Дата справочника показана в состоянии доски. Новые платные сервисы не подключены.

Перетаскивание доступно также в списке и всех масштабах календаря. В списке сортировка по сроку/человеку определяет изменяемое поле; в обычном/приоритетном порядке меняется квадрат и очередь. Из алфавитной сортировки перенос включает ручной порядок. В календаре срок меняется с сохранением статуса; внутри дня меняется очередь. В обзоре месяцев число сохраняется, ограничиваясь последним днём целевого месяца. В мобильном месяце нажмите число задач, затем тяните карточку выбранного дня за ручку на нужную дату. Пробел на ручке начинает/подтверждает перенос, стрелки выбирают цель, Escape отменяет.

ПТО в этом портале — «Конструкторский отдел», Bitrix ID `189` (подтверждено владельцем 09.11.2026). Его сотрудники и дочерние подразделения входят в справочник вместе с маркетингом. Привязка использует ID, поэтому пробелы или изменение названия отдела не исключают его из загрузки.
