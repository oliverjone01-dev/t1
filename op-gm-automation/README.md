# Автоматизация ОП ГМ

Проект автоматизации отдела продаж ГМ. Живёт в отдельной ветке `op-gm-automation-v1`
и публикуется на отдельный URL, не задевая остальной сайт GENGROUP.

## URL

- Бой: `https://oliverjone01-dev.github.io/t1/op-gm/`

## Как устроена публикация

По образцу `/rop/`, `/prod/` и `/office/` (см. `.github/workflows/deploy-pages.yml`):

1. Контент проекта лежит в этой ветке (`op-gm-automation-v1`), папка `op-gm-automation/public/`.
2. Шаг `Build OP-GM automation (isolated, /op-gm/)` в `deploy-pages.yml` (в main) забирает
   ветку через `git fetch` + `git worktree` и копирует `public/` в `_site/op-gm/`.
3. Шаг обёрнут в `continue-on-error: true` - поломка проекта не валит остальной сайт.

Деплой срабатывает при каждом запуске `deploy-pages.yml` (push в main, ночные синки,
ручной workflow_dispatch). Чтобы выкатить свежие правки этой ветки без ожидания -
Actions → "Deploy to GitHub Pages" → Run workflow.

## Дизайн-система

Сайт собран на **Контур DS 1.5.1** (`kontur-ds/`). Правила: `kontur-ds/DESIGN_SYSTEM.md` и `kontur-ds/SKILL.md`.

- Цвета, размеры, радиусы, движение только из `kontur-ds/tokens/tokens.css`; в `src/*.css` своих цветов нет.
- Компоненты кита: каркас с меню-аккордеоном, шапка с выбором кабинета (`KS.seg`) и периода,
  палитра команд Ctrl+K (`KS.cmdk`), плотность (`KS.density`), плитки KPI одной панелью со спарклайнами
  и дельтой к прошлому периоду, класс цифры точкой (`KS.kind`: данные / гипотеза), статус точкой и словом
  (`KS.status`), вердикт 1.5, подсказки `data-tip`, графики-пресеты ApexCharts с таблицей-двойником,
  врезки, следующий шаг, панель деталей, смена экранов через `KS.vt`. Светлая и тёмная тема.
- Липкие шапки таблиц (с 1.4): широкие таблицы обёрнуты в `ks-table-wrap--scroll` (хелпер `scrollWrap`
  в `src/opgm.js`), иначе шапка наезжает на строки внутри прокрутки.
- Пакет не правится. Новая версия системы: заменить папку `kontur-ds/` целиком и пересобрать.
- Проверка перед публикацией:
  `python3 kontur-ds/tools/check_ds.py <страница без шифроблока> src/*.css src/*.js` и живой контраст
  всех экранов за паролем (функция из `kontur-ds/tools/contrast_live.mjs`) в обеих темах и обеих плотностях.
  Внимание: на `public/index.html` с шифроблоком сторож работает очень долго, проверять копию без поля `ct`.

Рядом с сайтом лежат страницы самой дизайн-системы (без данных ОП ГМ и без пароля):
- настройка вида шаблона: `/t1/op-gm/kontur-ds/templates/nastroyki.html`;
- образцы: `.../templates/obzor.html`, `treker.html`, `otchet.html`, `starter.html`;
- витрина всех элементов: `/t1/op-gm/kontur-ds/specimen.html`.
Вид, сохранённый на странице настроек, действует на шаблоны рядом с ней (папка `templates/`), а не на сайт ОП ГМ:
у сайта своя папка и свой ключ настроек. Чтобы перенести вид на сайт, «Код для проекта» кладётся в
`kontur-ds/kit/brand.js` и сайт пересобирается.

## Разделы

Навигация спроектирована СПАРТАКОМ под две роли:

- **Детализация** (с 29.09.2026, первый пункт, стартовая страница «Обстановка») - семь подразделов одной
  страницей: Обстановка, Куда уходят клиенты, Дожим и скорость, Как звучит в чате, Цена, Причины и возражения,
  Список на понедельник. Раздел пришёл архивом `glass-memory-detalizaciya` (данные Авито, 2 кабинета, 8 недель).
  Числа из переписки идут с меткой «данные», смысловая разметка диалогов (стадии, причины, реакция на цену,
  оценка эффекта дожима) с меткой «гипотеза». Нормы 70 / 85 / 30 / 20% черновые и ждут подтверждения CMO.
  Устройство:
  - код раздела `detalizaciya.js` и его данные вне репозитория и на сайте только в шифроблоке: в них ID диалогов
    и сводные цифры; код подключается после ввода пароля;
  - расширение дизайн-системы `kx` (`src/kx/kx.css`, `src/kx/kx.js`) работает только внутри раздела: класс `.kx`
    стоит на контейнере раздела, а не на всём приложении, палитра ⌘K, подсказки `data-kx-tip` и перехват кликов `data-kx-drill`, `data-copy`
    у `kx` включены только на экранах «Детализации»; на остальных экранах работают палитра и панели кита;
  - нарушения правил Контур DS в `kx.css` исправлены при установке: токены вместо `#fff` и `rgba()`, капс рецептом
    `--tracking-caps`, подъём по наведению только для мыши; скелетон, спиннер кнопки и приглушение полос потока
    помечены выключателем `--ks-allow` с причиной.
- **Сегодня** - очередь менеджера: жалобы, не ответили, вопрос последним, оставил телефон, цена без суммы.
  Только чаты, где последним написал клиент.
- **Пульс ОП** - экран РОПа: вердикт за период, плитки по каждому кабинету, недельные графики, цена, звонки,
  объявления, гарантия, следующий шаг (Иван и РОП, 06.10.2026).
- **Аналитика Авито** - скорость, типовые проблемы с правилом и замером точности, объявления, звонки, рассылка.
- **Разборы** - все диалоги с фильтрами и переписка целиком; детальные разборы v3.

Период в шапке (7, 30, 90 дней, весь ряд) отсчитывается назад от выгрузки. Если в одном из периодов
меньше 10 диалогов, дельта не показывается, а кабинет не входит в вердикт.

## Как пересобрать с новой выгрузкой

1. Слой Авито. Сырые выгрузки хранит Иван у себя, в репозиторий они не попадают; рабочие файлы только во временной папке.
   - Еженедельно (окно «чаты с updated не раньше periodFrom», без CSV): склейка с принятой сборкой.
     Достать D.av из шифроблока `public/index.html` в A.json (как в `src/build.cjs`, шаг 1), затем
     `python3 src/merge_av.py A.json <raw1.json> <raw2.json> <папка>`. Кабинет каждого файла определяется по пересечению
     channelId с A, не по имени файла. periodFrom окна не позже прошлой выгрузки минус сутки (следующее окно: не позже
     понедельника прошлой недели 00:00 МСК). Любое нарушение правил склейки = код выхода 2 и причина. Правила С1-С11:
     `knowledge/episodes/2026-09/feniks-decisions-opgm-restyle-20260929.md` (ветка сессии), §3.
   - Полная выгрузка с CSV: `python3 src/build_av.py OLD_RAW.json OLD_INDEX.csv NEW_RAW.json NEW_INDEX.csv <папка>`.
   - Приёмка: `python3 tools/accept_dpack.py A.json <raw1.json> <raw2.json> <папка>/av.json <папка>/recon.json`
     (независимый пересчёт, код сборки не импортирует; провал = код выхода 1).
2. `OPGM_PW=<пароль> node src/build.cjs <av.json> <recon.json>` - пароль передаётся только через переменную окружения
   и в репозиторий не попадает. Смена пароля: `OPGM_PW_OLD=<старый> OPGM_PW=<новый> node src/build.cjs ...`.
   Ввод пароля нормализуется одинаково при сборке (расшифровка и шифрование) и на странице входа (normPw).
   Пароль и любые его свойства не писать в репозиторий, эпизоды и трейсы: репозиторий публичный.
   «Детализация»: новая неделя собирается `drafts/build_package.py` в `sales-detalizaciya` в `data.js`. Папка раздела
   с `data.js` и `detalizaciya.js` передаётся третьим аргументом: `node src/build.cjs <av.json> <recon.json> <папка>`.
   Оба файла живут вне репозитория (`src/detal/` в .gitignore): в данных ID диалогов, в коде сводные цифры раздела.
   На сайт они идут только в шифроблоке. Без третьего аргумента остаются данные и код прошлой сборки.
3. Перед публикацией: сверка цифр с независимым пересчётом и Step 12.5 (ФЕНИКС).

Данные в открытом виде (выгрузки, `av.json`) в репозиторий не коммитятся: там имена и телефоны клиентов.

## Откат

Revert одного `public/` не годится: прошлая сборка зашифрована прежним паролем, действующий её не откроет.
Откат делается пересборкой прошлого кода текущим паролем:

1. `git archive <коммит> op-gm-automation | tar -x -C <папка>` - код прошлой версии во временную папку.
2. Положить туда текущий `public/index.html` (в нём данные) и собрать её `src/build.cjs` с действующим `OPGM_PW`.
3. Скопировать собранный `public/` в ветку, закоммитить, запустить deploy-pages.

Проверено 23.09.2026 на v5 (ddb5115e): сборка прошла, вход действующим паролем открывает «Пульс».
Время около 10 минут.

## Правила

- Вся разработка проекта - в ветке `op-gm-automation-v1`, не в main.
- С 1.5.1 кит хранит настройки вида (`KS.prefs`) под ключом своей папки сайта (`ks-prefs:/t1/op-gm/`): вид,
  сохранённый на странице Контур DS из другой папки того же github.io, к этому сайту не применяется. От нарочной
  записи в этот ключ со страницы того же адреса ключ не защищает (предел одного источника в браузере). Своего
  обхода в проекте нет.
- Тема и плотность на телефоне в меню (`.ks-sidebar-tools` в `src/shell.html`), их включает кит.
- Статика рядом с сайтом: кит, код и ApexCharts лежат в `public/`. Снаружи только шрифт Golos Text с Google Fonts, как в Контур DS.
- Перед публикацией содержательных артефактов - Step 12.5 (ФЕНИКС), как для любого критического деливерабла.
