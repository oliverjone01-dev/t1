# GG Sales Academy

Аналитическая учебная платформа отдела продаж. Строится с разборов качества работы с клиентами и личных кабинетов.

Проект архитектуры: `knowledge/episodes/2026-08/`. Методика разбора: `.claude/skills/kostya-ai/`.

## Три контура, а не три раздела одного сайта

Контур определяется классом данных внутри, а не темой. Это главное решение, из которого следует всё остальное.

| Контур | Что внутри | Персональные данные | Где живёт | Коммитится |
|---|---|---|---|---|
| **1A. Библиотека** | Методика, нормативы отдела в агрегате, квалификация, возражения, дожим, эскалация, фразебук, материалы, глоссарий, правовая страница, changelog | Нет | GitHub Pages, `/academy/` | Да |
| **2. Кабинет** | Личный разбор: имя, цитаты клиентов, суммы сделок, задача на 14 дней | Да | Локальная сборка, раздача файлом | Никогда |
| **3. Штаб** | Сводка РОПа и панель Ивана: все менеджеры сразу | Да | Локальная сборка, 2 получателя | Никогда |

Почему так. При статике без бэкенда роль на клиенте не проверяется, её обходят через просмотр исходного кода. Роль **запекается**: менеджер не видит данные коллеги не потому, что ему запрещено, а потому что их нет в его файле.

Побочный выигрыш: библиотека это большая часть объёма платформы, и она не содержит персональных данных. Её можно развивать и публиковать, не дожидаясь снятия вето, которое стоит на контурах 2 и 3.

## Гейт: почему в контурах разная механика

| Контур | Механизм | Что реально защищено |
|---|---|---|
| 1A | SHA-256 плюс `sessionStorage`, как на `gg-seo-geo-monster` | Ничего. Это ширма от случайного взгляда, и её достаточно: прятать нечего |
| 2, 3 | Payload зашифрован: PBKDF2-SHA256 600 000 итераций, AES-256-GCM, соль своя на файл | Содержимое. Без пароля в файле нет читаемого текста, включая просмотр исходного кода |

Гейт образца 1A **прячет** контент, лежащий в файле открытым текстом. Для методики это честно. Для персональных оценок сотрудников недопустимо, поэтому кабинеты шифруются по-настоящему.

```bash
# Контур 1A: библиотека, публикуется
ACADEMY_PASS='пароль-отдела' node gg-sales-academy/src/build-library.mjs > gg-sales-academy/public/index.html

# Контур 2 и 3: кабинеты и штаб, локально
#  1. Данные из выгрузки диалогов

python3 .claude/skills/kostya-ai/scripts/dialogs-normalize.py /tmp/dialogs.jsonl /tmp/msgs.jsonl
python3 .claude/skills/kostya-ai/scripts/dialogs-analyze.py /tmp/msgs.jsonl /tmp/analysis.json
#  2. Снимок сделок из ветки данных
git show origin/rop-dashboard-v1:analytics-mvp/rop/data/rop.json > /tmp/rop.json
node .claude/skills/kostya-ai/scripts/kostya-audit.mjs /tmp/rop.json > /tmp/kostya.json
#  3. Страницы
python3 .claude/skills/kostya-ai/scripts/build-pages.py /tmp/analysis.json /tmp/per_manager.json /tmp/cab /tmp/kostya.json
#  4. Шифрование и гейт
node .claude/skills/kostya-ai/scripts/build-platform.mjs /tmp/cab gg-sales-academy/build
```

Сборка кабинетов падает, если plaintext просочился в готовый файл. Это не предупреждение, а остановка.

## Пароли

Генерируются сборщиком в `PASSWORDS.local.json`, в git не попадают. Формат: три слова из производственного словаря плюс число, чтобы пароль можно было продиктовать по телефону.

Пересборка не меняет уже выданный пароль: файл паролей читается перед генерацией.

**Раздача: файл одним каналом, пароль другим.** Письмо, где в одном теле лежит и файл, и пароль, обнуляет всю схему.

## Чего схема не даёт

Написано здесь, а не в примечаниях, потому что это ограничения модели, а не мелочи реализации.

1. **Нет отзыва доступа.** Выданный файл работает бессрочно. Ротация пароля влияет только на следующую сборку.
2. **Нет журнала открытий.** Кто и сколько раз открыл, файл не знает.
3. **Пароль не равен человеку.** Аутентификации личности нет.
4. **Пересылка не предотвращается.** Водяной знак это сдерживание, не защита. Скриншот не ловится в принципе.
5. **Подбор пароля при утечке файла идёт офлайн.** Держится на длине пароля и стоимости PBKDF2.
6. **Потеря пароля лечится только новой сборкой.**

Потолок схемы известен: если понадобятся отзыв доступа и журнал, это HTTP Basic Auth на nginx с отдельным логином на человека. Не бэкенд и не БД, шесть строк конфига. Нужен хостинг под контролем холдинга.

## Правило единственного источника

Контент не живёт в коде генераторов. Расхождение между тем, что менеджер видит в кабинете, и тем, что написано в библиотеке, разрушает доверие быстрее любой ошибки в цифрах.

Сейчас это правило нарушено: системные дефекты продублированы в `build-pages.py` и в `build-library.mjs`. Вынос контента в `src/content/` стоит в очереди 1.
