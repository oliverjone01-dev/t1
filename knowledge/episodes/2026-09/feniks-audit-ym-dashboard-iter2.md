## 1. Ответы на три вопроса автора

### Q1. Есть ли ещё путь к тихой потере накопительных данных

Да, четыре, и три из них гейт не закрывает вообще.

1. **`orders.ndjson` не сторожится ничем.** Шаг «Промежуточный коммит факт-слоя»
   (`.github/workflows/ym-snapshots.yml:91-117`) делает `git add -A analytics-mvp/data-ym` + commit ДО шага гейта
   (`:136-148`), а `prev()` там читает `git show HEAD:`. То есть baseline для orders пишется этим же прогоном.
   Проба: `npx tsx src/scripts/ym/validate-facts.ts /tmp/ym_cur.ndjson /tmp/ym_cur.ndjson --month-key=d --sum=amount`
   печатает «строк 200 -> 200, потерь нет», exit=0, при том что в фикстуре выкинуто 200 строк из 400.
   Гейт на orders структурно не может сработать в тот единственный момент, когда он нужен.
2. **`sku_views.ndjson` (1.6 МБ, кормит воронку, `daily_totals`, `history`) не передан в гейт вовсе**:
   в workflow только `netting`, `orders`, `realization_monthly`. Дефект DAY-как-даты (20 388 строк на 733 ключа)
   был из этого файла, и поймал его человек, а не гейт.
3. **Порог выключается переменной окружения без валидации.** `YM_FACTS_DROP_GATE=abc` даёт `Number('abc') = NaN`,
   сравнение `c.n < NaN` всегда false: exit=0 и печать «потерь нет» при потере 50% месяца.
   `YM_FACTS_DROP_GATE=1` отключает гейт целиком, сообщение то же. Это ровно та дыра класса env-override,
   за которую якорь ТИМУР держал 7.9 (`validate-facts.ts:14,45`).
4. **Гранулярность порога грубее гранулярности чистки.** Чистим по паре (кабинет, месяц)
   (`reports.ts`, `purged.has(\`${r.business}/${r.d.slice(0,7)}\`)`), а сторожим по месяцу целиком
   (`validate-facts.ts:35`, `slice(0,7)` без кабинета). На живом `netting.ndjson` минимальная доля пары
   в своём месяце 19.2% (1023124/2026-06), значит потеря половины кабинета за месяц (9.6%) проходит под порогом 10%.
   Сегодня полная потеря любой пары гейт разбудит (проверил все 18 пар), частичная - нет.

Отдельно: гейт **односторонний**. Он сторожит только просадку. Любой рост, включая задвоение, проходит молча.
Это и делает следующий пункт боевым.

### Q2. Не создаёт ли переоткрытие пар реализации задвоение

Создаёт. Утверждение «переоткрываются только пары с нулевым вкладом» на живом состоянии ложно.

Проба (симуляция цикла `reports.ts:117-125` на `data-ym/realization_state.json`):

```
done pairs before: 38  reopened: 13  left: 25
месяцы с переоткрытыми парами: 2026-02, 2026-03, 2026-04, 2026-08
  2026-02: строк 43, продано 61 шт, сумма 1 259 030 руб
  2026-03: строк 47, продано 67 шт, сумма 1 262 655 руб
  2026-04: строк 43, продано 70 шт, сумма 1 262 585 руб
  2026-08: строк 44, продано 58 шт, сумма   952 805 руб
СУММА под риском задвоения: 4 737 075
rows with 'from' field: 0
```

Механика: признак «пара ничего не дала» берётся из `shops_with_rows`, а тот теперь наполняется из поля `from`,
которого нет ни у одной из 177 строк `realization_monthly.ndjson` (файл собран версией без поля).
В состоянии `shops_with_rows = []` у 2026-02, 03, 04, 05, 06, 07, 09 и `['149154933']` у 2026-08.
Поэтому цикл открывает пары, которые строки давали. Дальше `bySku` засеян из `existing`
(`reports.ts`: `b[r.sku] = {sold: r.sold, ...}`), а разбор добавляет: `a.sold += ...`, `a.amount += ...`.
Вычитания прошлого вклада пары нет. Второй разбор той же пары кладёт второй слой.

Второй порядок: починка №2 (наполнять `shops_with_rows` из данных) сегодня инертна, потому что `from` пуст,
и единственный путь её оживить проходит через починку №1, то есть через задвоение. Две правки, каждая разумная,
в связке дают порчу.

Тест, который «доказывает» инвариант (`reports-lib.test.ts:178-196`), переписывает продовый цикл локальной копией
и берёт фикстуру `shops_with_rows: ['A']`. В живых данных этот массив пуст. Тест зелёный, инвариант не проверен.

Гейты не поймают: `validate-facts` ловит только просадку, дельта-гейт смотрит 30-дневные производные,
md5 OZON и smoke к числам Маркета не относятся. Поймает `ym:reconcile` (штуки реализации против доставленных),
но уже после того, как накопительный файл перезаписан.

### Q3. Не выдаётся ли неизвестность за факт

Три места, одно введено этим диффом.

1. **`ДРР канала, %` = `0%`** на `public/market/marketing.html` при расходе 541 772 ₽, при том что на той же
   странице пилюля говорит «кабинета кампаний у Маркета в API нет: ДРР и CPO не считаются», и `ads_30d.json`
   несёт `totals.drr = 0` рядом с `spend = 541771.93`. До этого диффа расход был 0 и нолик читался согласованно,
   теперь страница спорит сама с собой. Это регрессия дельты.
2. **Покрытие 2026-02 / 03 / 04 подаётся как факт.** Пилюля печатает «реализация: 2026-02, 2026-03, 2026-04,
   2026-08 · закрытый месяц добран 1/7 магазинов». Про 02/03/04 покрытие неизвестно (`shops_with_rows = []`),
   и честное «неизвестно, а не нулевое» реализовано в `reconcile-lib.ts` только для предыдущего месяца.
3. **`closedMeta.updated = 1970-01-01`** лежит в блобе 6 страниц. Сейчас не рендерится (узлы `#pnl`/`#pnlMeta`
   для Маркета выключены), поэтому это не ложь на экране, но мёртвая метадата в опубликованном артефакте.

## 2. Что в дельте сделано сильно (для протокола, не для смягчения оценки)

- Разложение сверки денег на ноги с признанием «нога сборов ноль тождественно, значит проверяются только
  начисления» (`reconcile-lib.ts`). Это редкая честность: сверка перестала притворяться проверкой сборов.
- «Строки есть, разбивки нет» -> `known: false`, а не «0 из 7». Проверяемо ложное утверждение снято.
- Ключ чистки реестра приведён к ключу возобновляемости (`business/YYYY-MM` с обеих сторон), список чистки
  строится из запрошенных пар, а не из ответа.
- Гейт накопительного слоя реально падает: проба на фикстуре из живого `netting.ndjson` дала
  `FACTS INVALID: 2026-01 строк было 400, стало 200`, exit=1.
- Разделение платформ в `site.ts` + сторож в `smoke.ts` на текст про Акты, зашитые месяцы OZON и нераскрытые
  плейсхолдеры.
