# Probe: отчёт продвижения OZON с листом Union (объединённая карточка)

Дата: 2026-10-01. Источник: выгрузки кабинета OZON Performance, присланы Иваном 01.10, март-июль 2026 (по месяцу на файл).

## Структура
- Лист `Statistics`: строка = SKU x кампания x место размещения. Поля: Расход; «Продажи в продвижении, ₽» и «Продано товаров, шт» (сам рекламируемый SKU); «Продажи в продвижении с заказов модели, ₽» и «Продано товаров модели, шт» (другие SKU объединённой карточки). Свои и модельные продажи не пересекаются: «ДРР в продвижении» = расход / свои продажи (проверено на 8 строках апреля).
- Лист `Union`: строка = SKU в продвижении x кампания x SKU из объединённой карточки, с продажами ₽ и шт. SKU сам с собой не встречается (0 строк).

## Подвохи
- Union больше «продаж модели» в Statistics на 0-11% (апрель 6 609 649 против 6 216 061): разница - пары, у которых в Statistics расход 0 и модель 0. На разнесение расхода не влияет (делить нечего).
- 9 пар из 66 (март) и 7 из 81 (апрель) по Union лежат в РАЗНЫХ карточках по снимку `data/card_groups.json` (23.09): состав карточек менялся. Для разнесения брать Union своего месяца, а не снимок.
- API (`data/ads_attr_daily.ndjson`, поля omM, soldM) отдаёт модельные продажи итогом по SKU, без разбивки по соседу; покрытие неполное (июль: 608 244 расхода против 808 971 в отчёте на тех же 18 парах). Отчёт и API - одно семейство (OZON), это не сверка.
- Отчёты за август и сентябрь присланы Иваном 01.10 (сессия v15), в репо не лежат - сверка ниже.

## Проба API 01.10 (Actions run 36855939046, кампания 40047060, 01.09-01.10)
- Attribution-отчёт API (`/api/client/statistics`, CSV) отдаёт по SKU «Продано товаров модели» и «Продажи с заказов модели» итогом, листа соседей (Union) нет.
- Обходной путь: сосед = заказ товара той же карточки в день атрибуции, штуки = soldM, сумма = omM (допуск 1%). Проверка против Union март-июль: внутри карточки 21 из 22 совпали, по всему магазину 4 из 6 (не используем), 1 не найден.
- Атрибуция OZON включает заказы, которые потом отменены (пример: 0210427575-0149-1, 28.09).
- Август: CPC 1 214 589, пары с атрибуцией 973 335 (80%), на соседей 227 519, без атрибуции 241 254. Сентябрь: 791 263, 746 742 (94%), 281 596, 44 521.

## Сверка с отчётами кабинета август-сентябрь (01.10, сессия v15)
Одно семейство источников с API (кабинет OZON Performance): это проверка МЕТОДА поиска соседа и полноты нашего сбора, а не независимая сверка денег.
- Найденные соседи против листа Union: август 10 из 10, сентябрь 18 из 18 (28 из 28; вместе с мартом-июлем 49 из 50).
- Доля CPC на соседей (по шт, лист Statistics): август 352 034 по отчёту против 227 531 у нас, сентябрь 316 746 против 281 606. Недосчёт - из-за пропусков сбора, не из-за метода.
- Штуки по парам (свои / модели) разошлись в 14 парах августа и 6 сентября; пар с продажами по отчёту и без атрибуции в нашем сборе - по 6 в каждом месяце.
- Покрытие сбора атрибуции по дням (доля CPC в днях со строкой атрибуции): август 46,4% (563 109 из 1 214 589), сентябрь 86,8% (687 040 из 791 263). «Покрытие по парам» 80% / 94% его завышало.
- CPC сентября: отчёт 819 925, у нас 791 263 (данные по 29.09). Август: 1 214 592 против 1 214 589.
- 40047060 (GGT-46): в сборе 22 дня из 26, все с нулями; продажа соседа на 75 900 из пробы API - в пропущенный день.
