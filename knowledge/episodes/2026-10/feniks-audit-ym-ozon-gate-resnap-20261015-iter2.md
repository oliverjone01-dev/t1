## Ответы на четыре вопроса автора

### 1. Что глушит `|| echo "::warning::"`

Только пересъём. Проверено исполнением, не чтением.

**Структура.** yml:148-151 - один and-or список: `( cd analytics-mvp && md5sum public/*.html > public.md5 && { md5sum data/* | grep -v competitors > data.md5 || true; } && echo ... ) || echo "::warning::..."`.
- `git reset --hard` (yml:138) - отдельная команда строкой выше.
- Наложение `cp -r /tmp/ym-keep/data-ym/. analytics-mvp/data-ym/` (yml:162) - отдельная команда ниже.
- Продолжения строк чистые: последний байт строк 148-150 - обратная косая черта.

**Пробы** (`iter2_q1_probes.py`, настоящий шаг bec7a87, `-eo pipefail`):
- P1, сбой reset (шим, exit 128): шаг rc=128, ни пересъёма, ни `::warning::`, remote y1. Не заглушен.
- P2, сбой наложения cp после пересъёма: в логе «слепок OZON переснят на ...», затем rc=1. Не заглушен.
- P3, resnap_fail: `::warning::` в шаге промежуточного коммита, push идёт (y2), гейт rc=1 «public.md5: no properly formatted checksum lines found».
- P5, гонка: лог «слепок OZON переснят на 85f1586: 2 html, 2 data», 85f1586 - голова main после fetch.

**`|| true` внутри** закрывает только ветку data, ровно как yml:91.
- Глушит то же, что и исходный слепок: ошибки md5sum на подкаталогах data/ (под pipefail иначе падало бы всегда), нечитаемый файл (он выпадает из data.md5) и пустой вывод grep.
- pathequiv: пересъём совпадает со слепком yml:86 байт-в-байт.

**Хрупкость на будущее (P4, не дефект).** Слева от `||` bash снимает `-e` внутри сабшелла.
- `( false; echo A ) || echo warn` печатает A и не печатает warn.
- Сейчас цепочка целиком на `&&`, поэтому сбой доходит до `||`.
- Если кто-то добавит строку внутрь скобок без `&&`, её сбой пройдёт молча и `::warning::` не появится. Тест этого не ловит. Достаточно строки в комментарии: «внутри скобок только через &&».

### 3. Остаточное окно гонки

Окна, описанного в self-check (чекпоинт 21), нет. После фикса чужой коммит гейт не роняет ни в каком окне.

- **Статика.** Git-операции, меняющие дерево (без комментариев):
  - yml:136/138 - fetch и reset промежуточного коммита, за reset идёт пересъём;
  - yml:301/303 - fetch и reset финального коммита, после гейта (yml:271).
  - В npm-скриптах ym:* git нет. `child_process` вне *.test.ts в src/scripts/ym нет.
  - Между промежуточным коммитом и гейтом дерево меняют только наши продьюсеры.
- **Динамика.** late_foreign (чужой OZON-коммит после успешного промежуточного push): PASS на bec7a87 и на 9a3a212. Гейт сравнивает локальное дерево с локальным слепком. Чужой коммит увидит только финальный push, и его reset идёт уже после гейта.
- **Как окно вернуть.** Только новой операцией смены дерева до гейта (M8). Тест этого не заметит.

**Настоящие остаточные риски:**
- (а) сбой пересъёма: редкий, нужен main без public/*.html. Гейт красный с сообщением не о причине (N3);
- (б) G5, слепота к новым файлам и подкаталогам, как до фикса;
- (в) регресс при будущей правке шага: тест слабый и не запускается (N1, N2);
- (г) финальный reset после гейта не проверяется. Коммит стейджит только data-ym и public/market (yml:292, 322), поэтому OZON-файлы на main мы не меняем (итерация 1).

Ошибка self-check в безопасную сторону, но у неё есть второй порядок. Кто прочтёт «гейт может упасть от гонки», спишет на гонку и настоящий красный гейт.
- Верная формулировка для PR и E088: «после фикса красный гейт OZON означает правку OZON самим прогоном или сбой пересъёма (смотри `::warning::` в шаге промежуточного коммита)».
