## K1: ложное «заказы закоммичены» (регрессия iter2)

Строка 172 теперь сравнивает `!= success`, раньше было `= failure`. Мотив в комментарии 171: «шаг, оборванный по timeout-minutes, может прийти cancelled». Исходник раннера это опровергает (G1). Таймаут шага даёт failure, его ловило и старое условие. `Canceled` ставится только при отмене всего job, а тогда `if: !cancelled()` не даёт финальному шагу запуститься.

На практике расширение добавило один случай: `skipped`. Он возникает, когда падает «Сбор по заказам», ровно как в run 55. Шаги ниже уходят в skipped, коммит без `if` пропускается. Финальный шаг при этом запускается и пишет:

```
::error::начисления: по SKU skipped, эквайринг skipped, канальный P&L skipped - заказы закоммичены, перезапусти workflow
```

На 54569ad этот сценарий даёт exit 0 без сообщения (W1, `probe-final-step.py`). Цвет прогона не меняется. Но после #484, где заказы «молча не доходили», ложная фраза про коммит может ввести в заблуждение того, кто читает аннотации. Исправить можно двумя способами:
- вернуть `= failure` и поправить комментарий;
- дать шагу коммита `id` и печатать «заказы закоммичены» только при его success.
