# Реестр ошибок работы с цифрами

`registry.jsonl`: одна строка = один повторяющийся тип ошибки (55 записей, каждая отнесена к одному из классов К1-К14) с симптомом, корнем, правилом, способом проверки (где возможно, автоматической) и доказательствами (коммиты, файлы). Обезличено: без фамилий, телефонов, email, номеров заказов.

Создан 29.09.2026 из ретро 9 чатов аналитики (337 найденных косяков [ДАННЫЕ, ручная разметка коммитов, верхняя граница]) (ОЗОН v1, v2, v3; ЯМ v1, v2; Дашборды GENGROUP v1; РОП ГГ 28.09 и 29.09; Я.Директ). Пополняется на шаге 8 скилла `data-guard` в конце задачи; лестница эскалации и формат: `.claude/skills/data-guard/references/retro.md`.

Использование:
- `python3 .claude/skills/data-guard/scripts/registry_match.py "<задача>"` - похожие прошлые ошибки (pre-mortem);
- `python3 .claude/skills/data-guard/scripts/registry_match.py --validate` - проверка формата и отсутствия персональных данных;
- хук `data-guard` сам показывает до 3 похожих ошибок, когда сообщение похоже на работу с цифрами.

Разбор реестра раз в месяц в `/reflexion`: срабатывание = новый случай с тем же корнем (растёт `count`, обновляется `last_seen`); записи, у которых `last_seen` старше 3 месяцев, объединяются или удаляются. Менять реестр может любая сессия через PR; удаление и объединение записей только на рефлексии.

Реестр не входит в хеш аудита (`audit_hash.py` исключает `knowledge/errors/`), чтобы запись ретро после go не требовала нового аудита. Поэтому реестр не является доверенным источником решений: это подсказки для pre-mortem, а не правила.
