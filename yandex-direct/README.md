# Yandex Direct - рабочая папка

Рабочее пространство по настройке и оптимизации Яндекс.Директ для брендов GENGROUP.
Ветка: `claude/yandex-direct-optimization-c96txb`.

## Что здесь лежит

### `skills/direct/` - skill аудита и оптимизации Директа (staged)

Vendored open-source skill для AI-агентов (Claude Code / Cursor), API Директа v5.

| Параметр | Значение |
|---|---|
| Источник | https://github.com/Silverov/yandex-direct-skill |
| Авторы | Nick Serebrov & Kobe |
| Лицензия | MIT (файл `skills/direct/LICENSE`) |
| Дата снимка | 2026-07-08 |
| Реализация | shell + curl + jq |

Возможности:
- `audit` - полный аудит аккаунта, 55 проверок (YD01-YD55), скоринг 0-100 и оценка A-F
- `campaigns` - список кампаний со статусами и метриками
- `create` - создание кампаний
- `keywords` - работа с ключами (добавление, пауза, ставки)
- `report` - отчёты (CTR, CPC, конверсии, расход)
- `optimize` - рекомендации по эффективности бюджета
- `budget` - анализ расхода и прогноз
- `negative` - минус-слова против слива бюджета

Веса категорий аудита: Конверсии/Метрика 25%, Слив бюджета 20%, Структура аккаунта 15%,
Ключи/качество 15%, Объявления/расширения 15%, Настройки/таргетинг 10%.

## Security review (проведён перед внесением)

- Скрипты обращаются только к официальным эндпоинтам: `api.direct.yandex.com/json/v5`
  и `/json/v5/reports`. Сторонних хостов нет.
- OAuth-токен читается локально из `~/.secrets/yandex-direct.json` и передаётся только
  в заголовке `Authorization: Bearer` к API Яндекса. Токен нигде не хардкодится и не
  уходит на сторону.
- Нет `eval`, нет `rm -rf`, нет исполнения удалённого контента.

## Активация

Skill подключён в живой ростер (`.claude/skills/direct/`). Для работы нужны два условия,
оба настраиваются в окне настроек окружения Claude Code on the web.

### 1. Токен (аутентификация)

Скрипты берут учётные данные в порядке приоритета:
1. Переменные окружения (рекомендуется для web) - `YANDEX_DIRECT_TOKEN`,
   опционально `YANDEX_DIRECT_LOGIN` (логин клиента для агентских аккаунтов).
2. Локальный файл (для терминала) - `~/.secrets/yandex-direct.json`
   формата `{ "oauth_token": "...", "client_login": "..." }`, права `chmod 600`.

Переменные окружения задаются в настройках окружения (формат `.env`, без кавычек):

```
YANDEX_DIRECT_TOKEN=<OAUTH_TOKEN>
YANDEX_DIRECT_LOGIN=<логин-клиента>
YANDEX_METRIKA_TOKEN=<OAUTH_TOKEN_METRIKA>
```

Переменные применяются при старте новой сессии. Токен получается через OAuth-приложение
Яндекса с доступом к API Директа (https://yandex.ru/dev/direct).

Важно (безопасность): в Claude Code on the web выделенного secrets-store пока нет,
переменные окружения видны тем, кто может редактировать окружение. Токен в git не коммитить.

### Хранение секретов (тот же паттерн, что в analytics-mvp)

- В git коммитится только шаблон `yandex-direct/.env.example` (пустые значения).
- Реальные токены кладутся в `yandex-direct/.env` - он в `.gitignore` и на GitHub НЕ уходит.
- `.gitignore` закрывает: `**/.env`, `**/.env.local`, `**/.secrets/`, `yandex-direct.json`.
- Приоритет чтения токена скриптами: переменные окружения → `yandex-direct/.env` →
  `~/.secrets/yandex-direct.json`. Реальные ключи в репозитории не хранятся никогда.

### 2. Сетевой доступ

Сетевая политика окружения по умолчанию блокирует внешние домены (прокси отдаёт 403 на
`api.direct.yandex.com`). В настройках окружения нужно выбрать уровень доступа Custom и
добавить в Allowed domains:

```
api.direct.yandex.com
api-metrika.yandex.net
```

Без этого скрипты не достучатся до API даже с валидным токеном.

### Зависимости

`curl` и `jq` уже присутствуют в окружении (проверено).

## Дисциплина работы

Любая задача с цифрами (эффект на выручку, CPA, ROMI, бюджеты) проходит Protocol 9
(Reality Audit) до выводов. Каждая цифра помечается `[ДАННЫЕ]` (с источником) или
`[ГИПОТЕЗА]` (с допущениями). Критические артефакты - через Step 12.5 (ФЕНИКС).
