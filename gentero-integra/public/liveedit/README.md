# liveedit - правка блоков на странице и история версий

Два модуля, которые встраиваются одной строкой в любой внутренний проект.

- **blockedit** - клик по любому тексту, правка на месте, сохранение на сервер.
- **versions** - история версий с откатом, как в Google Docs, со своей панелью.

Хранилище общее: Supabase (тот же проект, что у модуля комментариев) или
localStorage. Содержимое можно шифровать в браузере, тогда сервер видит только
base64 и не может ни прочитать текст, ни найти его поиском.

## Встройка

```html
<script src="https://oliverjone01-dev.github.io/t1/smm/liveedit/liveedit-init.js"
        data-doc="имя-проекта" data-code="1234" defer></script>
```

Панели по умолчанию скрыты. Чтобы их увидеть, откройте страницу с `?edit=1` и
введите код редактора. Обычный зритель документа не видит ни кнопок, ни
подсказок: у него патчи просто применяются к тексту.

## Параметры (data-атрибуты)

| Атрибут | Зачем | По умолчанию |
|---|---|---|
| `data-doc` | Ключ документа. Разные значения = разные истории, одна база на все проекты. | путь страницы |
| `data-root` | Корень правимой области. | `#doc`, иначе `body` |
| `data-selector` | Что считать блоком. | заголовки, абзацы, пункты списков, ячейки таблиц, всё с `data-edit` |
| `data-code` | Код редактора. Без него правку не включить. | пусто (правка без кода) |
| `data-storage` | `local` = только этот браузер. | общая база |
| `data-auto` | Авто-снимок версии каждые N правок, `0` выключает. | `8` |
| `data-always` | `1` = панели видны всегда, без `?edit=1`. | выкл |
| `data-crypt` | `wait` = ключ шифрования придёт от страницы позже. | без шифрования |

Адрес страницы понимает `?edit=1` (показать панели) и `?store=local`
(писать в этот браузер, а не на сервер: удобно для репетиции показа).

## Как адресуются блоки

Есть `data-edit="ид"` - берётся он. Нет - идентификатор считается сам:

```
документ / секция / тег / хэш исходного текста
gt/s-02-what/p/7c43feda
```

Хэш берётся от **шаблонного** текста, а не от отредактированного. Отсюда два
следствия, оба намеренные.

Патч переживает переверстку: можно переписать CSS, поменять сетку, перенести
блок в другое место секции - адрес не меняется. Шаблон живёт в git, контент в
базе, эти две оси не мешают друг другу.

Патч отваливается, если переписан сам исходный текст этого абзаца в шаблоне.
Это правильное поведение: значит, шаблонная формулировка изменилась и старая
правка к ней уже не относится. Такие патчи не пропадают молча, они видны как
`orphans` в `BLOCKEDIT_INFO()`.

Критичным блокам лучше проставить `data-edit` руками, тогда адрес не зависит
от текста вообще.

## Что сохраняется

Не файл целиком, а карта патчей `{block_id: html}`. Версия это снимок такой
карты. Поэтому история версий весит килобайты, а не мегабайты, и откат меняет
только текст, не трогая вёрстку.

Вставка из буфера идёт только текстом. Сохраняемый HTML проходит белый список
тегов (`b, strong, i, em, u, br, span, a, ul, ol, li, p, small, sup, sub, code,
div`) и атрибутов (`class, href, target, rel, data-edit`), остальное
разворачивается. `javascript:` в ссылках вырезается.

## Шифрование

```js
window.LIVEEDIT_KEY(cryptoKey);   // отдать модулям ключ, когда он появился
```

Страница с парольным входом (см. `gentero-integra/build-gate.js`) выводит
AES-ключ из пароля и передаёт его сюда. До этого момента модули ничего не
читают и не пишут. Формат байтов общий: `iv[12] || ciphertext+tag`, base64.

Чего при этом не будет: поиска и сравнения на стороне сервера. Всё считается в
браузере после расшифровки. Потеря пароля означает потерю всех версий, ключ
нигде не депонируется.

## Только версии, без редактора

Когда состояние держит сам проект (форма, конструктор, настройки дашборда):

```html
<script>window.VERSIONS_HOST = {
  getState: function(){ return собратьСостояние(); },
  setState: function(s, o){ применить(s); }   // o.preview = true: только показать
};</script>
<script src=".../smm/liveedit/versions-init.js" data-doc="имя-проекта" defer></script>
```

## База

`schema.sql`, выполнить один раз в SQL editor проекта Supabase. Две таблицы,
`doc_blocks` и `doc_versions`, обе разделяются полем `doc_key`. anon-ключ
публичен по дизайну, поэтому защита содержимого лежит на шифровании, а не на
политиках RLS.

## Публичные хуки

| Вызов | Что делает |
|---|---|
| `BLOCKEDIT_REFRESH()` | Наложить патчи заново после смены DOM (переключение вкладки, динамический рендер) |
| `BLOCKEDIT_STATE()` | `{v, docKey, blocks}` |
| `BLOCKEDIT_APPLY(state)` | Применить и сохранить |
| `BLOCKEDIT_PREVIEW(state)` | Только показать, хранилище не трогать |
| `BLOCKEDIT_INFO()` | Сколько блоков, сколько патчей, какие осиротели |
| `VERSIONS_SNAP(label)` | Снять версию |
| `VERSIONS_TOUCH()` | «Была правка», для авто-снимков |
| `VERSIONS_FLUSH()` | Снять версию, если есть несохранённые правки |

## Файлы

- `liveedit-init.js` - загрузчик редактора и версий (одна строка встройки)
- `versions-init.js` - загрузчик только версий
- `blockedit.js` - редактор блоков
- `versions.js` - история версий и её панель
- `store.js` - Supabase и localStorage за одним интерфейсом
- `crypt.js` - AES-256-GCM поверх PBKDF2, совместим с `build-gate.js`
- `schema.sql` - таблицы

После правки ядра поднимите `CORE_VERSION` в обоих загрузчиках, иначе у
проектов останется старая версия из кэша.

## Тема

Модули читают токены хост-страницы через `var()` с тёмными фолбэками
(`--card`, `--ink`, `--line`, `--cta`). На светлом хосте переопределите
`--cta` на тёмный вариант, иначе золотой текст на светлом фоне провалит
контраст. То же ограничение, что у модуля комментариев.
