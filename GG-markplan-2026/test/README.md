# Стенды страницы плана

Два стенда на Playwright, оба ходят по собранной странице в headless-Chromium,
без установки зависимостей проекта: страница статическая.

```
node make-fixtures.mjs     # собрать фикстуры из public/gantt-v2.csv
node audit.mjs live        # живая таблица: 7 ширин x 2 темы
node audit.mjs snapshot    # таблица недоступна: тот же матричный прогон
node robust.mjs            # шесть сценариев испорченного источника
node gate-probes.mjs       # пробы против самого гейта оценок, браузер не нужен
```

Playwright нужен в `node_modules` рядом (`npm i playwright`), Chromium берётся
из `/opt/pw-browsers/chromium-1194`. Путь к браузеру задан в обоих файлах
константой `executablePath` и меняется под свою машину.

## Что проверяет audit.mjs

Ширины 320 / 360 / 390 / 768 / 1024 / 1440 / 1920, обе темы, оба источника
данных. По каждой комбинации: горизонтальный скролл документа, выход текста и
чипов за левую панель графика, единственность и текст `h1`, нумерация секций,
отсутствие удалённых секций, живые цели всех ссылок навигации, видимость
навигации на узких экранах, расшифровка меток источника, метка источника в
каждой строке задачи, отметка свежести, отсутствие второго бейджа свежести,
подпись сводки просрочек источником списка, один и тот же красный у рамки и
чипов просрочки, единая версия ассетов, отсутствие внутреннего жаргона и путей
к файлам в тексте, `aria-pressed`, кнопка «раскрыть все блоки», печатный режим.

### Гейт утверждений об оценках

Перед запуском браузера `audit.mjs` рекурсивно вычитывает все публикуемые файлы
в `public` (`html/js/css/csv/json/md/txt`), ищет любое `N из 10` или `N/10` и
требует, чтобы такое число было подтверждено отчётом аудита из
`knowledge/episodes`, у которого в `deliverable_ref` назван именно этот
артефакт. Строки журнала `traces` больше не авторизуют оценку сами по себе:
дописать строку в `.jsonl` дешевле, чем положить отчёт, проходящий схему.

**Чего этот гейт не делает, и это надо понимать.** Он не доказывает подлинность
оценки. Отчёты пишет тот же, кто правит страницу, поэтому приписать себе девять
баллов можно, положив рядом отчёт на девять баллов. Это проверка
согласованности, а не подлинности. Единственная настоящая защита это чужой
аудит, и подменять её словами «страница прошла автопроверку» нельзя.

Гейт живёт отдельным модулем `claims-gate.mjs`, и на него есть собственный
стенд `gate-probes.mjs`: 22 пробы без браузера, каждая повторяет приём, которым
гейт уже ломали. **Проба, которой нет в этом файле, считается непроверенной.**

Что гейт ловит, потому что каждое из этого пробовали сломать:

| Приём | Как закрыт |
|---|---|
| целое число «8 из 10» вместо дробного | целое считается оценкой рядом со словом про оценку, балл, вердикт, аудит или проверку |
| «9,9 из 10, вердикт принято» | отрицание после «10» отсекает только продолжение числа, не знак препинания |
| неразрывный пробел, `&nbsp;`, тонкий пробел | приводятся к обычному пробелу |
| разметка внутри числа, `<b>9,2</b>/10` | текст ищется в двух вариантах, с разметкой и без, находки объединяются |
| перенос строки между числом и мерой | файл читается целиком, а не построчно |
| исключение, растянутое на весь файл | исключение цепляется за контекст вокруг числа, а не за имя файла |
| файл в подпапке, `.json` | обход рекурсивный, расширения перечислены выше |
| разметка внутри меры, `из <i>10</i>` | то же: поиск в двух вариантах |
| «9,7 балла», «9,8 по десятибалльной» | мера это не только «из 10» и «/10» |
| пробел сущностью, `&#32;`, `&thinsp;` | приводятся к обычному пробелу |
| оценка, вписанная в «Обоснование» живой таблицы | отдельная проверка по отрисованному тексту страницы, в обоих режимах данных |
| оценка в свёрнутом блоке | после раскрытия всех блоков читается `textContent` всего документа: свёрнутый `details` в `innerText` не попадает, и проверка видела 2 блока из 16 |
| `public/**/razbor.html` в подпапке | освобождение ключуется относительным путём, а не именем файла |
| утверждение про план на самой странице разбора | освобождение снимается, если рядом с числом стоит «страниц», «план», «markplan» или «антикризис» |

### Форма без меры: почему её не ищут догадкой

«Оценка страницы по внутреннему аудиту: 9,9» без «из 10» общий поиск не видит.
Детектор на догадке (число рядом со словом про оценку) я собрал и выбросил:
слово «оценка» встречается в прозе не про баллы («оценка дыры расходится в 2,8
раза»), а в CSV колонка «Гейт» и автор «ФЕНИКС» стоят рядом с часами и днями в
каждой строке. Детектор краснел десятками ложных срабатываний, а проверка,
которая всегда красная, это проверка, которую перестают запускать.

Поэтому форма без меры не угадывается, а **запрещена там, где оценки
публикуются**: в полях `meta.gate` и `meta.audit` обоих файлов данных любое
число в пределах шкалы обязано нести меру, иначе прогон краснеет. Это правило
без эвристики: область узкая, и в ней у числа нет другого смысла.

Остаточные пробелы названы и заведены задачей Z24 в самом плане, с
ответственным и датой:

- проверка сверяет согласованность, а не подлинность (см. выше);
- оценка, написанная в обычном тексте вне полей вердикта и без слова про оценку
  рядом, не поймается.

Осознанные исключения лежат в `CLAIM_EXCEPTIONS` с текстом причины и печатаются
при каждом прогоне строкой `ПРОПУЩЕНО`. `razbor.html` выведен из общего правила
целиком как опубликованный отчёт разбора: оценки в нём относятся к разговору, а
не к странице. Взамен с неё требуется, чтобы у оценки на первом экране стояли
автор и статус записи, иначе прогон краснеет.

Эта проверка нашла три вещи, которых не увидел ни один аудит по `путь:строка`:
оценку в середине абзаца `meta.note` архивной страницы, оценку в плитке её
первого экрана и собственную дыру с запятой после «из 10».

Две проверки стоят отдельного упоминания, потому что появились после того, как
зелёный стенд подтвердил дефект как норму.

**Оценки в подвале проверяются по всему тексту подвала, а не по узлу,
который правили.** Иначе исправленный `#foot-gate` даёт зелёный прогон, пока в
соседнем абзаце того же подвала живёт устаревшая цифра.

**На печати проверяется не только то, что служебное скрыто, но и то, что
осталось:** отметка происхождения данных, расшифровка меток и сами метки. Первая
версия проверки требовала лишь скрытия шапки, то есть требовала, чтобы дата
данных ушла с листа вместе с ней.

## Что проверяет robust.mjs

| Фикстура | Ожидание |
|---|---|
| `gviz-garbage.csv` | даты `31.02.2026`, `0000-00-00`, `8/45/2026`, `2026-13-01`, `32.10.2026`, текст и длительности `0 / -3 / абв` дают «срок не назначен», ни одна задача не теряется, дат вне периода плана на экране нет |
| `gviz-nopr.csv` | нет колонки «Приоритет» - честный откат на список в странице |
| `gviz-empty.csv` | таблица из одной шапки - откат |
| `gviz-alldone.csv` | все статусы «готово» - сводка просрочек исчезает целиком |
| `gviz-claim.csv` | оценка «9,9 из 10» вписана в «Обоснование» задачи - положительный контроль: она обязана быть видна в отрисованном тексте и обязана не иметь отчёта, иначе гейт по тексту проверять нечего |
| запрос оборван | таблица недоступна - откат с подписью «данные не обновились» |

Зелёный прогон обоих стендов не является доказательством качества страницы и не
заменяет адверсариальный гейт (CLAUDE.md §4): проверка написана тем же, кто
писал страницу, и повторяет его представление о правильном поведении.
