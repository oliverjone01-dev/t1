## 3. Политика склейки (спецификация исполнителю)

Вход: A = D.av из public/index.html головы op-gm-automation-v1 (расшифровка как build.cjs:21-33); B = два сырых окна (sha256 из F8). Выход: av.json и recon.json для build.cjs. Сырые файлы и av.json в репозиторий не попадают. Каждое «стоп» = ненулевой код выхода и строка причины.

- **С1. Кабинет по пересечению channelId**, а не по имени файла или аккаунта (F7): чаты окна, созданные раньше `A.recon[tag].exported` минус сутки, находятся в A под одним тегом не меньше чем на 90% и под другим 0. Иначе стоп.
- **С2. Перекрытие окон:** periodFrom окна не позже `A.recon[tag].exported` минус 24 ч. Иначе стоп (дыра в данных). Для 29.09 условие выполнено: 21.09 00:00 МСК против выгрузки 22.09.
- **С3. Полнота окна вместо CSV:** каждый чат A с последним сообщением не раньше periodFrom обязан быть в окне. Пропуск = стоп.
- **С4. Чат только в A:** запись и сообщения байт в байт как в A.
- **С5. Чат только в B:** запись строится той же функцией, что в build_av.py. Правила детекторов не меняются; build_av.py разложить на функции, регресс: старый путь на тех же сырых с фиктивным CSV даёт те же chats и msgs.
- **С6. Чат в A и в B:** объединение сообщений по ключу (секунда, тип, сторона, порядковый номер среди сообщений с той же секундой, типом и стороной); сторона: клиент / мы (m и a вместе) / система. При совпадении ключа берётся строка B (удаления, статусы звонков свежее). Запись пересчитывается целиком по объединению, имя и объявление из B. Согласие выгрузок: каждое сообщение A не раньше первого сообщения B есть в B (overlap_missing = 0, иначе стоп). Чат, упёршийся в лимит 100, получает ранние сообщения из A; число восстановленных печатается.
- **С7. Объявления:** список A остаётся префиксом, новые названия дописываются в конец, индексы A не сдвигаются. В запись добавить id объявления (`context.value.id`). Число чатов со сменой названия печатается.
- **С8. «Писал в оба кабинета»** пересчитать по всему объединению тем же правилом (build_av.py:144-170); число изменившихся флагов печатается.
- **С9. recon:** `exported` из B (двигает EXPORT_TS; без этого чаты после 22.09 невидимы, F2); `json_chats`, `json_msgs`, `before_apr` по объединению; поля CSV остаются только как слой 22.09. Новые поля: `layers` (слой 22.09 с CSV, окно 21.09-29.09 без CSV) и `merge` (kept_old, replaced, added, truncated_100, restored_from_old, overlap_missing, t_changed, both_changed, ad_title_changed, mapping_overlap, window_missing).
- **С10.** Константу `exported` в build_av.py:172 брать из данных или убрать.
- **С11. Следующая выгрузка 05.10:** то же правило; база A = принятая сборка после Д-пакета; periodFrom не позже 28.09 00:00 МСК.

Что пометить на экране (Д5, код opgm.js, входит в Д-пакет обязательно):
- «Откуда цифры» (opgm.js:439-443): таблица слоёв, счётчики склейки, строка «CSV к окну 21-29.09 не выгружался; полноту окна проверили по прошлой выгрузке». Фраза «совпадает» остаётся только у слоя 22.09. Без этой правки экран напишет «совпадает» при разных числах.
- Врезка свежести `fresh()` (opgm.js:125-129), одна фраза: данные склеены из полной выгрузки по 22.09 и окна с 21.09; диалоги с новыми сообщениями пересчитаны, поэтому прошлые недели могут отличаться от прежних цифр; «Детализация» считает 8 недель по 20.09 и обновляется отдельно.
- Помесячные графики Скорости и Рассылки: «сентябрь до 29» из EXPORT_TS (Д1).

Шаг 2 Д-пакета, необязательный для выпуска данных: патч detalizaciya.js (К1 цвет NEW-B и Д6 «черновая норма»), сборка третьим аргументом, снимок чисел «Детализации» 0 расхождений. Если шаг 2 не проходит, данные выходят без него.
