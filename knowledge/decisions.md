- 2026-09-30 Roistat, поправки по итогам первого живого среза (runs 36696610547, 36697301501, 36697832771):
  - Период в `analytics/data` полуоткрытый `[from, to)`, границы в UTC. `to` всегда первый день следующего периода, иначе запрос молча теряет последние сутки. Часовой пояс подписывается на самой витрине: московские 00:00-03:00 у Ройстата уходят в предыдущие сутки.
  - Отменено решение «выручку по каналам берём метриками `custom_16..26`»: они пустые во всех строках и во всех периодах, воронка Битрикса в Ройстате пользовательскими метриками не наполнена. Деньги берём из штатных метрик.
  - Слова «прибыль» в витрине по данным Ройстата нет: себестоимость в Ройстат не заведена, `revenue` и `profit` совпадают до рубля, маржинальность равна нулю. Вернуться к вопросу можно только после загрузки себестоимости в сам Ройстат.
  - Продажей считается класс статуса `paid` по карте Ройстата (в воронке 49 это пять стадий), а не флаг `won` Битрикса. Определение берётся из API той системы, с которой идёт сверка.
  - Воронка Битрикса видна разрезом `order_field_339` «Идентификатор направления сделки». Ройстат считает все воронки холдинга, снимок Битрикса - только категорию 49; сводить их итоги напрямую нельзя.
- 2026-09-30 Roistat, поправки по итогам построчной раскладки сверки (runs 36737751819, 36738321227):
  - Деньги по сделке берём со строки ЛИДА, когда строки сделки у Ройстата нет: 62 сделки из 113 за август лежат только строкой лида со ссылкой `order_id_alias`. Искать деньги на строке сделки - значит записать их в нули и объявить пропажу, которой нет.
  - `payment_revenue` по месяцам берём из `analytics/data` как есть. Поля даты, по которому Ройстат раскладывает её по месяцам, в `order/list` нет; построчная сверка доказывает полноту и суммы, но не месячную нарезку.
  - Полнота постраничного обхода меряется числом СТРОК одного прохода против `total`, а не числом различных id: `total` считает строки. Расхождение строк и различных id - это дубли, отдельный вывод; дубли от съехавшего окна различает повтор обхода.
  - Поле денег в выгрузке не выбирается «по наибольшей сумме»: так побеждает поле с самыми длинными числами, а не с рублями. Эталон не воспроизведён - берём штатное поле и помечаем цифры гипотезой.
