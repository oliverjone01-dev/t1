# GG Sales Academy: решение об архитектуре

**Дата:** 2026-08-08
**Ветка:** `claude/optimizacija-menedzherov-gg-ytpe1w`, PR #197
**Постановка Ивана:** «Аналитическая учебная платформа, начинаем строить её с разборов и личных дашбордов на основании анализа качества их работы с клиентами. Вход по паролю как на сайте сотрудничества с АВ. Структуру проектирует СПАРТАК с агентами, всё модерирует ФЕНИКС.»

---

## Главное решение

Платформа делится на **три контура сборки по классу данных**, а не на три раздела одного сайта.

| Контур | Персональные данные | Где живёт | Коммитится |
|---|---|---|---|
| 1A. Библиотека | Нет | GitHub Pages, `/academy/` | Да |
| 2. Кабинет менеджера | Да | Локальная сборка, файл на руки | Никогда |
| 3. Штаб (РОП, Иван) | Да, по всем сразу | Локальная сборка, 2 получателя | Никогда |

**Почему.** При статике без бэкенда роль на клиенте не проверяется: проверку обходят через просмотр исходного кода. Роль **запекается** в файл. Менеджер не видит данные коллеги не потому, что ему запрещено, а потому что их физически нет в его файле.

**Что это разблокировало.** Большая часть объёма учебной платформы (методика, нормативы, скрипты, фразебук, возражения, дожим, глоссарий) не содержит персональных данных вообще. Вето ФЕНИКСА 5.8/10 стоит на кабинетах и штабе. Библиотека им не блокируется и может развиваться, пока Иван принимает решения по истории git и визе юриста. Это нашёл СПАРТАК при проектировании.

## Гейт: почему в контурах разная механика

Иван попросил повторить вход как на `gg-seo-geo-monster`. Там SHA-256 пароля в JS плюс `sessionStorage`, и собственная подпись этого гейта честно говорит: «защита от случайных глаз, не криптография». Контент лежит в файле открытым текстом и читается через просмотр исходного кода без пароля.

**Решение: одинаковый UX, разная механика по контурам.**

| Контур | Механизм | Что защищено |
|---|---|---|
| 1A | SHA-256 плюс `sessionStorage`, дословно как у АВ | Ничего, и этого достаточно: прятать нечего |
| 2, 3 | Payload зашифрован целиком: PBKDF2-SHA256 600 000 итераций (OWASP 2023), AES-256-GCM, соль своя на файл | Содержимое. Без пароля в файле нет читаемого текста |

Шифрование собирается Node WebCrypto, расшифровывается тем же WebCrypto в браузере, поэтому расхождение алгоритмов между сборкой и клиентом невозможно. Вывод ключа 279 мс, работает по `file://` без сети.

**Проверено в браузере:** неверный пароль отвергается (AES-GCM аутентифицирован и на неверном ключе бросает исключение, а не выдаёт мусор), пароль коллеги не открывает чужой кабинет, plaintext в собранном файле отсутствует.

## Дефект, который поймала автопроверка сборки

Первый прогон сборщика остановился с ошибкой «утечка». Причина оказалась не технической: имя человека выводилось на **экран блокировки**. Любой, у кого есть ссылка, узнавал, чей это кабинет, не зная пароля.

Исправлено: на гейте нейтральное «Кабинет менеджера», имя появляется после входа. Контроль утечки в сборщике оставлен и останавливает сборку, а не предупреждает.

---

## Чего схема не даёт

Зафиксировано явно, чтобы через три месяца это не выглядело сюрпризом:

1. Нет отзыва доступа. Выданный файл работает бессрочно, ротация пароля влияет только на следующую сборку.
2. Нет журнала открытий. Это то самое противоречие, которое ФЕНИКС нашёл в ТЗ: L1 Киркпатрика объявлен условием валидности всех выводов и недостижим в архитектуре локальных офлайн-файлов.
3. Пароль не равен человеку, аутентификации личности нет.
4. Пересылка не предотвращается, скриншот не ловится в принципе.
5. При утечке файла пароль подбирается офлайн. Держится на длине пароля и стоимости PBKDF2.

**Известный потолок.** Если понадобятся отзыв доступа и журнал, это HTTP Basic Auth на nginx с логином на человека: не бэкенд и не БД, шесть строк конфига. Нужен хостинг под контролем холдинга.

## Что решено не делать в первую очередь

Из проекта СПАРТАКА, каждое с обоснованием от наших данных:

1. **Рейтинг, лидерборд, баллы, бейджи.** При выборке 14 сделок доверительный интервал индекса от ±1.3 до ±2.6, три человека статистически неразличимы. Ни один из 23 детекторов не валидирован.
2. **Аттестация и влияние результатов на премию.** Нормативы помечены гипотезой до конца августа. Оценка людей по неоткалиброванному нормативу с денежными последствиями меняет правовую конструкцию платформы целиком.
3. **Тренажёр с LLM-оценкой.** Статика плюс LLM означает ключ API в файле на руках у десяти человек.
4. **Автоматическая рассылка кабинетов.** Создаёт вторую неконтролируемую копию персональных данных и снимает единственный оставшийся контроль, ручное решение о выдаче каждому.
5. **Любая цифра эффекта обучения в рублях.** Блокируется Protocol 9 без win/loss связки, которой нет.
6. **База звонков.** 193 записи существуют только метаданными. Раздел, наполненный на ноль, обесценивает соседние наполненные.
