1. **Царь-цель**: Метрика 487033158 «CRM | Все лиды» (плюс 487033859 «Качественные»). Механика: лид попадает в CRM → автовыгрузка в Google Sheets по API → проброс в Метрику по client_id как ОФЛАЙН-конверсия.

2. **MAX-канал - РЕШЕНО (2026-07-16).** Дмитрий реализовал проброс client_id из MAX в CRM и далее в Метрику-цель. Обращения из MAX теперь доходят до царь-цели 487033158. Пайплайн client_id → CRM → офлайн-конверсия рабочий (это опорная точка для фикса ниже).

3. **СЛЕПАЯ ЗОНА (открыта): онлайн-чат Битрикс24, веб-виджет Открытой линии.** Подтверждено 2026-07-16: чат-виджет НЕ передаёт client_id в CRM → лид из чата не уходит в офлайн-цель → не доходит до 487033158. ОТЛИЧИЕ от MAX: этот чат живёт НА сайте (браузерная сессия есть, ym client_id доступен на странице) - значит чинится проще, чем внешний мессенджер. Следствия:
   - CPL по 487033158 ЗАВЫШЕНЫ на долю чат-лидов.
   - Сравнение кампаний/каналов смещается, если доля чат-обращений разная (важно для вердикта эксперимента Поиск vs ТГ 24.07).
   - Директ недоучитывает чат-конверсии по кампаниям/ключам.

4. **Путь фикса чата (2 уровня; пайплайн MAX уже готов, дотянуть источник client_id):**
   - **Быстро (для Директа):** JS-цель Метрики на открытие чата / первое сообщение - `ym(104369223,'reachGoal','chat_lead')`. Чат на сайте → client_id родной, привязка к визиту автоматом. Директ сразу видит чат-интент. Считает начатые диалоги, не CRM-подтверждённые - ОТДЕЛЬНАЯ цель, не мешать с 487033158.
   - **Правильно (в царь-цель):** снять ym client_id на странице при старте диалога (`ym(104369223,'getClientID',cb)`) и записать его в карточку лида Открытой линии (кастомное поле / REST-обновление лида / cookie + робот Битрикс). Дальше СУЩЕСТВУЮЩАЯ офлайн-выгрузка (та же, что уже работает для MAX) сматчит чат-лид по client_id. То есть достроить только ЗАХВАТ client_id для канала веб-чата - пайплайн уже есть.
