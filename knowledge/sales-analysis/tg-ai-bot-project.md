# Проект: ответы бота в Telegram на вопросы отдела (@ropcache_bot)

Статус: проект и смета на согласование Ивану. Кода пока нет.
Дата: 2026-09-07.

## 1. Что хочет Иван

Любой участник рабочего чата может обратиться к боту прямо в чате и получить ответ - например «разбор по Лакомовой», «что дожать по крупным», «у кого просрочка». Сейчас бот только шлёт дайджест по расписанию и на вопросы не отвечает.

## 2. Ограничение (правило Ивана) и как мы его соблюдаем

Правило: «API только в дашборде по моему клику». Автоответ на вопрос из чата с вызовом ИИ - это расход API без клика в дашборде. Если открыть его всем без рамок, любой участник тратит кредиты Ивана бесконтрольно.

Решение - два слоя ответа:

- Слой 1, БЕЗ API (бесплатно, всем): карточка менеджера и сводки считаются детерминированно из снимка Bitrix (те же данные, что в дашборде и дайджесте). Это уже готовая логика - портфель, КП без дожима, просрочка, сделки 30+ дней, конкретные сделки. Расход ноль, правило не нарушается.
- Слой 2, С API (по рамкам): «умные» текстовые ответы и произвольные вопросы. Здесь расход кредитов, поэтому включается только с контролем (белый список, лимит, лог).

Так «все в чате» получают пользу сразу и бесплатно, а API остаётся под контролем.

## 3. Что бот отвечает без API (Слой 1)

Команды-обращения в чате (бот в группе видит только обращения к себе - упоминание, команда или ответ на его сообщение):

- `Лакомова` или `/kart Лакомова` - карточка менеджера: объём и число сделок, медиана чека, отклик, КП без дожима (сумма), просрочка, 30+ дней (работают или застряли), топ-3 сделки на дожим с номерами.
- `/otdel` - сводка по отделу: пайплайн, КП без дожима, просрочка, 30+, рейтинг менеджеров.
- `/dozhim` - список сделок с КП без дожима по всему отделу (что горит по деньгам).
- `/prosrochka` - просроченные дела по менеджерам.

Данные берутся из снимков `rop.json` и `dialog.json` (обновляются ночным и внутридневными кронами). Ответ - за секунды, без затрат.

## 4. Что бот делает через API (Слой 2)

Три разных места вызова API, их нельзя путать - у каждого свой контроль:

### 4.1. Недельный «Костя-ИИ» разбор по расписанию (главное)

Раз в неделю (пятница 12:00) бот сам формирует полный разбор отдела для РОПа: собирает данные, анализирует работу отдела, делает выводы, даёт рекомендации, называет сильные и слабые стороны по каждому менеджеру. По методике скилла `kostya-ai`.

Накопительно («пазл»), и это ключ к дешевизне:
- вход в модель = вывод прошлой недели + ДЕЛЬТА этой недели (что изменилось по сегментам), а не вся история заново;
- модель смотрит, стало лучше или хуже по слабой стороне каждого менеджера, обновляет вердикт и пишет «динамика вверх / вниз / стоит»;
- результат сохраняется и становится входом для следующей недели.

Контроль здесь - не белый список, а расписание: один запуск в неделю. Дневной аудит по желанию - тот же механизм, чаще.

### 4.2. Дашборд, по кнопке Ивана

Разбор по запросу: Иван жмёт «отправить на анализ» и получает свежий разбор. Как договаривались изначально.

### 4.3. Ответ на вопрос из чата `/ai` - ОТЛОЖЕНО (пока не внедряем)

Решение Ивана: сейчас не делаем. Когда вернёмся - тут обязателен белый список (кто может звать), дневной лимит и суточный потолок в рублях, лог каждого запроса. В текущий объём не входит.

Модель по умолчанию Sonnet 5; для глубоких разборов - опционально выше. Персональные оценки менеджеров перед первой рассылкой людям проходят гейт ФЕНИКСА (Step 12.5) и показ Ивану - Protocol 6 (HITL).

## 5. Смета API

Цены `[ДАННЫЕ]` (официальный справочник, 2026-06-24):
- Sonnet 5: вход $2 / выход $10 за 1 млн токенов.
- Haiku 4.5: вход $1 / выход $5 за 1 млн токенов.
- Batch API: минус 50% (для отложенных задач, не для живого чата).
- Prompt-кэш: повторяемый контекст (методичка, системный промпт) читается со скидкой ~90%.

Размер запроса `[ГИПОТЕЗА]` (наши сценарии):
- Недельный разбор отдела накопительно (прошлый вывод + дельта недели): ~20-25 тыс. вход, ~4 тыс. выход.
- Лёгкий (карточка + вопрос в контексте): ~6 тыс. токенов вход, ~1 тыс. выход.
- Тяжёлый (расширенный контекст по менеджеру): ~40 тыс. вход, ~1.5 тыс. выход.

Стоимость одного запроса `[ГИПОТЕЗА]`, курс ~90 ₽/$:
- Недельный разбор на Sonnet 5: ~$0.09 (~8 ₽).
- Лёгкий на Sonnet 5: ~$0.022 (~2 ₽). На Haiku: ~$0.011 (~1 ₽).
- Тяжёлый на Sonnet 5: ~$0.095 (~8.5 ₽).

Месячные сценарии `[ГИПОТЕЗА]`:
- ГЛАВНЫЙ. Недельный «Костя-ИИ» разбор отдела (4-5 запусков/мес): ~$0.4/мес (~35 ₽). Контроль - расписание.
- A. Плюс `/ai` только Иван и РОП, ~30 запросов/мес: ~$3/мес (~270 ₽).
- B. Плюс `/ai` весь чат, ~10 лёгких/день × 22 дня = 220/мес: ~$5/мес (~430 ₽).
- C. `/ai` без рамок, ~50 тяжёлых/день: ~$140/мес (~12 600 ₽). Риск «любой жжёт кредиты» - не рекомендуется, поэтому лимит на `/ai` обязателен.

Вывод: сам недельный разбор (то, что просит Иван для РОПа) стоит десятки рублей в месяц. Дорого только открытый `/ai` без лимита - но это отдельный слой 4.3.

Отдельно - ежедневный ИИ-аудит по всем менеджерам (план Ивана «ежедневный аудит по API»):
- 7 менеджеров × 1 запрос/день (карточка в контексте, ~6 тыс. вход / ~1.5 тыс. выход) × 22 рабочих дня = 154 запроса/мес.
- Sonnet 5: ~$4/мес (~360 ₽). С Batch API и кэшем - заметно ниже.

Вывод по смете: при разумных рамках (сценарии A и B плюс ежедневный аудит) расход - сотни рублей в месяц, а не десятки тысяч. Дорого становится только без лимитов (сценарий C).

## 6. Где это крутить

Важно разделить по способу запуска:

- Недельный разбор (4.1) - это РАСПИСАНИЕ, а не живой чат. Слушатель ему не нужен. Он запускается на том же GitHub Actions, что уже шлёт дайджест: по крону в пятницу бот считает срез (даром), берёт прошлый вывод + дельту, делает один вызов Anthropic API и шлёт результат в чат. Ничего нового поднимать не надо. Ключ Anthropic лежит секретом в GitHub (управляет Иван).
- Дашборд по кнопке (4.2) - уже умеет вызывать API по клику Ивана.
- Живой `/ai` из чата (4.3) - ОТЛОЖЕН. Только он потребовал бы всегда-включённого слушателя (n8n или «Константин»). Пока не делаем - площадку под него выбирать не нужно.

Итого: для того, что Иван просит сейчас (недельный разбор РОПу + кнопка в дашборде), отдельная площадка НЕ нужна. Хватает GitHub Actions плюс ключ Anthropic секретом.

## 7. Этапы

1. Согласовать проект и смету (этот документ).
2. Бесплатный слой: детерминированный недельный срез по сегментам + сохранение среза в git (накопление «пазла») + сравнение с прошлой неделей. Проверка в тест-чате.
3. Платный слой: добавить в пятничный крон вызов Anthropic API (ключ секретом) - «Костя-ИИ» разбор накопительно (прошлый вывод + дельта) → РОПу. Первый прогон в тест-чат, гейт ФЕНИКСА (Step 12.5) и показ Ивану до рассылки РОПу (Protocol 6, персональные оценки - HITL).
4. Опционально: дневной аудит тем же механизмом, чаще.
5. Позже и отдельно: живой `/ai` из чата на n8n/«Константине» с белым списком и лимитом.

## 8. Что нужно от Ивана для старта

- Положить ключ Anthropic секретом в GitHub (`ANTHROPIC_API_KEY`) - это включает платный слой для пятничного разбора и остаётся под контролем расписания.
- Подтвердить: пятница 12:00, первый прогон в тест-чат (не сразу РОПу).
- Бесплатный слой (срез + динамика) можно включать сразу, ключ для него не нужен.

## 9. Риски

- Ключ Anthropic в секрете GitHub: расход ограничен расписанием (один пятничный прогон), не зависит от активности чата. Открытый `/ai` (сценарий C) в объём не входит, пока отложен.
- Данные чувствительны (суммы сделок, имена, клиенты). Разбор идёт в рабочий чат, где все свои; наружу не выносить. Персональные оценки менеджеров - только после гейта ФЕНИКСА и решения Ивана.
- Задержка данных: разбор по последнему снимку; в тексте показывать время снимка, чтобы не спутать со «сейчас».
- Качество ИИ-вывода: первый прогон в тест-чат под гейтом ФЕНИКСА, РОПу - только после апрува методики.
