### Проблемы

**BLOCKER**

**B1. Метрика успеха не измеряется и сама себя засчитывает.**
- После unshallow `rework_rate.py --since 2026-09-01` даёт 87 из 715, то есть 12%. Это уже ниже цели 15%, до всякого внедрения.
- База в retro.md (17-100%) снята другим методом: «по заголовкам, реально выше», «около 74%». Воспроизвести её нельзя, чаты не привязаны к session id.
- Скрипт не отличает правки заказчика от своих фиксов и от return ФЕНИКСА. В списке переделок есть «правки по аудиту ФЕНИКСА», «Revert feat(deploy)», «fix(ci)».
- Метрика зависит от слов в заголовке коммита, а заголовок пишет сам агент (эффект Гудхарта).

Правка:
- (a) Записать базу как [ДАННЫЕ]: sha или session id по 7 чатам, формула, вывод `--session` по каждому.
- (b) Ввести трейлер `Rework: customer|self|feniks` и считать цель только по customer.
- (c) До выполнения (a) и (b) цель <15% помечать [ГИПОТЕЗА].
- (d) При несуществующей ветке скрипт падает с traceback, нужна нормальная ошибка.

**MAJOR**

**M1. build_regex срабатывает на чтение файлов на main.** Команды `cat`, `grep`, `git log`, `git diff` с build-katya.ts, а также `node --check build.js`, дают permissionDecision ask. Воспроизведено. Правка: матчить только запуск в начале сегмента (`(^|[;&|]\s*)(npx\s+)?(tsx|node|npm run|pnpm|yarn|bash)\s+...build`), исключить cat, grep, git, rg, sed, head. Добавить 4 негативных теста.

**M2. Гейт К11 не привязан к артефакту (см. A1), и есть обратная сторона.** Если ФЕНИКС проверяет незакоммиченную работу, как сейчас, то любой коммит после go всегда приводит к ask. Так вырабатывается привычка ставить DG_OVERRIDE. Правка: ФЕНИКС пишет в отчёт `AUDITED: <branch>@<tree-hash>`, subagent-trace кладёт это в трейс, хук сравнивает с `HEAD^{tree}`, не считая traces/ и knowledge/episodes. Возможность подделки записать как остаточный риск.

**M3. Merge-гейт срабатывает на любой `gh pr merge`, не только на работу с цифрами.** Он спрашивает и на контент, и на трейсы, и на хендоффы. Шаг 8.4 сам создаёт второй PR (реестр) на каждую задачу, а значит и второй ask. Правка: спрашивать, только если diff против origin/main задевает analytics-mvp/, tools/, knowledge/semantic/metrics, *.ndjson. PR, которые меняют только knowledge/errors, sessions/handoff или traces, пропускать молча.

**M4. SKILL.md противоречит хуку.** Шаг 7 говорит «слияние без go только по записанному решению Ивана», а хук принимает любой DG_OVERRIDE от агента. Правка: либо требовать ссылку на запись вида `DG_OVERRIDE="decisions.md#якорь"` и проверять, что строка существует, либо честно переписать шаг 7.

**M5. Stop-хук даёт ложные срабатывания, и каждое стоит лишнего хода.**
- По документации additionalContext у Stop продолжает разговор («The conversation continues»).
- «Проверено: тесты 15/15, api отвечает» вызывает срабатывание (воспроизведено), и оно не ограничено через once().
- numbers_prompt_regex ловит лишнее: «директорию», «директора», «маркетинг», «чеклист», «unittest», «50%», «рубрики». На «создай директорию для логов» в контекст приходит E054 про мутации в Директе.

Правка: убрать «проверено» и «совпадает» из claim_regex или требовать рядом денежный контекст; добавить `once(sid, claim-hash)`; поставить границы слов (`\bдирект\b`, `маркет(?!инг)`); убрать `%`, `чек`, `unit`, голый `api`.

**M6. Хуки уходят в плагин, а скилл нет.**
- hooks.json плагина gengroup-roster теперь содержит хуки data-guard, но скилла data-guard нет в plugin.json/skills. SKILL и реестр ищутся от CLAUDE_PROJECT_DIR.
- В чужом репо с этим плагином хук будет спрашивать go ФЕНИКСА на push в main и срабатывать на сборку на main (у TURBIUM под регулярку попадает `node site/build-locked.mjs`). При этом он ссылается на скилл, которого там нет.
- Если в t1 установлен ещё и плагин, хуки выполняются дважды.

Правка: либо убрать data-guard из hooks.json, либо добавить скилл в плагин, резолвить путь к скиллу от `__file__` и выходить молча, если в ROOT нет `.claude/data-guard.json`.

**M7. skillOverrides "name-only" прячет разводку для `audit`.** Вызов дизайн-скиллов не ломается: по документации при name-only модель видит имя, скилл остаётся в / меню. Но из описания `audit` пропадает фраза «дизайн-аудит интерфейса, НЕ заменяет гейт ФЕНИКСА». В репо, где «аудит» означает ФЕНИКСА, это повышает риск ложного вызова. Тот же риск у скиллов с общими именами: extract, optimize, harden, normalize, clarify, critique. Запись `frontend-design-reference` мёртвая: SKILL.md там нет. Сама правка к data-guard не относится и в коммите не упомянута. Правка: для audit и скиллов с общими именами поставить "user-invocable-only" или "on"; удалить frontend-design-reference; вынести в отдельный коммит с расчётом экономии токенов.

**M8. merge_window не закрывает главный инцидент К7.** `merge_window(old_30дн, {}, '2026-06-01', '2026-07-01')` возвращает 0 дней без ошибки (воспроизведено), то есть пустой ответ API стирает всё окно. Проверка untouched тавтологична. Правка: пустой или сильно усохший new должен давать InvariantError (параметр allow_shrink=False), плюс тест в py и ts.

**M9. Противоречие с analytics-dod.md §15.1.** DoD требует сверку «Σ по SKU + сборы = payout» по `data/pnl_daily.ndjson`. Но этот файл строится из Ozon finance API (pnl-daily.ts, OzonSeller), то есть обе стороны из одного семейства. По шагу 5 это К5, а добавленная в DoD строка противоречие не снимает. Второе: invariants.md сверяет Ozon accrual (у которого по api-gotchas база = дата заказа) с realization v2 «по дате начисления». Правка: в DoD назвать P&L-сверку внутренним инвариантом, а внешней сделать реализацию, акт или выписку; уточнить базу дат.

**M10. У 46 из 108 sha в evidence реестра нет коммитов даже в полной истории.** Например 11c6746a (E001) и 2a71f653 (E003), скорее всего это удалённые squash-ветки. Правка: в каждой записи хотя бы одна ссылка, которая резолвится в main (номер PR или эпизод), либо поле `evidence_scope: deleted-branch`.

**M11. api-gotchas.md ссылается на временные файлы и не ставит теги.** Строка 66 ведёт в эфемерный scratchpad `/tmp/claude-0/.../scratchpad/`, у следующей сессии его не будет. Утверждения, взятые из стороннего MCP (строки 32, 36, 37, 42, 60, 61, включая «пустое тело `{}` создаёт реальную отгрузку»), по правилу самого файла должны нести [ГИПОТЕЗА] или «вторичный источник». Правка: убрать путь, дать URL плюс коммит или положить выдержки в knowledge/semantic/probes/; проставить теги.
