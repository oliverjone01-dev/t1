# liveedit - правка блоков на странице и история версий

Два модуля, которые встраиваются одной строкой в любой внутренний проект.

- **blockedit** - клик по любому тексту, правка на месте, сохранение на сервер.
- **versions** - история версий с откатом, как в Google Docs, со своей панелью.

Хранилище общее: Supabase (тот же проект, что у модуля комментариев) или
localStorage. Содержимое можно шифровать в браузере.

## Встройка

```html
<script src="https://oliverjone01-dev.github.io/t1/smm/liveedit/liveedit-init.js"
        data-doc="имя-проекта" defer></script>
```

Панели по умолчанию скрыты. Чтобы их увидеть, откройте страницу с `?edit=1`.
Обычный зритель документа не видит ни кнопок, ни подсказок: у него патчи просто
применяются к тексту.

**Перед показом на большом экране открывайте страницу с `?show=1`.** У зрителя
кнопок нет, но остаётся диагностика: узкая красная полоса внизу на случай, когда
на экране НЕ тот текст. В переговорной она бесполезна и вредна: человек в зале
по ней ничего сделать не может, а вопрос задаст вслух. В режиме показа модуль
молчит совсем и пишет только в консоль.

## Параметры (data-атрибуты)

| Атрибут | Зачем | По умолчанию |
|---|---|---|
| `data-doc` | Ключ документа. Разные значения = разные истории, одна база на все проекты. | путь страницы |
| `data-root` | Корень правимой области. | `#doc`, иначе `body` |
| `data-selector` | Что считать блоком. | заголовки, абзацы, пункты списков, ячейки таблиц, всё с `data-edit` |
| `data-code` | Код для ЛОКАЛЬНОГО режима. На сервере не используется. | пусто |
| `data-storage` | `local` = только этот браузер. | общая база |
| `data-auto` | Авто-снимок версии каждые N правок, `0` выключает. | `8` |
| `data-always` | `1` = панели видны всегда, без `?edit=1`. | выкл |
| `data-crypt` | `wait` = ключ шифрования придёт от страницы позже. | без шифрования |
| `data-mode` | `show` = режим показа: ни панелей, ни диагностики, всё в консоль. | обычный |

Адрес страницы понимает `?edit=1` (показать панели), `?show=1` (режим показа) и
`?store=local` (писать в этот браузер, а не на сервер). Оба загрузчика читают их
одинаково.

## Кто имеет право писать

**На сервере право писать проверяет Supabase, а не браузер.** Политики RLS
разрешают `insert`, `update` и `delete` только роли `authenticated`, поэтому
редактор входит по почте и паролю (`auth.js`, Supabase Auth). Токен лежит в
`sessionStorage`: закрыл вкладку - вышел, чтобы доступ на запись не пережил
показ на чужом экране. Токен проверяется раз в десять минут и продлевается за пятнадцать минут до
конца: порог обязан быть больше интервала проверки, иначе между двумя тиками
остаётся окно с уже мёртвым токеном, и правка в нём улетает в 401.

Кода доступа в разметке нет намеренно. Он был в первой редакции и защищал
ровно ничего: страница публичная, атрибут виден в исходнике любому, кому дали
ссылку. `data-code` остался только для локального режима, где писать некуда,
кроме собственного браузера.

Чтение анонимное: зритель должен видеть правки, а текст в базе зашифрован.

## Как адресуются блоки

Есть `data-edit="ид"` - берётся он. Нет - идентификатор считается сам:

```
документ / секция / тег / хэш исходного текста
gt/s-02-what/p/7c43feda
```

**`data-doc` в этой формуле берётся с корневого элемента, а не с тега script.**
Это два разных значения, и путать их дорого:

| Где стоит | Что задаёт | Пример на ИНТЕГРЕ |
|---|---|---|
| тег `<script>` | ключ документа в базе, отдельная история версий | `integra-deal` |
| корневой элемент (`#doc`) | префикс адресов блоков внутри страницы | `gt` или `gm` |

Префикс нужен там, где на одном ключе документа живут несколько экранов: на
ИНТЕГРЕ это две вкладки, которые по очереди занимают один и тот же `#doc`. По
префиксу модуль понимает, что патч соседней вкладки не сирота, а просто ждёт
своей очереди. Если на корне `data-doc` нет, префиксом становится `doc`, и все
блоки всех экранов сваливаются в одно пространство имён.

Хэш берётся от **шаблонного** текста, а не от отредактированного. Отсюда два
следствия, оба намеренные.

Патч переживает переверстку: можно переписать CSS, поменять сетку, перенести
блок в другое место секции.

Патч отваливается, если переписан сам исходный текст этого абзаца в шаблоне.
Такие патчи **не пропадают молча**: они считаются осиротевшими, и страница
показывает красную плашку сверху с их числом. Ручные `data-edit` считаются
наравне с автоматическими адресами. Плашку видит и зритель без
`?edit=1`, потому что молчаливая подмена правленого текста шаблонным на показе
опаснее, чем некрасивая полоса.

Для ячеек таблиц в адрес дополнительно входит подпись строки и номер колонки.
Без этого «да», «нет» и «-» в разных строках дают один хэш, а порядковый номер
переезжает на соседа при вставке строки, и правка садится не в ту ячейку.

Критичным цифрам всё равно лучше проставить `data-edit` руками: тогда адрес не
зависит от текста вообще.

## Что сохраняется

Не файл целиком, а карта патчей `{block_id: html}`. Версия это снимок такой
карты. Поэтому история весит килобайты, а откат меняет только текст, не трогая
вёрстку.

Вставка из буфера идёт только текстом. HTML проходит белый список тегов
(`b, strong, i, em, u, br, span, a, ul, ol, li, p, small, sup, sub, code, div`)
и атрибутов (`class, href, target, rel`), остальное разворачивается;
`javascript:`, `data:` и `vbscript:` в ссылках вырезаются вместе с ведущими
управляющими символами. Фильтр стоит **и на записи, и на чтении из базы**, а
разбор идёт в отдельном inert-документе, чтобы `<img onerror>` не выполнился
раньше, чем его вырежут. Доверять содержимому базы нельзя: писать туда может не
только этот код.

## Шифрование

```js
window.LIVEEDIT_KEY(cryptoKey);   // отдать модулям ключ, когда он появился
window.LIVEEDIT_READY             // Promise: патчи наложены или их не будет
```

Страница с парольным входом (`gentero-integra/build-gate.js`) выводит AES-ключ
из пароля и передаёт его сюда, а перед снятием парольного экрана ждёт
`LIVEEDIT_READY`. Без этого ожидания зал сначала видит шаблонные цифры, а через
полсекунды их подмену на глазах.

Потолок ожидания 9 секунд, он намеренно больше таймаута запроса к хранилищу
(8 секунд). Иначе оставалось бы окно, где экран уже снят, а ответ ещё едет.
Если патчи всё же пришли после потолка, они **не накладываются**: вместо
подмены цифр на глазах показывается плашка с предложением обновить страницу.

Форматы байтов разные, не перепутать:

```
тело документа   base64( salt[16] || iv[12] || ciphertext+tag )
патч и снимок    base64(            iv[12] || ciphertext+tag )
```

Совместимость между ними по ключу, а не по байтам. Патчи и снимки дополнительно
связаны со своим местом через AAD (`doc_key|block_id`, `doc_key|version`): без
этого payload одной ячейки таблицы валидно расшифровался бы на месте другой, и
подмена цифр не потребовала бы знания пароля.

## Границы, о которых стоит знать

- **Обнаружения конфликта нет.** Запись идёт безусловным upsert без сверки
  времени. Две вкладки, правящие один блок, тихо перезапишут друг друга.
  Перед откатом сервер перечитывается, чтобы не стереть чужую работу, но это
  не заменяет блокировку.
- **Последняя правка при закрытии вкладки** уходит через `keepalive`, а он
  ограничен 64 КБ. Блок крупнее не уйдёт, и это попадёт в плашку.
- **Восстановление из выгрузки ручное.** `liveedit-cli.js` только читает,
  обратной загрузки в базу нет.
- **Внутри одного проекта Supabase разделения по документам нет.** Политики
  дают вошедшему право писать в любой `doc_key`. Регистрация посторонних
  выключается в консоли руками, кодом это не проверяется.

## Что этот модуль НЕ защищает

Читайте это до того, как класть сюда что-то чувствительное.

- **Кто знает пароль документа, читает всё.** Все патчи и все снимки версий, то
  есть каждую промежуточную редакцию, включая те формулировки, которые вы потом
  смягчили. Удаление версии в панели убирает строку, но не отменяет того, что
  её уже могли выгрузить.
- **Кто знает пароль, может и писать** корректно зашифрованные патчи, если у
  него есть учётка редактора.
- **Разделения доступа внутри документа нет.** Ключ на документ один. Материал,
  который часть читателей видеть не должна, кладётся в отдельный документ с
  отдельным паролем, а не в приватный слой того же.
- **Метаданные открыты.** `doc_key`, `block_id`, `author`, `label` версии и
  таймстемпы лежат незашифрованными. `block_id` содержит хэш шаблонного текста,
  а шаблон публичен, поэтому по ним видно, какие именно абзацы вы правили,
  сколько раз и когда. Само содержимое правки при этом закрыто.
- **Шифрование не защищает целостность и доступность**, только тайну. От
  удаления и подмены защищают политики RLS и AAD, а не шифр.
- **Потеря пароля означает потерю всех версий.** Ключ нигде не депонируется.
- **Поиска и сравнения на сервере нет.** Всё считается в браузере после
  расшифровки.

## Резервная копия

Плашка появляется и в трёх других случаях: сервер не ответил, часть строк не
открылась вашим ключом, правка не сохранилась на сервер. Последнее важнее
всего: при отказе записи карта патчей откатывается к состоянию базы, а текст
на экране остаётся правленым. Плашка так и говорит: «на экране они есть, в базе
нет». Это сделано намеренно, чтобы не отнимать текст у того, кто его только что
набрал, но полагаться на экран как на признак сохранности нельзя.

Кнопка «Выгрузить копию» в панели версий отдаёт JSON с расшифрованным текущим
состоянием, шаблонными текстами и всей загруженной историей. Храните её вне
Supabase. Файл открытый, в публичный репозиторий он не кладётся.

Если панель недоступна (проект уснул, RLS перекрыт, база переехала), строки
выгружаются из Supabase как JSON и расшифровываются вне браузера:

```
node liveedit-cli.js decrypt <gated.html> <rows.json> <пароль> [doc_key]
```

Соль берётся из самой собранной страницы.

## Только версии, без редактора

Когда состояние держит сам проект (форма, конструктор, настройки дашборда):

```html
<script>window.VERSIONS_HOST = {
  getState: function(){ return собратьСостояние(); },
  setState: function(s, o){ применить(s); }   // o.preview = true: только показать
};</script>
<script src=".../smm/liveedit/versions-init.js" data-doc="имя-проекта" defer></script>
```

В этом режиме вход живёт в самой панели: кнопка «Войти, чтобы сохранять»
появляется, пока сеанс не открыт, а «Сохранить версию» до входа заблокирована.
Готовность (`LIVEEDIT_READY`) этот загрузчик не отдаёт: ждать историю версий
перед показом документа незачем.

## Две копии модуля

Канонический исходник лежит в `smm/public/liveedit/`. В `gentero-integra/public/liveedit/`
лежит его копия, потому что GitHub Pages раскладывает проекты по подпапкам и
боевая страница грузит модуль относительным путём.

**После любой правки прогоните `node test-sync.js`**: он сверяет обе копии
побайтово и падает при расхождении. Пока сверка ручная, правка, внесённая в одну
копию, до боевой страницы не доезжает, и это уже случалось.

## База

`schema.sql`, выполнить один раз в SQL editor проекта Supabase. Скрипт
идемпотентный и снимает политики первой редакции. Пользователь-редактор
заводится руками в Authentication -> Users, регистрация посторонних там же
выключается.

## Публичные хуки

| Вызов | Что делает |
|---|---|
| `BLOCKEDIT_REFRESH()` | Наложить патчи заново после смены DOM (переключение вкладки, динамический рендер). Пересчитывает и плашку состояния: без этого её число описывало бы предыдущую вкладку |
| `BLOCKEDIT_RELOAD()` | Перечитать сервер (используется перед откатом) |

| `BLOCKEDIT_APPLY(state)` | Применить и сохранить. Требует прав на запись |
| `BLOCKEDIT_PREVIEW(state)` | Только показать, хранилище не трогать |
| `BLOCKEDIT_EXPORT()` | Расшифрованная карта патчей и шаблонов |
| `BLOCKEDIT_INFO()` | Блоки, патчи, сироты, состояние загрузки, право записи |
| `BLOCKEDIT_SETCRYPT(c)` | Отдать ключ |
| `VERSIONS_SNAP(label)` | Снять версию |
| `VERSIONS_TOUCH()` | «Была правка», для авто-снимков |
| `VERSIONS_FLUSH()` | Снять версию, если есть несохранённые правки |
| `VERSIONS_RELOAD()` | Перечитать историю |
| `VERSIONS_PREVIEWING()` | Идёт ли просмотр старой версии |
| `VERSIONS_EXPORT()` | Выгрузить копию файлом |
| `VERSIONS_EXITPREVIEW()` | Закрыть просмотр версии (зовётся при перерисовке документа) |
| `LIVEEDIT_TOOLATE()` | Пришли ли патчи после снятия парольного экрана |
| `VERSIONS_SETCRYPT(c)` | Отдать ключ |
| `LIVEEDIT_KEY(cryptoKey)` | Передать модулям ключ страницы, возвращает `LIVEEDIT_READY` |

### Ключи прошлых сборок

Страница с шифрованием выводит ключ из пароля и **соли**, а соль лежит в самой
собранной странице. Пока сборщик генерировал соль заново на каждую публикацию,
ключ менялся, и все сохранённые правки переставали открываться. Соль теперь
берётся из предыдущей сборки, а прошлые соли перечислены в
`gentero-integra/liveedit-salts.json` и попадают на страницу как
`window.LIVEEDIT_ALT_SALTS`.

| Вызов | Что делает |
|---|---|
| `LIVEEDIT_ALTKEYS([CryptoKey])` | Отдать модулям ключи прошлых сборок. Показ ими не задерживается: они приезжают после основного |
| `BLOCKEDIT_ALTKEYS([LiveCrypt])` | То же для редактора блоков напрямую |
| `VERSIONS_ALTKEYS([LiveCrypt])` | То же для истории версий |
| `BLOCKEDIT_LOCAL_COUNT()` | Сколько правок лежит в localStorage этого браузера |
| `BLOCKEDIT_IMPORT_LOCAL()` | Перенести их на сервер, вернуть `{ok, total}` |
| `VERSIONS_PAINTAUTH()` | Перерисовать состояние входа в панели версий |

Правка, прочитанная запасным ключом, после входа редактора перешифровывается
текущим. Это единственный способ вернуть в оборот то, что было сохранено до
стабилизации соли.

После правки ядер поднимите `CORE_VERSION` в обоих загрузчиках, иначе у

подхватят изменения не мгновенно, поэтому всё версионируемое лежит в ядрах.

## Оформление

Интерфейс модуля собран из своих токенов. Все имена начинаются с `--le-`, и это
не аккуратность, а условие работоспособности: до `theme.js` модуль читал цвета
из переменных страницы-хозяина (`--ink`, `--card`, `--line`, `--cta`). Имена
ходовые, и на первой же тёмной странице с `--ink: #071008` заголовок панели
оказался чёрным по тёмно-серому. Совпасть случайно с `--le-surface-2` уже нельзя.

**Свой акцент подключается двумя строками:**

```css
:root{ --le-accent:#c7ff39; --le-accent-ink:#071008 }
```

`--le-accent` красит основное действие, метку последней версии, обводку фокуса и
подсветку правимого блока. `--le-accent-ink` это текст поверх акцента, его
контраст к акценту проверяет проект: ниже 4.5:1 опускать нельзя.

Больше проект не объявляет ничего. Остальные токены служебные, их имена могут
поменяться в следующей редакции. Внутри модуль читает акцент как
`var(--le-accent, var(--le-accent-auto))`, иначе переопределение не сработало бы
вовсе: у `:root` проекта и `:root` модуля одинаковая специфичность, а лист
модуля добавляется скриптом и всегда лежит ниже.

Шрифт наследуется от страницы, размеры и начертания задаёт модуль. Шортката
`font:` с `inherit` в позиции семейства в коде нет: такая запись невалидна
целиком, и её отбрасывание роняло типографику панели на стили хоста. Это
утверждение проверяется, а не декларируется: `node test-css.js` падает, если
шорткат вернётся, и он же ловит обращение к CSS-переменной без префикса `--le-`.

Кольцо фокуса намеренно **не** строится на акценте: белая обводка вплотную и
тёмная сразу за ней видны на любой подложке, включая сам акцент. Пока кольцо
рисовалось акцентом, на баннере просмотра версии оно совпадало с фоном один в
один, и человек с клавиатуры не видел, стоит он на «Вернуть эту» или на
«К текущей».

Проект может объявить `--le-safe-top` высотой своей фиксированной шапки. По ней
модуль ставит панель правки блока и баннер просмотра, иначе для блока в начале
страницы они уезжают под чужую шапку.

## Тема и доступность

Тему модули выбирают по **фактическому фону хоста**, а не по системной
настройке зрителя: страница может быть жёстко тёмной при светлой системе.
Результат пишется в `data-le-theme` на `<html>`. Чтобы зафиксировать тему
вручную, поставьте `data-le-theme` и `data-le-theme-lock="1"`: измерение тогда
не перетирает выбор. После смены темы самой страницей вызовите
`LiveTheme.apply('#doc')`.

Контраст текста к своей подложке не ниже 4.5:1 на обеих темах, включая подписи
и диагностику; границы кнопок и полей не ниже 3:1. «Было» и «стало» в сравнении
версий различаются не только цветом: у «было» знак минус и зачёркивание, у
«стало» знак плюс. На монохромном проекторе и при дальтонизме направление
изменения читается.

Правка доступна с клавиатуры: в режиме правки блоки получают `tabindex`, вход
по Enter, сохранение по Ctrl+Enter, отмена по Esc. Закрытая панель версий
помечается `inert` и уходит из порядка табуляции. Статусы объявляются через
`role="status"`, баннер просмотра версии - через `aria-live="assertive"`, имена
кнопок в списке версий содержат дату своей версии. Удаление версии сделано
значком без подписи, но с полным `aria-label`: подпись словом рядом с «Вернуть»
провоцирует промах, а необратимое действие промаха не прощает.

## Стенд оформления

`demo.html` показывает обе панели на локальном хранилище, без сервера, пароля и
логина. Кнопка «Насыпать версий» кладёт историю с разным возрастом и разным
числом отличий, кнопка смены темы переворачивает фон страницы и заставляет
модуль перевыбрать тему.

```
python3 -m http.server 8099    # из smm/public
open http://127.0.0.1:8099/liveedit/demo.html
```
