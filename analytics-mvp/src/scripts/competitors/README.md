# Пилот: публичные данные по конкурентам GG с OZON

Отвечает на вопрос Ивана: «можно ли по конкурентам тянуть цену / выручку / заказы за день по артикулу».

**Решение по итогу пилота: собираем только ФАКТ** - цена / базовая цена / рейтинг / отзывы / наличие /
остаток. Заказы и выручку не оцениваем (OZON их не отдаёт, а оценка - это гипотеза, не факт).

## Что OZON отдаёт, а что нет

| Поле | Источник | Класс |
|---|---|---|
| Цена, базовая цена | публичная карточка (composer-api) | **[ДАННЫЕ]** |
| Рейтинг, число отзывов | публичная карточка | **[ДАННЫЕ]** |
| Наличие, остаток (если показан) | публичная карточка | **[ДАННЫЕ]** |
| Заказы / выручка за сутки | НЕ отдаётся ни Seller API, ни публично | не собираем |

OZON Seller API возвращает только данные твоего кабинета. Продажи чужих SKU не отдаёт нигде.
Кабинетная «Аналитика конкурентов» / «Что продавать» - только UI (Premium Plus), без публичного API.

## Файлы

- `input.json` - 13 артикулов конкурентов из Excel (Стол обеденный, ЛайфМебель / OpenDesign), привязка к товару GG.
- `parse.ts` - чистый парсер ответа composer-api (тестируется на фикстуре, без сети).
- `parse.test.ts` - тесты парсера (6 шт).
- `pilot.ts` - оркестратор: скрейпит карточки, пишет снимок + отчёт (только публичные поля).

## Запуск

```bash
# Локально (где открыт ozon.ru) или в GitHub Actions:
npx tsx src/scripts/competitors/pilot.ts --out data/competitors
```

Выход: `data/competitors/competitors_YYYY-MM-DD.json` + `report_YYYY-MM-DD.md`.
Workflow: `.github/workflows/competitors-pilot.yml` (ручной запуск; для истории цен включить cron).

## Ограничения (честно)

- **Сеть:** в web-контейнере Claude `ozon.ru` закрыт политикой (403) - живой прогон только из Actions/локально.
- **Анти-бот:** «только цена» НЕ обходит защиту - OZON режет сам скрейпинг по IP дата-центра (включая
  GitHub Actions), независимо от набора полей. Если 0 карточек - нужен **резидентный прокси**
  (через undici ProxyAgent, следующая итерация) или ручной прогон с домашнего IP.
- **Остаток** OZON показывает не всегда (часто пусто) - это нормально.

## Следующий шаг

Цена/рейтинг/отзывы собираемы и надёжны. Чтобы получить реальные цифры, пилот надо прогнать там,
где открыт `ozon.ru` (домашний IP / Actions). Если датацентр-IP режется анти-ботом - добавить
резидентный прокси (минимальная доработка `pilot.ts` на undici ProxyAgent под env `OZON_SCRAPE_PROXY`).

## Пополнение списка: импорт из Google-таблицы

Чтобы не править `input.json` руками, список конкурентов ведётся в Google-таблице и импортируется
скриптом. Так удобно дозаполнять и обновлять данные - добавил строки, перезапустил импорт.

**Колонки** (первая строка - заголовки; принимаются рус/англ, порядок любой, лишние игнорируются):

| Заголовок | Что класть |
|---|---|
| Артикул | SKU конкурента на OZON (число из ссылки `ozon.ru/product/<sku>`; можно вставить и саму ссылку) |
| Продавец | имя конкурента |
| Название конкурента | название его карточки |
| Товар GG | наш товар, с которым сравниваем |
| Категория | категория (по ней работает фильтр на дашборде) |
| Квалификация | Горячий / Тёплый / Холодный |

Стартовый шаблон с текущими 13 строками: `competitors_template.csv` (Google Sheets -> Файл -> Импорт).

**Доступ:** таблицу открыть «всем, у кого есть ссылка» (Доступ -> Читатель) или опубликовать вкладку -
импорт тянет CSV-экспорт без OAuth, поэтому работает и локально, и в Actions.

**Запуск:**

```bash
# по ссылке на таблицу (gid вкладки подхватится из ссылки):
npm run import:competitors -- --url "https://docs.google.com/spreadsheets/d/<ID>/edit#gid=0"
# или по ID + номеру вкладки:
npm run import:competitors -- --id <ID> --gid 0
# или через окружение (удобно для CI):
COMPETITORS_SHEET_ID=<ID> npm run import:competitors
```

Импорт перезаписывает `input.json` (валидирует артикулы, чистит дубли/пустые строки, пишет
предупреждения). Дальше: `npm run katya` (демо-лист обновится) и/или прогон пилота (живые данные).
