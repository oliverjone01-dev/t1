# Атрибуция лидов GENGLASS: постоянные факты (для любой аналитики)

Обновлено: 2026-07-16, источник - Дмитрий (владелец кабинета Директа).

1. **Царь-цель**: Метрика 487033158 «CRM | Все лиды» (плюс 487033859 «Качественные»). Механика: лид попадает в CRM → автовыгрузка в Google Sheets по API → проброс в Метрику по client_id как ОФЛАЙН-конверсия.

2. **СЛЕПАЯ ЗОНА: онлайн-чат MAX (виджет yourgood).** Подтверждено 2026-07-16: чат НЕ фиксируется в офлайн-целях, т.к. в CRM не передаёт client_id. Обращения через чат частые → эти лиды НЕ доходят до царь-цели вообще. Следствия:
   - Все CPL по цели 487033158 ЗАВЫШЕНЫ (реальных лидов больше).
   - Сравнение каналов/кампаний искажается, если доля чат-обращений в них разная (важно для эксперимента Поиск vs ТГ - вердикт 24.07 может быть смещён).
   - Оптимизация Директа по этой цели недоучитывает чат-конверсии по кампаниям/ключам.

3. **Путь фикса (2 уровня, независимы):**
   - **Быстро (client-side, не требует CRM):** повесить JS-цель Метрики на событие «отправлено первое сообщение в чат MAX» - `ym(104369223,'reachGoal','chat_lead')`. client_id тут родной (то же событие на той же странице со счётчиком). Директ сразу увидит чат-конверсии по кампаниям/ключам. Минус - качество (чат-опенер != заявка), поэтому это ОТДЕЛЬНАЯ цель, не мешать с 487033158. Можно сделать составную оптимизацию.
   - **Правильно (в CRM):** при старте диалога снять ym client_id JS-сниппетом и записать в карточку CRM (скрытое поле / бэкенд по chat session id), тогда офлайн-выгрузка сматчит чат-лид с визитом. Если виджет yourgood не умеет кастомные параметры - это ограничение вендора, обходится своим сниппетом.

4. **Квантификация слепой зоны:** посчитать в CRM долю лидов с source=чат/MAX за период vs всего → это процент недоучёта. До этого все «видимые» CPL держать с пометкой «реальный ниже на долю MAX».

5. Кабинет Директа e-20085264: разметка utm_source=yandex. Источник utm_source=abdm - P0 (не кабинет).
