# Yandex Direct - рабочая папка

Рабочее пространство по настройке и оптимизации Яндекс.Директ для брендов GENGROUP.
Ветка: `claude/yandex-direct-optimization-c96txb`.

## Что здесь лежит

### `skills/direct/` - skill аудита и оптимизации Директа (staged)

Vendored open-source skill для AI-агентов (Claude Code / Cursor), API Директа v5.

| Параметр | Значение |
|---|---|
| Источник | https://github.com/Silverov/yandex-direct-skill |

Возможности:
- `audit` - полный аудит аккаунта, 55 проверок (YD01-YD55), скоринг 0-100 и оценка A-F
- `campaigns` - список кампаний со статусами и метриками
- `create` - создание кампаний
- `keywords` - работа с ключами (добавление, пауза, ставки)
- `report` - отчёты (CTR, CPC, конверсии, расход)
- `optimize` - рекомендации по эффективности бюджета
- `budget` - анализ расхода и прогноз
- `negative` - минус-слова против слива бюджета

Веса категорий аудита: Конверсии/Метрика 25%, Слив бюджета 20%, Структура аккаунта 15%,
Ключи/качество 15%, Объявления/расширения 15%, Настройки/таргетинг 10%.

## Security review (проведён перед внесением)

- Скрипты обращаются только к официальным эндпоинтам: `api.direct.yandex.com/json/v5`
  и `/json/v5/reports`. Сторонних хостов нет.
- OAuth-токен читается локально из `~/.secrets/yandex-direct.json` и передаётся только
  в заголовке `Authorization: Bearer` к API Яндекса. Токен нигде не хардкодится и не
  уходит на сторону.
- Нет `eval`, нет `rm -rf`, нет исполнения удалённого контента.

## Активация

Skill подключён в живой ростер (`.claude/skills/direct/`). Для работы нужны два условия,
оба настраиваются в окне настроек окружения Claude Code on the web.

### 1. Токен (аутентификация)

Скрипты берут учётные данные в порядке приоритета:
1. Переменные окружения (рекомендуется для web) - `YANDEX_DIRECT_TOKEN`,
   опционально `YANDEX_DIRECT_LOGIN` (логин клиента для агентских аккаунтов).
2. Локальный файл (для терминала) - `~/.secrets/yandex-direct.json`
   формата `{ "oauth_token": "...", "client_login": "..." }`, права `chmod 600`.

Переменные окружения задаются в настройках окружения (формат `.env`, без кавычек):

```
YANDEX_DIRECT_TOKEN=<OAUTH_TOKEN>
YANDEX_DIRECT_LOGIN=<логин-клиента>
YANDEX_METRIKA_TOKEN=<OAUTH_TOKEN_METRIKA>
YANDEX_METRIKA_COUNTER=104369223
```

Счётчик `104369223` - рабочий счётчик GENGLASS ("Новый GenGlass", genglass.ru,
связка с Директом + ecommerce). Это идентификатор, не секрет.

Переменные применяются при старте новой сессии. Токен получается через OAuth-приложение
Яндекса с доступом к API Директа (https://yandex.ru/dev/direct).

Важно (безопасность): в Claude Code on the web выделенного secrets-store пока нет,
переменные окружения видны тем, кто может редактировать окружение. Токен в git не коммитить.

### Хранение секретов (тот же паттерн, что в analytics-mvp)

- В git коммитится только шаблон `yandex-direct/.env.example` (пустые значения).
- Реальные токены кладутся в `yandex-direct/.env` - он в `.gitignore` и на GitHub НЕ уходит.
- `.gitignore` закрывает: `**/.env`, `**/.env.local`, `**/.secrets/`, `yandex-direct.json`.
- Приоритет чтения токена скриптами: переменные окружения → `yandex-direct/.env` →
  `~/.secrets/yandex-direct.json`. Реальные ключи в репозитории не хранятся никогда.

### 2. Сетевой доступ

Сетевая политика окружения по умолчанию блокирует внешние домены (прокси отдаёт 403 на
`api.direct.yandex.com`). В настройках окружения нужно выбрать уровень доступа Custom и
добавить в Allowed domains:

```
api.direct.yandex.com
api-metrika.yandex.net
```

Без этого скрипты не достучатся до API даже с валидным токеном.

### Зависимости

`curl` и `jq` уже присутствуют в окружении (проверено).

## Остаток на счёте: контракт (живые пробы 30.09.2026)

Ночной синк снимает остаток в `yandex-direct/data/direct_account.json`. Разбор живёт одним
модулем `dashboard/lib-account.mjs`, стенд - `tests/account-stand.mjs` (гоняется в workflow
до живых вызовов).

**Сервиса `accountmanagement` в API v5 НЕТ.** `POST /json/v5/accountmanagement` отвечает
HTTP 404. Остаток отдаёт только Live v4, и это другой протокол: **токен лежит в теле
запроса**, а не в заголовке. Поэтому тело запроса и текст ответа не попадают в сообщения об
ошибках ни при каком исходе - иначе токен уехал бы в лог Actions. [ДАННЫЕ]

Хост: `https://api.direct.yandex.com/live/v4/json/`. Домен `api.direct.yandex.ru` прокси
**закрыт** (403 «Host not in allowlist»), но Live v4 отвечает и на `.com`, который уже в
allowlist. Отдельный домен добавлять не нужно. [ДАННЫЕ]

`SelectionCriteria` передаётся **пустым**. С явным `Logins` Директ отвечает
`515 Требуется подключить общий счёт` и отдаёт пустой список счетов. [ДАННЫЕ]

### Что приходит

| Поле ответа | В снимке | Значение 30.09.2026 |
|---|---|---|
| `Amount` | `balance` | 52 655.11 |
| `AmountAvailableForTransfer` | `available_for_transfer` | 53 138.15 |
| `AccountDayBudget.Amount` | `day_budget` | 5 000 |
| `EmailNotification.MoneyWarningValue` | `warning_at` | 20 |
| `AgencyName` | `agency` | eLama.ru |
| `Currency` | `currency` | RUB |

**Суммы приходят строками** («52655.11»), не числами. Разбор возвращает `null` на пропуске,
пустой строке и мусоре, и `0` только на честном нуле: `Number('')` даёт ровно 0, и без этой
развилки отсутствующий остаток показал бы «денег нет» (реестр E075). [ДАННЫЕ]

**`balance` и `available_for_transfer` - разные числа**, и второе больше первого:
`Amount` это остаток на общем счёте, а `AmountAvailableForTransfer` учитывает возврат с
кампаний. Путать их нельзя. [ДАННЫЕ]

**Счёт обслуживает агентство eLama.** Остаток в кабинете eLama - **другое число**, этим
снимком не покрыто. Говорить «столько денег на рекламе» по одному этому полю нельзя. [ДАННЫЕ]

### Почему одного числа достаточно, и когда перестанет

Все 35 кампаний финансируются с общего счёта (`Funds.Mode = SHARED_ACCOUNT_FUNDS`),
собственных кошельков у кампаний нет - значит один `Amount` описывает всю рекламу. [ДАННЫЕ]

Это условие, а не свойство: если хоть одна кампания переедет на `CAMPAIGN_FUNDS`, остаток
общего счёта перестанет быть полной картиной. Поэтому синк пишет в снимок свод
`funding.modes` и флаг `funding.all_shared`, а прогон печатает предупреждение. Складывать
общий счёт с кошельками кампаний молча нельзя - это двойной учёт.

### Чем этот остаток НЕ сверен

Обе цифры - из одного источника, самого Директа, поэтому «сошлось» тут не говорится.
Независимой стороной были бы остаток в кабинете eLama или платёж банка. Пока это
односторонний факт API. [ДАННЫЕ]

Отказ снятия **не валит синк**: остальные снимки нужнее одного числа. Но и не молчит - в
снимке остаётся `ok: false` с полем `error`, а прогон печатает строку в сводку. Ноль вместо
отказа не подставляется никогда.

### Чего в снимке нет намеренно

- `Login` и `Email` из ответа не переносятся: снимок коммитится в репозиторий.
- `dateFrom` / `dateTo` не кладутся: остаток это **момент**, а не период, и подпись периодом
  заставила бы читать его как «за 30 дней». Момент - в `generated_at`.
- «На сколько дней хватит» не считается. Это метрика с определением (по какому окну средний
  расход, ограничивает ли дневной бюджет), её спека и Step 12.5 - перед первым виджетом.

## Дисциплина работы

Любая задача с цифрами (эффект на выручку, CPA, ROMI, бюджеты) проходит Protocol 9
(Reality Audit) до выводов. Каждая цифра помечается `[ДАННЫЕ]` (с источником) или
`[ГИПОТЕЗА]` (с допущениями). Критические артефакты - через Step 12.5 (ФЕНИКС).
