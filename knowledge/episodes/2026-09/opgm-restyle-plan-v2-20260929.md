### 3.1 Метод

1. **Состояния:** 7 экранов с шапкой (Пульс, Скорость, Проблемы, Объявления, Звонки, Рассылка, Все диалоги) × 3 кабинета × 4 периода = 84; «Сегодня» 3 кабинета × 4 срока = 12; «Откуда цифры», 6 экранов архива, Разборы, Скрипты, Что делать = 10; профили менеджеров из данных (на стенде 1). Итого 107 на стенде [ПРОВЕРЕНО: `numsnap snap`, строка «состояний 107»]. Экранов вне «Детализации» 18 по меню (opgm.js:546-556), не 19, как в v1.
2. **Ключ смысловой, не порядковый:** плитка = подпись плитки (`.ks-tile-label`, в ней кабинет) + часть плитки; ячейка = раздел + заголовок строки + заголовок столбца (или `data-label`); полоса = раздел + подпись полосы; строка вердикта = имя (кабинет и показатель); карточка переписки = хэш `data-th`; прочий текст = раздел + текст блока с цифрами, заменёнными на `#`; `dd` получает подпись своего `dt`. Раздел = заголовок карточки, очереди, панели или вердикта.
3. **Сравниваются числовые токены под ключом по порядку** (v3; разделители тысяч склеиваются, знак «+» и «-» сохраняется), не сырой текст. Мультимножество осталось только у ячеек таблиц: ключ ячейки уже несёт строку и столбец. Перестановка чисел внутри блока (строка источника, подсказка «было / стало») - расхождение.
4. **Графики (v3):** подписи осей, подписи данных и легенда ApexCharts собираются отдельным классом «график» (ключ = раздел + номер графика + часть), по порядку, без `<title>`. Данные графиков дополнительно идут через таблицу-двойник. `style`/`script` не собираются. **Собираются** числа в `data-tip` и `aria-label` спарклайнов. Волна, которая меняет размер графика, меняет и шкалу оси: такие изменения идут записью `allow_change` на «» график» с причиной.
5. **Слои поверх (v3):** у каждой плитки с `data-drill` панель открывается, числа панели снимаются под ключом `[drill]`. Число плитки сравнивается с **назначенным узлом итога панели** (`[data-panel-total]`, иначе кнопка «все N в «Все диалоги»», пустая панель = 0), а не с любым числом панели. Регрессия (было равно или узла не было, стало не равно; узел итога пропал) = необъяснённое расхождение. На базе 24eb500d итог назначен у 32 панелей из 80, все 32 равны плитке; у 48 панелей скорости и доли за 15 минут итога нет (старое правило давало «да» у 16 из них совпадением). Требование W3: `data-panel-total` у каждой панели, цель 80 из 80.
6. **Условия съёмки:** часы браузера = момент выгрузки, `reducedMotion: reduce`, Europe/Moscow, ширины 1280 и 390 (состояния 390 с суффиксом « @390», без панелей и фильтров). Графики экрана дорисованы до открытия панели; между закрытием и открытием панели 400 мс, больше таймера очистки 320 мс (kit.js:330, §4.3).
7. **Закреплённые входы:** sha256 канонического JSON данных стенда в отчёте снимка; при разных sha сравнение не идёт (код 2). На реальных данных: пара «до/после» собирается из одних и тех же av.json и recon.json (sha256 обоих в отчёте снимка); на каждой понедельничной выгрузке новая база снимается на старом коде.
8. **Манифест волны** (JSON): `rename` (переименования из §5), `allow_new` (новый узел допустим, только если его значение уже есть на том же состоянии; `value_from_re` указывает узел-источник, например «всего ответить» для героя W2), `allow_change`, `allow_removed`. Запись манифеста, которая ни разу не сработала, это провал: манифест не может быть шире изменения.
9. **Коды выхода:** 0 = необъяснённых 0; 1 = есть необъяснённые или лишние записи манифеста; 2 = разные входы, разные или частичные режимы прогона, снимок старого формата, ошибка страницы.
10. **Покрытие данных (§15 п.3), а не селекторов:** отчёт снимка печатает состояния из матрицы, ключи, узлы с цифрами по классам, слабые ключи (раздел «экран» без слов в тексте), панели открыто из скольких. На реальных данных дополнительно: доля чатов выгрузки, попавших хотя бы в один экран за «всё время» (берётся из отчёта склейки Д5).
11. **База снимается после выпуска Д-пакета**, не на 24eb500d (Р8); на реальных данных её снимает сессия Д-пакета (§3.7).
12. **Читаемость (v3):** у каждого ключа число читаемых узлов: прямоугольник текста больше 0, `visibility: visible`, альфа цвета и итоговая непрозрачность с предками не меньше 0,5, кегль не меньше 11 px, предок с `overflow: hidden|clip` не обрезает больше половины. «Читался в базе, не читается после» = расхождение «перестал читаться» (объясняется только записью `allow_hidden` с причиной). Критерий W1 «на 390 без прокрутки вбок» действует только вместе с этим.
13. **Фильтры «Все диалоги» (v3):** каждое значение «Проблема», «Отметка», «Кто начал» один раз (24 состояния на стенде), выбор через `selectOption` с событием change.
14. **Режим прогона в meta (v3):** `views`, `no_drawers`, `close_wait`, `widths`, `no_filters`, `data_mode`, признак `partial` и матрица «снято N из M». `diff` даёт код 2, если режимы пары разные или снимок частичный без явного `--allow-partial`; отчёт печатает матрицу и «панелей N из N».

### 3.5 Изъяны метода, которые остаются (честно)

- Ключ «прочий текст» держится на тексте блока: переписанная фраза с числом даёт «узел пропал» и «новый узел». Это правильное поведение (текст с числом изменился), но каждая такая правка требует записи `rename` в манифесте.
- Совпадение значения героя с числом где-то на экране без `value_from_re` слабее: в первой версии манифеста без узла-источника 2 из 12 состояний отрицательного контроля прошли случайно. Поэтому `value_from_re` обязателен для каждой записи `allow_new` с `value_must_exist` (инструмент печатает предупреждение, если его нет).
- Снимок на двух ширинах, 1280 и 390 (v3). Панели и фильтры снимаются только на 1280: на 390 проверяются экраны. Панели на 390 - открытый пункт (§14).
- Читаемость не видит: цвет текста, равный фону (это ловит контраст §4), перекрытие узла другим элементом (z-index), `clip-path`. Это классы следующей итерации гейта, если волна их вводит.
- Панели переписки («Посмотреть переписку») в снимок чисел не входят, только в контраст.

### 3.7 Реальные данные (ТЗ iter2 п.8): решение

**Решение: загрузчик, а не «только стенд».** Гейты волн на реальных данных запускает **сессия Д-пакета**: только у неё есть пароль, и только она расшифровывает D.

- `numsnap snap --data <папка> --op <op-gm-automation> --src <src волны> --out <файл>`: папка с `D.json` (весь расшифрованный D) или `av.json` + `recon.json` (+ `D-rest.json` с остальными ключами D). D передаётся в страницу через `addInitScript` и живёт только в памяти процесса и страницы (`harness/realdata.cjs`, `harness/fixture.js` берёт `window.__REAL_D`).
- Папка данных и выходной файл обязаны лежать вне любого git-репозитория, иначе код 2 до запуска браузера. `diff` на реальных данных не печатает значения (только ключи и число токенов), пока не задан `--values`.
- Пара «до/после» - один и тот же D (sha256 канонического D в meta, как у фикстуры).
- В план, эпизоды и отчёты ФЕНИКСУ сессия Д-пакета передаёт только коды выхода, счётчики и ключи без значений.
- W0: базу на данных 05.10 снимает сессия Д-пакета после пересборки 05.10 на принятом коде; гейт W1 и W2 на реальных данных - она же, на ветках, которые подготовила сессия рестайлинга.
