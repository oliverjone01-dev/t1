# Свод Маркета против июльского файла Ивана: разбор расхождений

**Дата:** 2026-09-17
**Источник:** выгрузка Ивана «свод июль» (130 строк, 122 артикула, два кабинета - Мебель и Зеркала)
**Задача Ивана:** «не сходятся данные по июлю собранной аналитики и твои данные, проанализируй выяви
несоответствия, столбцы расположи также как и у меня»

## Модель расчёта Ивана восстановлена точно

Проверена на артикуле GGT-35-1-3-100-180 до копейки и на итогах листа:

- **Поступление** = Продажи + Доставка покупателя − сумма 9 колонок сборов
  (Размещение, Программа лояльности, Продвижение, Общие расходы, Доставка, Приём платежа,
  Перевод платежа, Баллы Маркета, DBS)
- **Валовая прибыль** = Поступление − СС произв
- **Маржа, %** = Валовая / Поступление
- **АДМ 30%** и **Налоги 15%** = от Поступления; на артикулах с ОТРИЦАТЕЛЬНЫМ поступлением не
  начисляются (3 таких артикула на −15 422,64 ₽, отсюда итог АДМ 1 608 198,82 вместо 1 603 572,03)
- **Чистая прибыль** = Валовая − АДМ − Налоги
- **Рентабельность, %** = Чистая / Поступление

Порядок колонок: Артикул · Название · Продажи · Доставка покупателя · Размещение · Программа
лояльности и отзывы · Продвижение · [Общие расходы] · Доставка · Приём платежа покупателя ·
Перевод платежа покупателя · Баллы Маркета · DBS · Штуки · Выручка ЯМ шт · СС произв за шт ·
СС произв · Валовая прибыль · Маржа % · АДМ 30% · Налоги 15% · Чистая прибыль · Рентабельность %.
«Выручка ЯМ, шт» = Поступление на единицу. Группировка: ИТОГ, строка ставок, кабинет, артикулы.

## Расхождение 1: Баллы Маркета, −1 724 146 ₽. Разные базисы, ошибки нет ни у кого

Файл Ивана считает баллы, СПИСАННЫЕ В ИЮЛЕ. Свод считает все баллы ПО ИЮЛЬСКИМ ЗАКАЗАМ.

Разложение баллов по июльским заказам на месяц проводки в реестре:

| группа артикулов | списано в июле | списано в августе |
|---|---:|---:|
| где числа совпали (77 артикулов) | 2 292 266 | 0 |
| где разошлись (45 артикулов) | 889 916 | 1 679 470 |

По 77 артикулам, где всё списание прошло в июле, значения совпадают до рубля. Расхождение ровно
там, где Маркет дописал списание в августе: 1 679 470 из 1 724 146, то есть 97%.

Это тот же вопрос, что поднят в `ym-act-vs-bonuses-cabinet-20260917.md`: период заказа против
периода списания. Решение за Иваном и РОМАНОМ, из данных не выводится.

## Расхождение 5: DBS, 400 674 ₽. Из API не берётся

Собственный расход на доставку. Partner API его не отдаёт: проверено при снятии этой колонки

## Что из этого чинится в коде

1. «Продажи» вычитают возвраты (расхождение 3, первые два артикула).
2. Порядок и состав колонок свода приводятся к раскладке Ивана.
3. Водопад считается из тех же чисел, что таблица свода.

Не чинится без решения Ивана: базис баллов (1), лист СС (2), заказ GGT-12-2 (3), источник DBS (5).

## Как месяц докатывается: замер по факту

Вопрос Ивана: «сейчас ты заполняешь месяц который уже прошел и баллы списанные в августе ты видишь,
но если поставить сентябрь, ты же не увидишь баллы которые будут списаны потом, как это будет
докатываться».

Механика: свод не дописывается, он ПЕРЕСЧИТЫВАЕТСЯ ЦЕЛИКОМ при каждом прогоне из всего реестра.
Поэтому прошлые месяцы растут задним числом сами, без ручных действий.

Замер по всем месяцам: когда Маркет списывает услуги по заказам месяца (доля от итога месяца).

| месяц заказа | деньгами: свой / +1 / +2 | итого деньгами | баллами: свой / +1 / +2 | итого баллами |
|---|---|---:|---|---:|
| 2026-02 | 64% / 36% / 0% | 362 148 | 85% / 15% / 0% | 1 253 167 |
| 2026-03 | 72% / 28% / 0% | 704 054 | 91% / 9% / 0% | 1 692 024 |
| 2026-04 | 67% / 27% / 6% | 491 615 | 55% / 44% / 1% | 3 350 516 |
| 2026-05 | 67% / 33% / 1% | 385 650 | 66% / 33% / 1% | 3 002 286 |
| 2026-06 | 62% / 38% / 0% | 487 403 | 64% / 36% / 0% | 2 254 165 |
| 2026-07 | 64% / 36% / 0% | 1 145 313 | 65% / 35% / 0% | 4 861 651 |
| 2026-08 | 52% / 48% / 0% | 771 230 | 52% / 48% / 0% | 4 157 665 |
| 2026-09 | 100% / 0% / 0% | 129 007 | 100% / 0% / 0% | 1 019 520 |

Вывод: в свой месяц приходит около двух третей услуг, остальное в следующий, после +2 практически
ничего. Месяц становится окончательным примерно через месяц после закрытия.

Прямое следствие, которое обязано быть на экране: август собран на 52%, а «100%» сентября - это
артефакт (октября ещё нет). По незрелым месяцам расходы занижены, а прибыль завышена. Читать их
как факт нельзя.

## Выбор базиса: два разных вопроса, оба нужны

| | по месяцу заказа (свод сейчас) | по месяцу списания (файл Ивана) |
|---|---|---|
| экономика артикула | верная: услуги лежат на своих продажах | ломается: в сентябре сидят услуги августовских заказов |
| закрытый месяц | окончателен через ~месяц | окончателен сразу |
| сходится с кабинетом | нет и не должен | да, до рубля |
| текущий месяц | занижены расходы, завышена прибыль | честен, но не про продажи этого месяца |

Предложено Ивану: базу свода оставить по месяцу заказа; добавить индикатор зрелости месяца,
считаемый по доле заказов месяца без проводок в реестре (факт, не прогноз); рядом показывать
кассовое число «списано в этом месяце» для сверки с кабинетом.
