## 1. Цель
Песочница СВОД v2.1 как прикладной инструмент КПД/CR отдела продаж + «Куратор по памятке»:
машинные разборы диалогов менеджеров против памятки GENGLASS v2.3 с уликами-цитатами.
«Готово» для куратора = именная публикация на отдел: гейт ФЕНИКСА - precision >=90% при
n>=30 на каждое показываемое правило, решение по почтовому каналу, повторный взгляд на
ранжирование.

## 3. Решения и почему
- Отдел видит всех в кураторе (Иван 03.09) - планка одна.
- Улика принадлежит АВТОРУ сообщения (e.who -> канон ростера), не владельцу сделки;
  офис - строка «Первая линия» (ФЕНИКС G2/B1).
- Первый ответ - РАБОЧИЕ минуты 9-18 без сб/вс (workMinutes).
- Пороги калибровки по аудиториям (ФЕНИКС 04.09): песочница 85% при n>=15;
  публикация на отдел 90% при n>=30. Правило ниже порога скрывается ВМЕСТЕ со счётчиками
  (K1: все числа от показываемых улик).
- Приветствие (R10) - СЧЁТЧИК, не улика; якорь = первое исходящее нового диалога.
- pamyatka-блок в ночные досье ТОЛЬКО под env PAMYATKA_AI=1 (условие 3 песочницы ФЕНИКСА,
  до переразметки).
- Норматив 15 мин / цель 100% - подтверждены Иваном, не трогать.
- Ссылка песочницы менеджерам НЕ рассылается до гейта публикации (условие 1).

## 6. Грабли
- e.who в ДВУХ форматах имени - только канон ростера как ключ (B1). \b и \w не работают с кириллицей.
- Гварды писать от ПРАВДЫ, не от реализации: дважды зелёный smoke сопровождал сломанную страницу.
- Новое правило до коммита: выгрузить ВСЕ его улики на живой неделе, глазами минимум 10;
  фикстура обязана кодировать доминирующий поток данных (R10: менеджер здоровается ПЕРВЫМ).
- Письма-треды/звонки/боты (K_NONMSG) - не «клиент написал»; подписи писем дают ложных «директоров».
- github.io из контейнера недоступен (прокси) - верификация деплоя по conclusions run'ов.
- Скрэтчпад прошлой сессии утерян (rop-fresh/dlg-fresh/shot-скрипты/kalibrovka-страница) -
  всё регенерируется скриптами репо, страница разметки - однофайловый генератор, есть в истории чата, проще переписать заново из payload.
