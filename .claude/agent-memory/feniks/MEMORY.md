- Self-claimed score внутри артефакта (sales-director 2026-06-30) → veto-кандидат.
- Правка защитного механизма без регрессионного теста даёт регрессию: ростер v3, итерация 3 (2026-09-06),
  allow-list read-only команд впустил исполнителя `env`, 4 ранее закрытых вектора открылись. Проверять не только
  «закрыто ли названное», но и «не открылось ли ранее закрытое»: сравнивать поведение хука на двух коммитах.
- Автор закрывает критерий приёмки по букве на урезанной фикстуре. Формулировать приёмку на полном объекте
  (ростер v3, итерация 3: кейс стенда без `checkpoints` VALID, с 25 чекпоинтами INVALID). Моя доля вины,
  формулировка приёмки в итерации 2 была слабой.
- Правка ложных срабатываний делается по моим примерам, а не по причине. Требовать формулировку класса
  («символ `>` в тексте не есть перенаправление»), иначе соседний случай остаётся сломанным.
- Поправка правила расходится не по всем слоям: v3 дошла до схемы, валидатора, workflow и документов, но не до
