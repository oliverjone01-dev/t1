# Проект: ответы бота в Telegram на вопросы отдела (@ropcache_bot)

Статус: проект и смета на согласование Ивану. Кода пока нет.
Дата: 2026-09-07.

## 1. Что хочет Иван

Любой участник рабочего чата может обратиться к боту прямо в чате и получить ответ - например «разбор по Лакомовой», «что дожать по крупным», «у кого просрочка». Сейчас бот только шлёт дайджест по расписанию и на вопросы не отвечает.

## 2. Ограничение (правило Ивана) и как мы его соблюдаем

Правило: «API только в дашборде по моему клику». Автоответ на вопрос из чата с вызовом ИИ - это расход API без клика в дашборде. Если открыть его всем без рамок, любой участник тратит кредиты Ивана бесконтрольно.

Решение - два слоя ответа:

- Слой 1, БЕЗ API (бесплатно, всем): карточка менеджера и сводки считаются детерминированно из снимка Bitrix (те же данные, что в дашборде и дайджесте). Это уже готовая логика - портфель, КП без дожима, просрочка, сделки 30+ дней, конкретные сделки. Расход ноль, правило не нарушается.
- Слой 2, С API (по рамкам): «умные» текстовые ответы и произвольные вопросы. Здесь расход кредитов, поэтому включается только с контролем (белый список, лимит, лог).

Так «все в чате» получают пользу сразу и бесплатно, а API остаётся под контролем.

## 3. Что бот отвечает без API (Слой 1)

Команды-обращения в чате (бот в группе видит только обращения к себе - упоминание, команда или ответ на его сообщение):

- `Лакомова` или `/kart Лакомова` - карточка менеджера: объём и число сделок, медиана чека, отклик, КП без дожима (сумма), просрочка, 30+ дней (работают или застряли), топ-3 сделки на дожим с номерами.
- `/otdel` - сводка по отделу: пайплайн, КП без дожима, просрочка, 30+, рейтинг менеджеров.
- `/dozhim` - список сделок с КП без дожима по всему отделу (что горит по деньгам).
- `/prosrochka` - просроченные дела по менеджерам.

Данные берутся из снимков `rop.json` и `dialog.json` (обновляются ночным и внутридневными кронами). Ответ - за секунды, без затрат.

## 4. Что бот отвечает через API (Слой 2)

- `/ai <вопрос>` - произвольный вопрос. В контекст модели кладётся не сырой массив диалогов, а уже посчитанная карточка нужного менеджера или сводка отдела плюс методичка оценки. Это держит запрос компактным и дешёвым.
- Модель по умолчанию Sonnet 5 (баланс цена/качество); для тяжёлых разборов - опционально выше.

Контроль расхода (обязателен для Слоя 2):
- Белый список, кто может звать `/ai` (например Иван и РОП), либо все с общим дневным потолком.
- Дневной лимит запросов и суточный потолок в рублях - при превышении бот отвечает «лимит на сегодня исчерпан».
- Лог каждого запроса: кто, что спросил, сколько токенов, стоимость. Складывается в git/таблицу для сверки.

## 5. Смета API

Цены `[ДАННЫЕ]` (официальный справочник, 2026-06-24):
- Sonnet 5: вход $2 / выход $10 за 1 млн токенов.
- Haiku 4.5: вход $1 / выход $5 за 1 млн токенов.
- Batch API: минус 50% (для отложенных задач, не для живого чата).
- Prompt-кэш: повторяемый контекст (методичка, системный промпт) читается со скидкой ~90%.

Размер запроса `[ГИПОТЕЗА]` (наши сценарии):
- Лёгкий (карточка + вопрос в контексте): ~6 тыс. токенов вход, ~1 тыс. выход.
- Тяжёлый (расширенный контекст по менеджеру): ~40 тыс. вход, ~1.5 тыс. выход.

Стоимость одного запроса `[ГИПОТЕЗА]`, курс ~90 ₽/$:
- Лёгкий на Sonnet 5: ~$0.022 (~2 ₽). На Haiku: ~$0.011 (~1 ₽).
- Тяжёлый на Sonnet 5: ~$0.095 (~8.5 ₽).

Месячные сценарии `[ГИПОТЕЗА]`:
- A. Только Иван и РОП, ~30 запросов/мес (в основном тяжёлые): ~$3/мес (~270 ₽).
- B. Весь чат по команде `/ai`, ~10 лёгких/день × 22 дня = 220/мес: ~$5/мес (~430 ₽). Если тяжёлые - ~$21/мес (~1900 ₽).
- C. Без рамок, ~50 тяжёлых/день: ~$140/мес (~12 600 ₽). Это и есть риск «любой жжёт кредиты» - не рекомендуется.

Отдельно - ежедневный ИИ-аудит по всем менеджерам (план Ивана «ежедневный аудит по API»):
- 7 менеджеров × 1 запрос/день (карточка в контексте, ~6 тыс. вход / ~1.5 тыс. выход) × 22 рабочих дня = 154 запроса/мес.
- Sonnet 5: ~$4/мес (~360 ₽). С Batch API и кэшем - заметно ниже.

Вывод по смете: при разумных рамках (сценарии A и B плюс ежедневный аудит) расход - сотни рублей в месяц, а не десятки тысяч. Дорого становится только без лимитов (сценарий C).

## 6. Где крутить слушатель (платформа не выбрана)

Живой ответ в чате требует всегда-включённого процесса. Сам бот-токен ничего не слушает. Варианты:

| Платформа | Плюсы | Минусы |
|---|---|---|
| n8n (в стеке) | Готовый Telegram-триггер, ИИ-нода, лог; быстрый старт | n8n-коннектор сейчас требует авторизации в claude.ai; из этой сессии подключить нельзя |
| Бот «Константин» (VPS/облако) | Полный контроль, свой лог и бюджет, ровно под план Ивана | Дольше поднять, нужен сервер и деплой |
| GitHub Actions (опрос) | Ничего нового поднимать не надо | Не живой чат: опрос раз в несколько минут, задержки; для диалога не годится |

Рекомендация: слой 1 (бесплатные карточки) не требует API и его можно повесить на n8n или «Константина» первым. Слой 2 (API) включать вторым, когда выбрана площадка и заданы лимиты. GitHub Actions - только как временный костыль для нечастых команд без реального времени.

## 7. Этапы

1. Согласовать проект и смету (этот документ).
2. Выбрать площадку (n8n или «Константин») и авторизовать доступ.
3. Слой 1: бот отвечает карточкой менеджера и сводками без API. Проверка в тест-чате.
4. Слой 2: включить `/ai` с белым списком, дневным лимитом и логом. Гейт ФЕНИКСА на методику перед выкладкой людям (Protocol 6, персональные оценки - HITL).
5. Ежедневный ИИ-аудит по API с итогами в бота, когда «Константин» готов.

## 8. Что нужно от Ивана для старта

- Выбор площадки (или «поднимаем Константина»).
- Кто в белом списке `/ai` и какой дневной потолок в рублях.
- Подтверждение, что слой 1 (бесплатные карточки) открываем всем в чате.

## 9. Риски

- Открытый `/ai` без лимита = неконтролируемый расход (сценарий C). Митигируется белым списком и суточным потолком.
- Данные в ответах чувствительны (суммы сделок, имена, клиенты). Бот отвечает в рабочий чат, где все свои; наружу не выносить. Персональные оценки менеджеров - только после гейта ФЕНИКСА и решения Ивана.
- Задержка данных: бот отвечает по последнему снимку; в ответе показывать время снимка, чтобы не спутать со «сейчас».
