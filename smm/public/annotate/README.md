# Модуль комментирования (annotate)

Комментарии к выделенным областям на любой внутренней странице - как в Figma /
Google Drive. Выделение участка, имя автора (спрашивается один раз), дата/время,
ответы деревом, цвет на каждого автора, общий доступ для всех участников.

## Встройка одной строкой

Вставьте перед `</body>` на любой странице:

```html
<script src="https://oliverjone01-dev.github.io/t1/smm/annotate/annotate-init.js"
        data-page="ИМЯ-ПРОЕКТА" data-sections=".slide" defer></script>
```

Это всё. Загрузчик подтянет ядро и подключит общий бэкенд.

> Внутри репозитория можно ссылаться и относительным путём до загрузчика
> (напр. `../annotate/annotate-init.js`) - он сам найдёт ядро рядом с собой,
> поэтому работает и в превью, и на бою.

## Параметры (data-атрибуты)

| Атрибут | Зачем | По умолчанию |
|---|---|---|
| `data-page` | Уникальный ключ страницы. Разные значения = разные ветки комментариев. Одна база на все проекты, не смешиваются. | путь страницы |
| `data-sections` | CSS-селектор блоков, к которым привязываются выделения. | `[data-annotate-section]` |
| `data-storage` | `local` = комментарии только в этом браузере. Не задавать = общее облако (Supabase). | общее облако |
| `data-poll` | Период подтягивания чужих комментариев, мс. | `6000` |

Если страница не дек со `.slide`, пометьте комментируемые блоки:

```html
<section data-annotate-section> ... </section>
```

Или оберните весь контент в один `<div data-annotate-section>` - тогда комментировать
можно всю страницу как полотно. Координаты хранятся в процентах от этого блока.

## Доработка

- Ядро - `annotate.js` (вся логика и стили инжектятся им). Правьте его.
- После правки поднимите `CORE_VERSION` в `annotate-init.js` - кэш сбросится у всех
  проектов сразу, ничего больше менять не нужно.
- Цвета авторов - массив `PALETTE` в `annotate.js`. Размеры/вид - в блоке `injectCSS`.

## Файлы

- `annotate-init.js` - загрузчик (Supabase-конфиг + дефолты, встройка одной строкой).
- `annotate.js` - ядро (логика + стили).
- `README.md` - этот файл.

## Бэкенд (Supabase)

Одна таблица на все проекты, настраивается один раз (SQL - внизу `annotate.js`).
Комментарии разделяются по `page_key`. anon-ключ публичный по дизайну, доступ
ограничивают политики RLS. Для внутреннего инструмента политики «любой по ссылке
может комментировать» подходят; при необходимости ужесточаются в Supabase.
