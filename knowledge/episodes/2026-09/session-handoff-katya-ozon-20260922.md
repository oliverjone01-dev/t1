## 2. Ключевые технические факты и грабли (обязательно к прочтению)

- **`build-katya.ts` — ОДИН билдер на OZON и Маркет.** Разделение через `IS_OZON` (из `src/paths.ts`, `PLATFORM=ozon|ym`). Сборка OZON заглушена: в начале `if (IS_OZON) { …exit }`. Чтобы собрать OZON-страницы вручную: временно вписать `if (IS_OZON && !process.env.KATYA_FORCE_OZON)`, запустить `KATYA_FORCE_OZON=1 npx tsx src/scripts/build-katya.ts`, **вернуть guard назад**. Задеплоенные OZON-страницы = закоммиченные `public/katya*.html` (deploy-pages.yml копирует `public/`). `npm run katya` OZON пропускает (guard) — деплой берёт закоммиченный HTML.
- **Грабля template literal:** страничный JS живёт внутри backtick-шаблона `pageJs`. Внутри него `\d`/`\w`/`\s` в регулярках СХЛОПЫВАЮТСЯ (теряют бэкслеш). Использовать `[0-9]`, `[A-Za-z]` и т.п. Проверять на СОБРАННОМ HTML, не только в Node.
- **Страница «Деньги» = `katya-money.html`** (не `katya.html`). Функции: `renderSkuAnalytics` (таблица по артикулам, `#skuan-t`), `renderOrdersAnalytics` (по заказам, `#ordan-t`, возвращает `ordGrand`), `renderCityLogistics` (логистика по городам, `#logi-t`), `renderAccountFees` (Общие расходы, `#acct`), `periodTotals`/`renderPlan` (План на месяц).
- **Водопад P&L (OZON)** строится из `ordGrand` (ИТОГО свода по заказам), НЕ из `periodTotals`. `periodTotals` кормит блок «План на месяц» (его «факт Чистая прибыль»). За закрытый месяц план≈таблица (доли %), за открытый — план ниже на висящие заказы (`amtReal` vs `amt`, подписано в карточке).
- **Источники доставки/сборов по SKU/заказу** (эмитятся в pageJs как `AN_*`):
  - `AN_ACQSKU`/`AN_STOSKU` — эквайринг/хранение по SKU/день из `data/acq_sku_daily.ndjson` (accrual/by-day API `/v1/finance/accrual/by-day`, секция `item_fees`). Хранение = метка `storage` (размещение/хранение). Всё через `accrual-buckets.ts`.
  - `AN_SHIPSKU`/`AN_DINCSKU` — наша доставка (расход) / доход покупателя по SKU из `delivery_orders` (по постингу, все месяцы). Источник — та же ведомость перевозчика, парсер `tools/orders/build_order_joins.py`.
  - `AN_DELIV`/`AN_DELIV_INC` — ведомость по offer/день (`delivery_sku_daily.ndjson`, `tools/delivery/build_delivery_sku_daily.py`), ТОЛЬКО закрытые месяцы (текущий парсер пропускает). Используется в «Общих» residual.
  - `AN_DELIV_CITYPL` — P&L перевозки по городу/день (`delivery_city_daily.ndjson`, тот же парсер `build_delivery_sku_daily.py`, добавлен в этой линии работ). Город есть только у нашей перевозки (ведомость), закрытые месяцы.
  - `orders_daily.ndjson` (per-order): `partner` (услуги партнёров), `delivery` (логистика OZON), `scheme` (FBO/FBS/rFBS), revenue, payout. Строится `src/scripts/ozon/orders-daily.ts`.
- **`accrual-buckets.ts`:** `RfbsServiceFee` теперь в бакете `other` (не `partner`) — это сбор OZON за схему rFBS, не партнёрская доставка. `RfbsDomesticDelivery`+`RfbsDomesticAgentFee` = `partner`.
- **Сверка доставки** («Логистика по городам»): каждый доставленный заказ едет одним из трёх — FBO/FBS = логистика OZON; rFBS+ведомость = наша перевозка; rFBS без ведомости = услуги партнёра. Проверено: **0 заказов без способа** во всех периодах. Классификация по СХЕМЕ (не по значению partner), поэтому перенос 20₽ её не ломает.
- **OZON API из сессии недоступен** (нет ключей). Пересборка `orders_daily`/снимков идёт ночным воркфлоу `ozon-snapshots.yml`. Ручные правки снимков (напр. перенос RfbsServiceFee в `orders_daily.ndjson`) — временны до следующего синка; поэтому фикс делается И в источнике (`accrual-buckets.ts`), И в текущем снимке.
- **§15 Definition of Done:** любое числовое изменение сверять с эталоном (отчёты OZON), проверять на 3 типах периода (закрытый/частичный/открытый), показывать покрытие. Smoke ловит JS-ошибки, НЕ неверные числа.
- **ФЕНИКС (Step 12.5):** критические числовые изменения дашборда прогонять через `feniks` subagent. В этой линии он дал по «Деньгам» финально `go 7.75` (после итераций 6.85→7.25→7.75).

**Общие файлы (риск конфликта):**

Общий блок `<style>` и `pageJs` — добавлять НОВЫЕ правила, не переписывать существующие строки Маркета.
- `src/scripts/katya-nav.ts` (`KPAGES`) — ОБЩИЙ список вкладок для ОБЕИХ площадок. Новая вкладка «Тесты» должна быть **OZON-only** (как «Реакция»: в шапке фильтр `key !== "reakciya" || IS_OZON`; на Маркете её нет, ссылка не ведёт в 404). При добавлении «Тесты» — сделать такой же фильтр.
- `traces/2026-09-22/agents.jsonl` — append-only, конфликтует всегда; резолв union-дедупом (см. ниже).
- Сгенерированные артефакты `public/*.html`, `data/sku_cogs.json` — конфликтуют; резолв ПЕРЕСБОРКОЙ (не руками): пересобрать OZON-страницы (force-build) поверх смерженного источника.

**Порядок резолва конфликта при мерже main:**
1. `git merge origin/main` → конфликты обычно только в `traces/*.jsonl` (+ иногда generated).
2. Trace: оставить объединение уникальных строк (union-дедуп), `git add`.
3. Проверить, что мои OZON-правки в `build-katya.ts` целы (grep по маркерам) и нет `<<<<<<<`.
4. Если main обновил данные (снимки) — ПЕРЕСОБРАТЬ OZON-страницы (force-build), затем `git add -A`, `git commit --no-edit`.
5. Никогда не форс-пушить чужую ветку; свою (`claude/focused-davinci-tKJCt`) после мержа PR перезапускать от `origin/main`.

**Деплой:** `deploy-pages.yml` копирует `analytics-mvp/public/.` в `_site/`. OZON-страницы (`katya*.html`) и Market-страницы (`market/*`) сосуществуют. Дать деплою ~2-3 мин после мержа, обновлять через Ctrl+F5.
