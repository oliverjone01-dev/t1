# Подвохи API и probe-чеклист

Собрано 29.09.2026 из спек вендоров (OpenAPI Маркета, спека WB из SDK), зеркал документации Ozon и Bitrix24, открытых клиентов и справки Директа. Сокращения источников и ссылки: `sources.md`. [ГИПОТЕЗА] = не проверено по первоисточнику. [вторичный источник] = взято из стороннего клиента (ozon-mcp-server) или его issue, в официальной документации не подтверждено: перед использованием проверь probe. Перед использованием строки старше 3 месяцев перепроверь спеку: площадки меняют API почти ежемесячно.

## Probe (до кода к новому эндпоинту, полю или отчёту)


1. **Спека.** Скачать спеку из первоисточника, записать дату или коммит. Искать `deprecated`, `shutdown-date`, «будет отключен» (рекомендую diff спеки в CI: у ЯМ коммиты почти ежедневные).
2. **Семантика.** Взять 3 известные сущности из кабинета (заказ, возврат, услугу) и найти их в ответе. Цель: убедиться, что эндпоинт отдаёт то, что нужно.
3. **Лимиты.** Выяснить максимальный период (запрос на 31/32/92 дня), размер страницы, rate-лимит и какой код его сигналит (429/420, есть ли Retry-After). Проверить параллельность: заказать 2 отчёта одновременно.
4. **Пагинация.** Проверить условие конца (`page_count`, `has_next`, `last_id`, 204/`[]`). Проверить, что ключ уникален и дублей между страницами нет. Число записей сверить с `row_count` или итогом.
5. **Какая дата фильтра.** Заказ, отгрузка, начисление или платёж? В какой TZ вход и выход? Тест на операции в 23:30 МСК.
6. **Единицы и знаки.** Копейки или рубли, строка или число, знак у списаний, ACCRUAL/DEDUCTION.
7. **Словари кодов.** Тянуть их вживую, названия EN->RU брать из API. Незнакомый код должен давать fail, а не «прочее».
8. **Пусто против нуля.** Запросить день с активностью и день без неё. Различать 204, `[]`, `NO_DATA` и отсутствующее поле. Дефолт 0 запрещён.
9. **Окно хранения.** 32 дня, 30 дней, «с 29.01.2024». Снимки писать append-only, не перезаписывать файл более коротким диапазоном.
10. **Доступ.** Premium-метод? Scope токена (например, WB «Финансы», ЯМ `finance-and-accounting`)?
11. **Эталон.** Один закрытый месяц сверить с закрывающим документом до кода агрегатов.
12. **Canary после релиза.** Ежедневный вызов с ожидаемым непустым результатом. Ошибка роняет job (fail-closed).


Итог probe сохраняется в `knowledge/semantic/probes/<source>.md`: дата, запрос, форма ответа (ключи и типы без значений), найденные эталонные сущности, лимиты, выводы.

## Безопасные изменения в рекламном кабинете


1. По умолчанию только чтение. Изменяющие вызовы блокируются ещё до отправки в сеть (S21, YD_READONLY). (рекомендую)
2. Сначала проверять в песочнице: у неё отдельный хост, есть is_sandbox и YD_SANDBOX (S20, S21). Что песочница повторяет боевой кабинет, это [ГИПОТЕЗА].
3. Своего dry-run в API нет, делаем его в обёртке. Превью возвращает тело запроса, ничего не отправляя (S22), а confirm=true нужен для реальной отправки (S21). Учесть: adimages_add даже в dry_run скачивает картинку (S22).
4. Держать белый список логинов для Client-Login (S21, YD_ALLOWED_LOGINS).
5. Разбирать ошибки и предупреждения по каждому элементу. Если применилась только часть, это не «ок» (S21).
6. Ставки передавать в микроединицах и перед отправкой проверять диапазон (S22).
7. Следить за баллами в заголовке Units. При ошибке 152 изменения вслепую не повторять (S20, S21).
8. Вести журнал (рекомендую): снимок состояния через get до изменения, diff после, кто, когда, ID апрува. Начинать с одного объекта, потом партиями.
9. Коммандер работает офлайн: данные уходят на сервер только по команде, и перед этим можно сделать ревью (docs/alternative-interfaces/direct-commander.md в зеркале). Формат его CSV я не проверял [ГИПОТЕЗА].


## Новые вероятные риски CRM и рекламы


- С 2026 года НДС 22%, поэтому ряды расходов с НДС за 2025 и 2026 годы напрямую не сравнить (S16).
- crm.deal.list больше не развивают. При переходе на crm.item.list поменяются имена пользовательских полей (camelCase) и фильтры по булевым полям: там нужны 1/0 вместо Y/N (S1, S5).
- Если в офлайн-конверсиях нет времени, Метрика ставит 23:59:59 в поясе счётчика, и день может съехать (S18).
- Если временной таргетинг настроен не по Москве, статистика показывает показы в дни, когда их быть не должно (S17).
- В одном дашборде могут смешаться автоматическая атрибуция (в Мастере кампаний её не выключить) и LSC (S15).
- Статистику Директа пересчитывают задним числом, поэтому сверка с актом за тот же месяц расходится законно (S14).
- Для Wordstat OAuth-токены, выпущенные после 01.06.2026, Yandex Cloud больше не меняет на IAM, нужен ключ сервисного аккаунта (S21).
- Урезанные права вебхука тихо уменьшают выборку (S5).
