# Telegram → отдельная вкладка новых задач

**Бот @gg_om_tasks_bot добавлен в группу; отдельная вкладка создана. Облачный обработчик требует активации.**

Доска читает обе вкладки и сохраняет правку в исходную вкладку задачи. Бот дописывает только вкладку Telegram. При недоступности любой вкладки чтение останавливается целиком, чтобы частичный ответ не удалил карточки. Обновляйте также существующий фоновый Apps Script из `background/dist`, прежде чем включать командный режим Firestore.
Группа: `-5372356223`. Таблица: `1qh-pi5I76k8ssUc6DxjeytFDrAta1N4ZdmVjaUFCUYY`, вкладка новых задач `1478506234` (основная вкладка `1102202601` сохраняется).

Отдельный закрытый Google Apps Script раз в минуту забирает новые сообщения выделенного Telegram-бота. Явное поручение становится новой строкой вкладки «Новые задачи · Telegram», затем попадает на доску через её обычную синхронизацию. Браузер и компьютер владельца могут быть выключены. Firestore, платная модель распознавания, сервер OpenAI и платный хостинг не нужны. Это работа в бесплатных квотах Google, а не обход лимитов: сроки выполнения триггера и непрерывность не гарантированы.

## Что распознаётся

- «Катя, подготовь каталог до 15.11.2026» → задача, Екатерина Машкова, срок 15 ноября.
- «Нужно обновить баннер завтра», «Можешь подготовить макет?», «Проверьте каталог» → задача без необходимости команды.
- «Не надо отправлять каталог», «Каталог уже готов», цитата, предположение или обычное обсуждение → пропуск.
- Неизвестное/неоднозначное имя не угадывается. Соответствия можно задать через `TELEGRAM_OWNER_MAP`.
- Сегодня/завтра вычисляются относительно времени сообщения по Москве; поддерживается «до ДД.ММ.ГГГГ».
- Одно сообщение — одна карточка. Полный исходный текст сохраняется в строке, заголовок ограничен 300 символами.
- Голосовые, изображения без подписи, пересланные сообщения и изменения старых сообщений не обрабатываются. Новая реплика без поручения не меняет старую задачу.
- Это консервативный языковой разбор, **не ИИ, понимающий весь диалог**. Неявные задачи, контекст ответов и сложные формулировки могут быть пропущены. Для гарантированного добавления текстового поручения есть необязательная команда `/task текст` или `#задача текст`.

Новая задача получает статус «В ожидании», попадает во «Входящие». Записываются постановщик, текст-основание, время и идентификатор сообщения. Для обычной закрытой группы Telegram нет универсальной прямой ссылки на сообщение — сохраняются номер группы и сообщения. Для публичной группы / супергруппы формируется ссылка, если Telegram предоставляет необходимые реквизиты.

## Установка

1. Создайте **отдельного** бота через [@BotFather](https://t.me/BotFather), добавьте в указанную группу. Через `/setprivacy` отключите Privacy Mode; при необходимости удалите и повторно добавьте бота в группу. Бот должен получать обычные сообщения, не только команды. Не подключайте имеющегося бота РОПа: у него другой обработчик.
2. Создайте **закрытый отдельный** проект на [script.google.com](https://script.google.com/), под Google-аккаунтом с правом редактирования таблицы. Не привязывайте проект к общедоступному файлу и не делитесь доступом к скрипту: редакторы скрипта смогут прочитать токен.
3. Соберите `npm run build:telegram` из `task-canvas`. Перенесите `telegram/dist/Code.gs` в `Code.gs`, а `telegram/dist/appsscript.json` — в манифест проекта (включить отображение манифеста в настройках).
4. В **Project Settings → Script properties** добавьте:

   | Свойство | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | Токен BotFather; не публиковать в коде или чате |
   | `TELEGRAM_BOT_USERNAME` | Имя созданного бота, с @ или без |
   | `TELEGRAM_OWNER_MAP` | Необязательно: JSON, например `{"катя":"Екатерина Машкова","@ivan":"Иван Раюшкин"}` |

   GitHub Actions secret `TELEGRAM_TASK_BOT_TOKEN` может хранить резервную копию, но Apps Script **не читает GitHub secrets**: для работы токен нужен именно в закрытых Script Properties.

5. Выполните `prepareTelegramIntake`, предоставьте Google разрешения. Манифест запрашивает доступ к Google Таблицам аккаунта; код жёстко ограничен указанным ID и проверяет основную вкладку и отдельную вкладку Telegram. Для стандартного собственного GCP-проекта дополнительно включите Sheets API; для стандартного управляемого Apps Script проекта сервис указан в манифесте. Проверка читает таблицу и реквизиты бота; задачи не добавляет и webhook не меняет.
6. Выполните `startTelegramIntake`. Начало отслеживания фиксируется при первом запуске, старая переписка не импортируется. Создаётся один минутный триггер. Не запускайте второй обработчик `getUpdates` для этого бота и не устанавливайте ему webhook.
7. Приёмка на реальных сервисах: отправьте в группу одно явное тестовое поручение с узнаваемым текстом. Убедитесь, что после работы триггера появилась **одна** строка и одна карточка; повторный ручной `pollTelegramTasks` не создаёт дубль. Откройте доску без входа, проверьте отображение. После проверки тестовую задачу можно архивировать на доске. До этих шагов интеграция не считается запущенной.

Скрипт сам не отправляет сообщений в группу. Ничего разворачивать как Web App не требуется.

## Надёжность и обслуживание

- `checkTelegramIntake` показывает включение, последний успешный опрос, последнюю ошибку и незавершённую запись. Результат виден в журнале выполнения. Включите штатные Google-уведомления об ошибках триггера; обычные успешные опросы не требуют внимания.
- `stopTelegramIntake` отключает триггер, сохраняя курсор. Повторный `startTelegramIntake` продолжает с него. Telegram хранит недоставленные обновления не более 24 часов; простой дольше суток может привести к пропускам. Это не средство загрузки истории группы.
- `getUpdates` вызывается с `timeout:0`, только 50 обновлений за опрос; лист читается лишь при обнаружении задачи или незавершённой записи. Бюджет обработки ограничен 45 секундами между сообщениями; один сетевой запрос всё равно может занять больше времени.
- Один Script Lock исключает перекрывающиеся запуски внутри одного проекта. Только группа `-5372356223` может добавить строку. Если Telegram преобразует её в супергруппу, ID изменится: потребуется проверенное обновление настройки в коде.
- ID карточки `tg-<chat_id>-<message_id>` позволяет узнавать повторное обновление даже после перезапуска. Существующие строки, включая архивные, никогда не перезаписываются ботом. Telegram-текст записывается как строка, а не формула.
- До отправки Google сохраняется незавершённое поручение в Script Properties частями. Курсор продвигается только после безопасного пропуска или подтверждения записи.
- При потере ответа Google следующий опрос сверяет ID в таблице. Если строка уже есть — работа продолжается. Если её нет — `WRITE_UNCERTAIN`, автоматические добавления останавливаются, поручение остаётся в очереди. Это намеренная остановка вместо риска дубля.
- Восстановление: выполните `checkTelegramIntake`, дождитесь завершения всех запросов, найдите ID в колонке S. Если строки нет, **явно подтвердите повтор**: внесите точный ID в `TELEGRAM_RETRY_PENDING_ID` и выполните `retryPendingTelegramTask`. Функция ещё раз проверит лист и добавит отсутствующую строку из сохранённой очереди. Не очищайте `PENDING_*` вручную.
- При ошибке доступа, квоте Google или конфликте другого потребителя Telegram обработка не подтверждается. После устранения причины опрос продолжится. Не меняйте токен на другого бота без `prepareTelegramIntake` и `startTelegramIntake`.

## Проверка исходников

`npm test` проверяет разбор, дедупликацию, буквальные значения ячеек, сбой записи и восстановление; `npm run build:telegram` собирает автономный скрипт. Тесты не вызывают реальные Telegram/Google API. Облачная авторизация, членство бота в группе, реальная запись и срабатывание триггера требуют отдельной проверки после установки.

Документация: [Telegram FAQ](https://core.telegram.org/bots/faq), [getUpdates](https://core.telegram.org/bots/api#getupdates), [триггеры Apps Script](https://developers.google.com/apps-script/guides/triggers/installable), [квоты Google](https://developers.google.com/apps-script/guides/services/quotas).
