# Свод по дате заказа: что берём из API и как он сошёлся с кабинетом

Сверка за **июль 2026, кабинет мебели (businessId 74986385)** против свода Кати
(`Свод по заказам_ июль 2026_v4.xlsx`, лист «Свод по товарам», строка ИТОГО) и против
закрывающих документов кабинета. Базис свода: **период по дате оформления заказа**, в расчёт идут
только заказы со статусом `DELIVERED`, штуки - доставленные минус возвращённые.

## 1. Источники: что именно берётся из API

| Колонка свода | Метод API | Поле |
|---|---|---|
| Артикул, название | `POST /campaigns/{id}/stats/orders` | `items[].shopSku`, `items[].offerName` |
| Шт. доставлено / возвращено | там же | `items[].count`, `items[].returns` |
| (+) Цена продажи | там же | `items[].prices[]` (все типы), × count |
| (+) Доставка с покупателя | там же | строка `DELIVERY` в `items[]` (модель DBS) |
| (−) Скидка Маркета покупателю | там же | `prices[]` тип `MARKETPLACE` |
| (−) Баллы Плюса | там же | `prices[]` типы `CASHBACK`, `SPASIBO` |
| (=) Платёж покупателя | там же | `prices[]` тип `BUYER` + доставка |
| (−) Возвраты покупателю | там же | `payments[]` тип `REFUND` |
| (+) Баллы начислены Маркетом | там же | `subsidies[]` |
| Услуги по 12 статьям | `POST /reports/united-netting/generate` (в кабинете - «Отчёт по платежам») | `OFFER_OR_SERVICE_NAME`, `TRANSACTION_SUM`, `TRANSACTION_TYPE`, `ORDER_ID` |
| Себестоимость | лист СС (`fixtures/cogs_prod_sku.csv`), не API | по ключу SKU |

Ключ связи услуг с товаром - `ORDER_ID` реестра. Внутри заказа услуга ложится на позицию по
`SHOP_SKU`, а где реестр SKU не называет - пропорционально начислениям позиций.

## 2. Чем оплачена услуга: правило и его проверка

Услуги Маркета оплачиваются деньгами и баллами. Разделение решает поле `TRANSACTION_SOURCE`, но в
уже собранном снимке его нет (колонка добавлена позже, реестр пересобирается). Пока его нет,
разделение идёт по `TRANSACTION_TYPE`, и это не догадка, а проверенное правило:

| Тип проводки | Что значит | Наш июль, мебель | Кабинет |
|---|---|---|---|
| `Удержание` | списано **деньгами** | 557 521 ₽ | 557 250,20 ₽ («Стоимость оказанных услуг по актам») → **+0,05%** |
| `Списание` | оплачено **баллами** | 2 326 514 ₽ | 2 350 590,89 ₽ (скидка за совместные акции + оплата бонусами) → **−1,0%** |
| `Возврат списания` | сторно услуги, оплаченной баллами | вычитается | |

Знак проводки берётся как есть (`−amount`), не по модулю: модуль превращал сторно в ещё один сбор и
завышал статью вдвое от суммы сторно.

Строка «Программа лояльности и отзывы» в этой таблице - только **денежная** половина статьи. Баллами по ней за июль проходит −12 447 ₽: проводки «Возврат списания» есть (34 строки, +375 288 ₽ по снимку), а парных «Списание» нет ни одной, поэтому статья выводится в UI с отрицательной стоимостью. Это открытый вопрос к реестру, а не ошибка счёта: итог «Услуги всего» от него не зависит.

**Услуги баллами.** Свод даёт 1 693 172 ₽ и сам помечает пробел: «услуги по июльским заказам в
августовском акте - нет данных». На том же базисе (только июльский акт) у нас 1 680 614 ₽, то есть
**−0,74%**. Августовский акт у нас уже собран и добавляет ещё 1 040 418 ₽ услуг по тем же июльским
заказам, поэтому итог свода - 2 721 033 ₽. Это не расхождение, а закрытый пробел.

**Классификация.** Штрафы «Отгрузка или доставка не вовремя» (12 022 ₽) у нас - отдельная статья, в
своде Кати они попали в «Размещение» (отсюда 192 301 против 204 195 при совпадающем итоге).

## 4. Что не сошлось и почему

| Что | Размер | Причина |
|---|---|---|
| Штук доставлено | +1 шт | Один заказ считает позиции иначе, чем выгрузка кабинета. |
| Цена продажи, скидка Маркета, платёж, выручка | +0,35..0,44% | Следствие той же лишней штуки: все четыре смещены в одну сторону и в одном порядке. |
| Сборы акта по заказам вне свода | 19 845 ₽ по 21 заказу (июль, мебель); 4 209 305 ₽ по снимку | Свод берёт только статус `DELIVERED`. Сборы по возвратам, отменам в доставке и по заказам вне выгрузки в блок не идут, но показаны отдельной строкой в отчёте о пробелах. |
| Баллы, осевшие на строке доставки | 169 618 ₽ (июль, мебель) | Субсидия заказа разносится по позициям пропорционально их стоимости, и доля строки доставки в свод не попадает. Без этого сумма баллов уходит на +6,8% от кабинета вместо +0,34%, то есть строка доставки субсидии действительно не несёт. Сумма раскрыта в блоке. |

**Общие расходы кабинета: -55% и чего не хватает.** В отчёте по платежам за июль ровно 6 строк без
номера заказа на 36 875 ₽, все типа «Удержание», оплаченных баллами среди них нет. У Кати в той же
строке 81 495 ₽: туда входят полки (1 657 ₽ деньгами + 15 051 ₽ баллами), подписки (16 990 ₽),
баннеры и буст за показы. Эти статьи живут в акте по стоимости услуг
(`united-marketplace-services`), который мы не собираем. Это не ошибка разнесения, а
неподключённый отчёт.

**Баллы начислены Маркетом: +2,7% и почему это не подгоняется.** Субсидия приходит на заказ целиком,
разносить её по позициям приходится нам. Три базы дают три ответа по июлю/мебели: стоимость позиций
(цена × штуки) 2 706 477 ₽ (+2,7%), проданная стоимость (`accruals`, возвращённое баллов не несёт)
2 574 878 ₽ (−2,3%), прежнее равнодолевое разнесение 2 644 342 ₽ (+0,34%). Из наших данных не
определяется, какая верна: расхождение упирается в два заказа с полным возвратом на 138 928 ₽
субсидии. Взята база «цена × штуки» - та же, что у доставки, возвратов и услуг: одна база на весь
блок, её нельзя подобрать под желаемый итог. Вопрос открыт на ДАТУ.

**Что было исправлено после аудита ФЕНИКСА (два круга, verdict return 6.0 и 6.65/10).** Первый круг: расхождение по доставке в −9 000 ₽ было объявлено здесь внешним («источник в выгрузке
кабинета»). Это неверно, причина была в нашем разборе. Цены в `stats/orders` приходят **за штуку**, а
свод складывал их без умножения на `count`: 576 279 ₽ недосчёта выручки по снимку, у SKU `GGR-10-1`
переворачивался знак маржи. Доставка вдобавок бралась по `accruals`, которые у полностью
возвращённой позиции равны нулю.

Второй круг нашёл ещё четыре дефекта того же класса:

1. **Доставка за счёт Маркета показывалась платежом покупателя.** `price` строки доставки включает
   тип `MARKETPLACE`: 2 599 ₽ по снимку (заказы 59225193154 и 56864253122). Теперь берётся только
   доля покупателя, доля Маркета уходит в «Скидку Маркета», как у товарной строки.
2. **Гейт тождества платежей был настроен под известный дефект:** считал общую сумму с допуском
   0,1% от неё (28 090 ₽) и молчал. Теперь считает **попарно** по (кабинет, месяц) с допуском 0,1%
   пары. Сейчас сходится **по всем 14 парам ровно в ноль**.
3. **Маржа считалась на смешанном базисе:** числитель с баллами, знаменатель без. 14 строк снимка
   показывали маржу выше 100%, максимум 885 389%. Теперь база одна (деньги + баллы), строк выше
   100% ноль.
4. **Возвраты разносились по `accruals`** и уезжали с возвращённого SKU на соседний (заказ
   58875910850: весь −11 066 ₽ садился на GGT-12-2 вместо GGR-11-4). Теперь возврат разносится по
   стоимости **возвращённых** штук; свод пересобирает разнесение сам и не ждёт пересбора выгрузки.

После исправлений доставка с покупателя, баллы Плюса, возвраты и заказы сходятся с кабинетом в ноль.

## 5. Чего свод не делает намеренно

- **Не берёт выручку по цене продажи.** Цена продажи включает скидку, которую платил Маркет, а не
  покупатель; расходы при этом попадали в учёт уже за вычетом баллов. Обе половины искажались в одну
  сторону. Выручка здесь - платёж покупателя плюс доставка минус возвраты.
- **Не смешивает базисы.** Остальные блоки страницы «Деньги» живут по дате доставки и по дате
  проводки реестра. Числа там законно другие: это разные вопросы («когда кабинет списал» против
  «на какие продажи легло»).
- **Не прячет пробелы.** Месяц, у которого ещё нет закрытого акта за следующий месяц, помечается
  «месяц не добран»; SKU без себестоимости помечается бейджем, и его выручка не идёт в покрытие.

## 6. Definition of Done (CLAUDE.md §15)

1. **Сверка с эталоном** - раздел 3: услуги деньгами +0,01% к акту; заказы, возвраты, доставка с
   покупателя и баллы Плюса сходятся в ноль; услуги баллами −0,74% на сопоставимом базисе.
   Дополнительное тождество внутри API, проверяемое на каждом прогоне `ym:derive`:
   Σ(платёж покупателя по своду) = Σ `paid_by_type.PAYMENT` по тем же заказам, расхождение
   2 599 ₽ на 28 093 190 ₽ (0,009%, округление построчного `r2`). Нарушение печатает
   `::warning::` - это гейт против повторения дефекта с ценой за штуку.
2. **Три типа периода** - закрытый месяц (июль 2026: `svc_settled=true`), незакрытый месяц
   (август 2026: акт за сентябрь ещё не закрыт, помечен), текущий месяц (сентябрь 2026: помечен).
   Часть месяца свод не поддерживает намеренно: услуги приходят месячным актом, дробить его нечем.
3. **Отчёт о покрытии** - в дашборде: заказы без реестра, сборы акта по заказам вне свода, баллы
   на строке доставки, месяцы актов, покрытие себестоимостью (июль, мебель - 86,2% выручки),
   бейдж «нет С\С» у затронутых строк. Разложение сборов реестра сходится до рубля:
   25 252 068 (в своде) + 192 793 (общие расходы) + 4 209 305 (вне свода) = 29 654 166 ₽,
   нераскрытого остатка нет. KPI «Валовая прибыль» считается только по SKU с известной
   себестоимостью и подписан долей выручки, которую они покрывают.
