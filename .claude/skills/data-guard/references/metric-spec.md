# Спека метрики: 18 полей

Спека заполняется до кода и подписывается заказчиком. Шаблон: `templates/metric-spec.yaml`. Хранится в `knowledge/semantic/metrics/<id>.yaml`. Смена формулы = новая версия с новой подписью.

**Блокирующие поля** (без подтверждения код не пишется): 6, 8, 9, 10, 11, 18.

|---|---|---|---|---|

## Чеклист «время и даты»

1. Одно поле даты привязки на метрику, подписано заказчиком.
2. Время события, не выгрузки. Время загрузки хранится отдельно (`loaded_at`).
3. Интервалы `[с, по)`, «7 дней» проверено тестом: ровно 7 дат.
4. Europe/Moscow, конвертация один раз на входе. `toISOString().slice(0,10)` и `new Date('YYYY-MM-DD')` без пояса запрещены.
5. Для каждого API записано, в какой зоне оно отдаёт даты (Ozon transaction без TZ, postings в UTC; Директ всегда МСК; Bitrix24 по поясу сервера).
6. Неделя с понедельника, месяц календарный.
7. Когортные метрики: окно задано, незрелые когорты скрыты или помечены.
8. Возвраты и отмены привязаны к явной дате; заказчику объяснено, как меняется прошлое.
9. Неполный текущий день или период помечен и не сравнивается с полными.
10. Горизонт поздних данных задан, пересчёт только в этом окне.
11. Смена периода на странице меняет каждый блок (тест).
12. Сравнение «к прошлому периоду» на равной длине и том же дне недели.
