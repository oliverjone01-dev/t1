# Вкладка «Реакция»: откуда берутся данные

Остальные семь вкладок собираются из снимков `data/*.ndjson`, которые тянет ночной синк
`ozon-snapshots.yml`. У «Реакции» источник другой, и автоматизировать его нельзя.

Ей нужны: лог действий по рекламным кампаниям, история ставки оплаты за заказ по обоим
инструментам, предельные цены и акции по всем товарам, воронка по товарам. Кабинет отдаёт
это только под живой сессией продавца по кукам. Ни GitHub Actions, ни сервер туда не
достучатся, поэтому срез снимается вручную из активной вкладки Chrome.

## Цикл обновления

1. Снять кабинет по `КАБИНЕТ_эндпоинты.md`, положить выгрузки в `tools/reakciya/data-cabinet/`.
2. `python3 tools/reakciya/build.py` - пересчёт в `data/reakciya.json` (нужны python3, pandas, numpy).
3. `npm run reakciya` - сборка `public/katya-reakciya.html`. Или `npm run katya`, он теперь собирает и её.
4. `npm run smoke` - прогон контролов.

Шаг 1 требует человека с доступом в кабинет. Шаги 2-4 воспроизводимы.

## Почему сырые выгрузки не в git

`tools/reakciya/data-cabinet/` весит около 7 МБ и содержит аналитику по каждому SKU по дням.
Репозиторий публичный, GitHub Pages раздаёт всё, что в нём лежит. Срез `data/reakciya.json`
(133 КБ) уже агрегирован и попадает на страницу, которая и так публична, поэтому его храним,
а сырьё - нет. Если сырьё понадобится для пересчёта, его приносит тот, кто снимал кабинет.

## Что должно быть в data-cabinet

| файл | что внутри |
|---|---|
| `snapshot_514_ГГГГ-ММ-ДД.psv` | снимок цен и акций по всем товарам |
| `analytics_sku_daily_*.psv` | воронка по товарам по дням |
| `price_history.pkl` | история цен по товарам |
| `ads_campaign_history_*.psv` | лог действий по кампаниям |
| `cpo_history.psv` | история ставки оплаты за заказ, все товары |

Плюс в `data/`: `events_new.psv` (свежие события рекламы) и `cur_prices.psv` (текущие цены).
Точные имена файлов зашиты в начале `build.py`.
