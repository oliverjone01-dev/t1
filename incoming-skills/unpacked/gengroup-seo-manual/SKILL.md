# SEO Manual Pipeline - Ручной контент-конвейер GENGROUP

## Назначение

Производство SEO-контента уровня, который невозможно получить через автогенерацию. Каждая статья проходит полный цикл от семантики до Schema.org и готова к публикации на genglass.ru/blog/ (или сайте другого бренда) силами контент-менеджера.

**Ключевое отличие от gengroup-seo-pipeline:** этот скилл работает здесь и сейчас, в чате с Иваном/контент-маркетологом. Никаких внешних интеграций. Результат - файлы, которые забирают и публикуют.

---

## ПРИНЦИП #0: КЛИЕНТ-FIRST (надстройка над всем остальным)

**Статья для SEO-роботов = брак. Статья для клиента, которую индексируют роботы = цель.**

Каждая статья GENGROUP пишется от боли и задачи реального покупателя, НЕ от каталога продуктов. Прежде чем писать - ответь на 4 вопроса:

1. **Кто этот человек?** (пол, возраст, ситуация: ремонт/новостройка/офис)
2. **Что он уже знает?** (уровень техэкспертизы: 0 / базовый / продвинутый)
3. **Чего он боится?** (5-7 реальных страхов, не SEO-запросов)
4. **Что он хочет сделать после прочтения?** (позвонить / рассчитать / сравнить / успокоиться)

**Структура статьи строится от клиента:**
```
Задача клиента (что ты хочешь решить?)
  -> Решение (какой тип перегородки тебе подходит, с фото "до/после")
  -> Страхи (безопасно ли? нужно ли согласовывать? будет ли шумоизоляция?)
  -> Бюджет (3 сценария: эконом / оптимум / премиум - в рублях за ПРОЕКТ, не за м2)
  -> Процесс (как это происходит от звонка до "живёшь с перегородкой")
  -> Доказательства (кейсы, отзывы, фото реальных проектов)
  -> CTA (конкретный следующий шаг)
```

**НЕ так (продукто-центричная, запрещено):**
```
Виды стекла -> Типы профиля -> Механизмы -> Артикулы -> Цены -> FAQ
```

**Техническая глубина** остаётся обязательной (числа, мм, кг, ₽ - правило content-expert). Но подаётся через призму клиентского вопроса:
- НЕ: "Стационарная перегородка (алюминиевый профиль) - 7 000-12 000 руб/м2"
- А: "Хотите просто разделить кухню и гостиную? Стационарная секция от 15 000 руб, монтаж за 1 день без пыли. Профиль алюминиевый - легкий, не ржавеет, окраска в любой цвет RAL"

**Для каждого бренда GENGROUP - своя ЦА:**

| Бренд | Типичный покупатель | Техэкспертиза | Ключевой страх |
|---|---|---|---|
| GENGLASS (перегородки) | Женщина 28-45, ремонт квартиры/студии | ~0 | "Разобьётся, дорого, сложно" |
| GENGLASS (столы) | Семья 30-45, обновление интерьера | ~0 | "Стекло непрактично, тяжёлый" |
| VALONTI | Пара 35-55, премиум ремонт | Низкая | "Оправдает ли цену?" |
| GENTERO | Офис-менеджер/дизайнер, B2B | Средняя | "Сроки, надёжность, бюджет" |
| GLASS-MEMORY | Семья в утрате, выбор памятника | ~0 | "Качество, долговечность, этичность" |

Этот принцип применяется ПЕРЕД всеми остальными правилами content-expert, humanizer-ru и других скиллов.

## ЭТАП 1: Сбор семантического ядра (Semantic Harvest)

### Вход
Иван или контент-маркетолог называет категорию: "перегородки лофт", "душевые", "столы обеденные" и т.д.

### Процесс

**1.1 Wordstat-данные через веб-поиск**
- Поиск: `wordstat.yandex.ru [категория]`, `[категория] купить частотность`
- Парсинг видимых данных из поисковой выдачи
- Фиксация: запрос, приблизительная частотность, тип интента

**1.2 Конкурентный анализ выдачи**
- Поиск: `[категория] site:miralls.ru`, `[категория] site:archpole.ru`, `[категория] site:loffi.ru`
- Фиксация: какие страницы ранжируются, по каким запросам, что в title/description
- Поиск: `[категория] site:genglass.ru` - что у нас уже есть (защита от каннибализации)

**1.3 Расширение семядра**
- Подсказки Яндекса: `[категория] + [a-я]` - автоподсказки
- Блок "Вместе с этим ищут" / "Похожие запросы" из выдачи
- Вопросы из "Люди спрашивают" (PAA-аналог Яндекса)
- Минимум 50 запросов на категорию, цель 150-300

**1.4 Классификация интентов**
Каждый запрос получает метку:
- **КОМ** - коммерческий ("купить", "цена", "заказать", "стоимость", "недорого")
- **ИНФ** - информационный ("как выбрать", "виды", "отличия", "размеры", "плюсы минусы")
- **НАВ** - навигационный ("genglass перегородки", конкретная модель)
- **ЛОК** - локальный ("перегородки москва", "перегородки в квартиру студию")

### Выход
Таблица (xlsx или в чате): запрос | частотность | интент | конкуренты в ТОП | есть ли у нас страница

## ЭТАП 2: Кластеризация и контент-план

### Процесс

**2.1 Группировка по search intent**
Объединять запросы, которые удовлетворяет ОДНА страница:
- "стеклянные перегородки для квартиры" + "межкомнатные перегородки из стекла" + "перегородки стекло купить" = один кластер
- "перегородка лофт или обычная" + "лофт перегородка отличия" = один кластер
- НЕ объединять: коммерческие и чисто информационные, если интент разный

**2.2 Определение типа статьи для кластера**
Из content-expert, 8 типов. Основные для SEO:
- Кластер с "как выбрать/виды/какой" → Type 1: Expert Guide
- Кластер с "топ/лучшие/рейтинг" → Type 2: Top-N Showcase
- Кластер с "vs/или/отличия/разница" → Type 5: Comparison
- Кластер с "что такое/почему/зачем" → Type 3: Technical Deep Dive
- Кластер с "вопросы/FAQ" → Type 7: FAQ Hub
- Кластер с "цена/стоимость/сколько стоит" → Type 8: Category Page SEO + калькулятор-линк

**2.3 Приоритизация**
Приоритет = (суммарная частотность кластера) × (коммерческий множитель) × (gap-множитель)
- Коммерческий множитель: КОМ = 3, ИНФ = 1, ЛОК = 2
- Gap-множитель: нет нашей страницы = 2, есть но вне ТОП-10 = 1.5, в ТОП-10 = 0.5

**2.4 Pillar-Satellite архитектура**
Для каждой категории выстроить:
```
PILLAR: "[Категория]: полный гайд от производителя" (Expert Guide, 3000-4000 слов)
├── SAT 1: Comparison ("X vs Y")
├── SAT 2: Top-N Showcase
├── SAT 3: Technical Deep Dive
├── SAT 4: FAQ Hub
└── SAT 5: Category SEO Page
```
Все сателлиты ссылаются на пиллар. Пиллар ссылается на все сателлиты.

### Выход
xlsx файл "Контент-план [категория]" со столбцами:
- ID кластера
- Кластер (название)
- Ключевые запросы (через запятую)
- Суммарная частотность
- Тип статьи (1-8)
- Приоритет (1-5)
- Pillar/Satellite
- Статус (новый/в работе/готово/опубликовано)
- Ответственный
- Дата публикации (план)

## ЭТАП 3: Генерация эталонной статьи (Content Forge Manual)

### Вход
Конкретный кластер из контент-плана. Загрузить ВСЕ 6 скиллов из таблицы оркестрации.

### Процесс

**3.1 Сбор фактуры**
Через gengroup-encyclopedia + project_knowledge_search:
- Характеристики продуктов категории (мм, кг, ₽, сроки)
- Производственный процесс (этапы, оборудование)
- Гарантийные условия
- Конкурентные преимущества
- Реальные кейсы / отзывы (если есть в базе)

**3.2 Генерация полного пакета**

Каждая статья = ОДИН документ (docx или md) с 6 блоками:

```
═══════════════════════════════════════════
БЛОК 1: META
═══════════════════════════════════════════
Title tag:        [до 60 символов]
Meta description: [140-160 символов]
H1:               [может отличаться от title]
Canonical URL:    genglass.ru/blog/[slug]/
Target keywords:  [список из кластера]

═══════════════════════════════════════════
БЛОК 2: ПОЛНЫЙ ТЕКСТ СТАТЬИ (HTML-ready)
═══════════════════════════════════════════
Разметка H2/H3/p/table/ul.
Inline CTA после каждого 3-го H2.
Товарные карточки GENGLASS (через cross-sell).
FAQ-блок (5-7 вопросов, Schema-ready).
Все числа из encyclopedia, не выдуманные.
Anti-Slop: humanizer-ru pass обязателен.
Brand: тон и стиль из gengroup-brand.

═══════════════════════════════════════════
БЛОК 3: ПРОМПТЫ ДЛЯ ИЛЛЮСТРАЦИЙ
═══════════════════════════════════════════
По 1 промпту на каждый H2-блок.
Стиль: лофт/минимализм/продуктовый (по brand).
Инструмент: Nano Banana Pro 2.
Размеры: 1200x800 (обложка), 800x600 (inline).
Кириллица НЕ генерируется в изображении -
добавляется постфактум в Figma/Canva.

═══════════════════════════════════════════
БЛОК 4: SCHEMA.ORG JSON-LD
═══════════════════════════════════════════
Article + FAQPage + Product (если релевантно).
BreadcrumbList.
Organization (GENGLASS).
Готовый код для вставки в <head>.

═══════════════════════════════════════════
БЛОК 5: GEO/AEO ЧЕК-ЛИСТ
═══════════════════════════════════════════
7 пунктов из gengroup-geo-aeo:
[ ] Entity Definition
[ ] FAQ-структура
[ ] Comparative Statements
[ ] Structured Data Hints
[ ] Citation-Worthy Statements
[ ] Source Attribution
[ ] Freshness Signals

═══════════════════════════════════════════
БЛОК 6: ПЕРЕЛИНКОВКА
═══════════════════════════════════════════
3-5 исходящих внутренних ссылок с anchor-текстами.
2-3 существующие страницы, которые должны
ссылаться НА ЭТУ статью (обратная перелинковка).
Pillar <-> Satellite связи.
```

**3.3 Humanizer pass**
Прогнать текст через gengroup-humanizer-ru:
- 30 паттернов AI-слопа
- Em dash sweep (заменить все "—" на "-")
- Добавить голос и характер
- Разбить монотонный ритм предложений

**3.4 Self-check перед отдачей**
Claude проверяет сам перед выдачей:
- [ ] Каждый H2 содержит минимум 3 конкретных числа?
- [ ] Нет ни одного запрещённого слова из Anti-Slop blocklist?
- [ ] Entity Definition в первых 2 предложениях?
- [ ] Inline CTA каждые 600-800 слов?
- [ ] FAQ - реальные вопросы, не выдуманные?
- [ ] Schema.org валидный JSON-LD?
- [ ] Нет em dash "—"?
- [ ] Перелинковка содержит конкретные URL genglass.ru?

## ЭТАП 4: Пакетная выдача

### Формат результата

**Для 1 статьи:** docx файл с 6 блоками + xlsx обновление контент-плана (статус = готово).

**Для пакета (3-5 статей):** каждая статья в отдельном docx + мастер-xlsx со всеми статусами + сводный чек-лист по GEO/AEO.

### Именование файлов
```
SEO_[бренд]_[slug]_[дата].docx
Пример: SEO_GENGLASS_kak-vybrat-peregorodku_2026-04-02.docx
```

## Быстрый старт (copy-paste)

Иван пишет:
> "Собери семядро и контент-план для категории [X], потом сгенери первую эталонную статью"

Claude:
1. Загружает этот скилл + encyclopedia
2. ЭТАП 1: собирает семядро через веб-поиск
3. ЭТАП 2: кластеризует, создаёт xlsx
4. ЭТАП 3: берёт приоритетный кластер, генерит статью с 6 блоками
5. Выдаёт xlsx + docx

Весь цикл на 1 категорию + 1 статью = 1-2 сообщения.
