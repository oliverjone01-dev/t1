# DECISIONS - GEO-monster v1.0

Решения автономной сборки: что / альтернативы / почему.

## D1. Стек: статический SPA без сборки вместо Vite+React+TS

**Альтернатива:** Vite + React + TypeScript (как в мастер-промте).
**Решение:** vanilla JS (hash-роутер, ~3 файла) в `public/`, без npm-сборки.
**Почему:** директива «используй готовое» сильнее предпочтения стека. В репо уже
работает конвейер деплоя статики (`deploy-pages.yml`: `public/` → `_site/seo/`), все
соседние продукты (smm, rop, prod) - самодостаточная статика. React-сборка добавила
бы npm-шаг в общий деплой и риск сломать чужие контуры. Функциональность модулей от
этого не пострадала; перф выигрывает (нет фреймворк-бандла, Lighthouse ≥90 проще).

## D2. Корень Pages не трогаем

**Мастер-промт:** index.html в корне с редиректом на ./seo/.
**Решение:** корень остаётся аналитикой OZON (боевой контур других команд), хаб живёт
в `/seo/`. Итоговый адрес совпадает с DoD: `…github.io/t1/seo/`.

## D3. Имена секретов: канон - уже существующие

`KEYSO_TOKEN` уже добавлен владельцем (10.07.2026) - оставлен каноном, `KEYSSO_API_KEY`
читается как fallback. Для Яндекса канон - `YM_TOKEN`/`YD_TOKEN` (короче), fallback -
`YANDEX_METRIKA_TOKEN`/`YANDEX_DIRECT_TOKEN` (имена из ветки yandex-direct-optimization).
Harvest принимает оба, SETUP.md документирует канон.

## D4. HUB_PASS через инжект при деплое

У статического сайта нет доступа к секретам, поэтому хэш пароля запечён в index.html
(дефолт genmonster2026), а деплой-шаг подменяет его sha256-хэшем из секрета `HUB_PASS`,
если тот задан. Сам пароль в репо не попадает никогда.

## D5. Расположение файлов: проект живёт в gg-seo-geo-monster/

README/SETUP/DECISIONS/BACKLOG, scripts/, data/, config/ - внутри папки проекта, не в
корне репо. Корень t1 - общий холдинг-репозиторий с чужими контурами (аналитика, SMM,
знания), захламлять его файлами одного проекта нельзя.

## D6. Схема keys.so - защитные экстракторы до первого живого 200

apidoc.keys.so закрыт из контейнера сетевой политикой (403 CONNECT). Пути отчётов и
имена полей взяты из референса keyso-mcp и публичных обзоров, парсинг ответа -
защитный (pick по синонимам ключей). Эндпоинты переопределяются env (`KEYSO_EP_*`)
без правки кода. Сверка на первом живом запуске harvest - в BACKLOG.

## D7. Демо-данные - генератор, не рукопись

`scripts/gen-demo.mjs`: детерминированный (seeded PRNG), правдоподобные ряды
(genglass ~314 ключей в топ-10, glass-memory ~37 - ниша уже), встроенные сигналы для
демонстрации модуля (просадка трафика GM, выпавшие ключи, рост miralls.ru). Схема
демо = схема живого harvest, UI не различает их кроме бейджа.

## D8. Метрика: цели (goals) отложены

Stat API отдаёт цели по goal_id, которых мы не знаем до доступа к счётчикам.
В снапшоте `goals: []`, подключение целей - BACKLOG. Конверсии не выдумываем.

## D9. Конкурент «promsteklo» не заведён

В мастер-промте домен помечен как «примерный». Сетевая политика контейнера не даёт
проверить его поиском. Выдумывать домен нельзя - записан в BACKLOG на проверку
владельцем/Семёном. gran-tech.ru и vpk-stone.ru заведены как заданы.

## D10. Compressed stages: P1 существовал до сборки

Harvest-контур (P1) частично существовал (keyso.mjs, wordstat.mjs, workflows) и уже
проходил ФЕНИКС-гейты в этой ветке (GO 8.3 и GO 8.0 по смежным приёмкам). Пересборки
не было - расширение до harvest.mjs (+Метрика, +Директ, +нормализация, +дельты).
ФЕНИКС-аудит итоговой сборки - один сквозной (P2-P5), результат ниже.

## D11. Image-промты: 3 модели с разной структурой

GPT - развёрнутая сцена; Nano Banana - серия с консистентностью и рендером кириллицы;
Grok - фотореализм. Брендовый стиль зашит константой (стекло, металл, лофт, тёплый
свет, без людей крупным планом). EN-промт + RU-подпись, 4 пресета форматов.

## D12. dtf для glass-memory - жёсткий стоп в генераторе

Не только пометка «не рекомендовано» на карточке: генератор M5 отказывается собирать
промт для этой пары и объясняет почему, предлагая vc (B2B дилерам) и dzen (деликатный
тон). Модуль обязан уметь отговаривать - реализовано буквально.

## D13. Схема keys.so сверена по живому прогону + openapi (закрывает D6/BACKLOG-1)

Первый живой harvest (#1, 10.07.2026) дал точную ошибку: мой выдуманный путь
`/report/simple/organic/keywords` не существует (HTTP 400). Реальная схема взята из
openapi-спеки референса keyso-mcp: фразы домена доступны через **групповой отчёт**
(`POST /report/group {domains[]} -> rid` -> опрос `state/<rid>` -> `organic/keywords/<rid>`),
конкуренты - `simple/organic/concurents` (опечатка в самом API), сводка -
`domain_dashboard` (подтверждён живым запросом). Бонус: в dashboard есть
`aiAnswersCnt` - упоминания сайта в ИИ-ответах Алисы - выведен в GEO-трекер (M3).
Незавершённый групповой отчёт добирается следующим прогоном (pending_rid в meta).

Попутно исправлено по фактам прогона: статусы источников копятся per-project
(второй проект больше не затирает первый - Метрика genglass показывала no-counter
из-за пустого счётчика glass-memory), LIVE-бейдж в Админке считается по ok/cached.
