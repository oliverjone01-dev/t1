# Yandex Direct - рабочая папка

Рабочее пространство по настройке и оптимизации Яндекс.Директ для брендов GENGROUP.
Ветка: `claude/yandex-direct-optimization-c96txb`.

## Что здесь лежит

### `skills/direct/` - skill аудита и оптимизации Директа (staged)

Vendored open-source skill для AI-агентов (Claude Code / Cursor), API Директа v5.

| Параметр | Значение |
|---|---|
| Источник | https://github.com/Silverov/yandex-direct-skill |
| Авторы | Nick Serebrov & Kobe |
| Лицензия | MIT (файл `skills/direct/LICENSE`) |
| Дата снимка | 2026-07-08 |
| Реализация | shell + curl + jq |

Возможности:
- `audit` - полный аудит аккаунта, 55 проверок (YD01-YD55), скоринг 0-100 и оценка A-F
- `campaigns` - список кампаний со статусами и метриками
- `create` - создание кампаний
- `keywords` - работа с ключами (добавление, пауза, ставки)
- `report` - отчёты (CTR, CPC, конверсии, расход)
- `optimize` - рекомендации по эффективности бюджета
- `budget` - анализ расхода и прогноз
- `negative` - минус-слова против слива бюджета

Веса категорий аудита: Конверсии/Метрика 25%, Слив бюджета 20%, Структура аккаунта 15%,
Ключи/качество 15%, Объявления/расширения 15%, Настройки/таргетинг 10%.

## Security review (проведён перед внесением)

- Скрипты обращаются только к официальным эндпоинтам: `api.direct.yandex.com/json/v5`
  и `/json/v5/reports`. Сторонних хостов нет.
- OAuth-токен читается локально из `~/.secrets/yandex-direct.json` и передаётся только
  в заголовке `Authorization: Bearer` к API Яндекса. Токен нигде не хардкодится и не
  уходит на сторону.
- Нет `eval`, нет `rm -rf`, нет исполнения удалённого контента.

## Активация (HITL-гейт, Protocol 6)

Skill внесён в staged-виде и НЕ подключён к живому ростеру `.claude/skills/`, потому что
он исполняет внешние API-вызовы с OAuth. Подключение - отдельное решение Ивана.

Когда будет решение активировать:

```bash
# 1. Подключить skill в живой ростер
cp -r yandex-direct/skills/direct ~/.claude/skills/direct   # или в .claude/skills/ репозитория

# 2. Настроить доступ к API Директа (получить OAuth-токен приложения)
mkdir -p ~/.secrets
cat > ~/.secrets/yandex-direct.json <<'JSON'
{ "oauth_token": "<OAUTH_TOKEN>", "client_login": "<логин-клиента>" }
JSON
chmod 600 ~/.secrets/yandex-direct.json

# 3. Проверить зависимости
which curl jq   # оба должны быть установлены
```

Токен получается через OAuth-приложение Яндекса с доступом к API Директа
(https://yandex.ru/dev/direct). Файл секретов держать вне git (уже вне репозитория,
в `$HOME/.secrets/`).

## Внешние источники по запросу (не vendored)

- `VKirill/yandex-direct-docs` - 520 md-страниц офиц. документации Директа (стратегии,
  таргетинги, кампании, модерация, API). LICENSE отсутствует, поэтому массово в репозиторий
  не вносим - фетчим по мере необходимости как справочник.
- `pavelmaksimov/tapi-yandex-direct` - Python-библиотека API (MIT), но без обновлений с 2021,
  совместимость с текущим API проверять отдельно.

## Дисциплина работы

Любая задача с цифрами (эффект на выручку, CPA, ROMI, бюджеты) проходит Protocol 9
(Reality Audit) до выводов. Каждая цифра помечается `[ДАННЫЕ]` (с источником) или
`[ГИПОТЕЗА]` (с допущениями). Критические артефакты - через Step 12.5 (ФЕНИКС).
