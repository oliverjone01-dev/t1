# Контракт данных

## Конверт одной цифры

Любое значение в `data/kontur.json` завёрнуто в пять полей. Четыре обязательны.

```json
{ "v": 444,
  "k": "ДАННЫЕ",
  "s": "keys.so через gg-seo-geo-monster/data/genglass/keysso.json",
  "at": "2026-09-07",
  "n": "" }
```

| Поле | Что значит |
|---|---|
| `v` | значение. Число или `null`, если выгрузки нет |
| `k` | класс: `ДАННЫЕ`, `ГИПОТЕЗА` или `ДЕМО` |
| `s` | источник: метод API или путь к файлу выгрузки |
| `at` | дата съёма, `ГГГГ-ММ-ДД` |
| `n` | примечание, может быть пустым |

Правила, которые проверяет сторож:

- класс только из трёх допустимых;
- у класса `ДАННЫЕ` обязателен непустой источник и дата в правильном формате;
- `v: null` с классом `ДАННЫЕ` запрещено: пустое значение это не данные.

## Классы

**ДАННЫЕ** - есть выгрузка, источник и дата. Можно нести собственнику.

**ГИПОТЕЗА** - бенчмарк, оценка или цифра, чей источник под сомнением. В план идёт
только пессимистичный сценарий. Пример: коэффициенты моста до денег, выгрузка
Директа, совпавшая у двух проектов.

**ДЕМО** - заглушка. Кабинет не подключён, выгрузки нет. Значение `null`.
Правдоподобное число вместо `null` запрещено: рядом с настоящими цифрами
заглушка перестаёт читаться как заглушка.

## Ряд позиций

`data/history/positions.ndjson`, по строке на проект и дату:

```json
{"ai_answers":84,"date":"2026-09-07","project":"gg","source":"keys.so",
 "top1":16,"top10":444,"top3":80,"top50":2145,"visibility":17}
```

Файл только дописывается. Повтор за тот же день перезаписывает строку, порядок
по дате. Пропущенный день не восстанавливается: у сводки домена в keys.so нет
ретроспективы, и это единственная причина, по которой файл вообще существует.

Имена полей в ряду и в интерфейсе различаются: `visibility` в ряду это `vis`
в сериях, `ai_answers` это `ai`. Карта соответствий одна, в `core.py`, константа `SF`.

## Добавить проект

Одна запись в `PROJECTS` в `tools/build_data.py`: код, папка выгрузки, имя,
домен и план выручки. Если для проекта есть свои внутренние факты, добавить их
в `FACTS`. Дальше пересборка данных и страницы. Ни строки в интерфейсе.

### Точка «в ряд ещё не записана»

Сборка добавляет в ряд свежий срез `keysso.json` на дату `measured`, чтобы карточка
и дельта считались по одной дате. В `positions.ndjson` эта точка попадает только
после прогона `tools/snapshot.py`. До тех пор она помечена источником
«срез keysso.json, в ряд ещё не записан»: если выгрузка обновится раньше прогона,
её значения топ-50 и ответов ИИ за этот день не сохранятся.

### Два числа визитов из поиска

`metrika.json` (поле `search_visits`) и `direct_metrika.json` (строка
`Search engine traffic`) дают по одному счётчику разные значения за один период:
первый фильтрует по `ym:s:lastTrafficSource`, второй группирует по
`ym:s:lastsignTrafficSource`. Обе цифры верные, это разные модели атрибуции.
Дашборд показывает обе и разницу между ними, выбирать одну молча нельзя.

### Список целей счётчика

`yandex-direct/data/raw/metrika-goals.json` снят руками 08.07.2026 при аудите
кабинета Директа (`yandex-direct/audit/2026-07-08-atomic-audit.md`) и ничем не
обновляется. Дата берётся из `git log` по файлу. В мелком клоне git приписывает
файл граничному коммиту, поэтому `git_file_date()` отбрасывает дату, если коммит
файла лежит на границе обрезанной истории; класс тогда понижается до ГИПОТЕЗА.
`kontur-snapshot.yml` клонирует репозиторий целиком (`fetch-depth: 0`).

### Конверсия заявки в сделку

`assum.crd` (11%) идёт как ГИПОТЕЗА: назван источник «Roistat GENGROUP, D2C»,
но выгрузки в репозитории нет.

### Цена заявки из рекламы

`direct.cpl` считается по одному прогону `direct-snapshots.yml`: расход из
`direct_daily.json`, заявки из `direct_metrika.json`, окно у них общее и
проверяется по `dateFrom`/`dateTo`. `v` делит расход на все заявки из рекламы
(105), `hi` на заявки, которые Метрика относит к Директу (101). Класс ГИПОТЕЗА:
оценкой цифру делает разнесение заявок по источникам, а не окна. Если окна
разошлись, цена заявки не считается.

### Чей кабинет Директа

`harvest.mjs` ходит в Директ одним `Client-Login` на все проекты и с пустым
`SelectionCriteria`, поэтому `direct.json` у всех проектов побайтно одинаковые:
это один кабинет. Чей он, задаёт константа `DIRECT_ACCOUNT_OWNER` в
`tools/build_data.py` (сейчас `genglass`). Основание: все шесть кампаний
«[На заказ] Перегородки», 22.09 клики равны кликам Директа по счётчику GENGLASS.
Сравнивать клики на каждой сборке нельзя: файлы пишут разные воркфлоу в разное
время, и равенство выполняется не каждое утро. У владельца выгрузка идёт как
ДАННЫЕ, у второго проекта `direct = null` и `direct_copy` с объяснением.
Если у проектов появятся свои кабинеты, файлы разойдутся, и каждый получит своё.

### План H2 и пороги собственника

`plan`, `thresh.mkt_share`, `thresh.roi_crisis`, `thresh.roi_ideal`,
`thresh.romi_plan` идут как ГИПОТЕЗА: они названы со ссылкой на Roadmap H2 и на
Богдана, но документа с ними в репозитории нет. Потолок маркетинга на экранах
собирается `CAPF()` и наследует класс от плана и доли.

### Демо-данных нет

Правдоподобных чисел на месте несобранных выгрузок в дашборде нет. Недельные ряды
строятся из дневного (`weekly()`), дерево разделов и вес страниц из выгрузки
топ-страниц, объём рекламы конкурентов из `ad_competitors`. Где выгрузки нет
вовсе (потерянные запросы, история выдачи, пересечения, конкуренты и источники в
ИИ, разбивка видимости по системам, индексация), экран говорит это плашкой.
