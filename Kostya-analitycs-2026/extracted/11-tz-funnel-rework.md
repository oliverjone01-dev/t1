Техническое задание на доработку воронки продаж «GG заказы»
Цель: Сохраняя существующую структуру стадий, внедрить систему контроля, автоматизацию и служебные элементы для повышения управляемости воронки и дисциплины в отделе продаж.
1. Действующие стадии воронки и уточнение их бизнес-логики
- Неразобранное: Заявки из любых источников. Требует разбора в течение __ рабочих часов (необходимо определить время здесь и далее во всем ТЗ и прописать в общем Регламенте отдела продаж)
- Новые заявки: Начало работы с заявкой. Первичный звонок/сообщение должен быть совершен в течение __ рабочих часов (очень важно быстро прорабатывать «теплые» заявки, чтобы конкуренты не оказались быстрее!)
- Взят в работу: Идет активный диалог с клиентом. Стадия для выяснения потребностей. Требует разбора в течение __ рабочих часов
- Квалифицирован: Транзитная стадия, на которой заявка должна находиться минимум времени, когда потребности выявлены и можно проводить техническую проработку. Требует разбора в течение __ рабочих часов
- Формирование ТЗ: Совместная проработка технической документации с конструкторским отделом. Требует разбора в течение __ рабочих часов/дней (обсудить и регламентировать в зависимости от сложности заказов)
- Отправлено КП: Клиент изучает предложение. Менеджер переходит в активный контроль принятия решения клиентом. Требует разбора в течение __ рабочих дней
- Принимают решение: Клиент подтвердил конкретные сроки принятия решения (например, 1-7 дней). Стадия для «горячих» клиентов с оговоренной датой. Требует поля «Дата решения клиента» (определить кол-во дней для категории «горячих клиентов»). Требует разбора по «Дата решения клиента»
- Предоплата получена: Необходимость финальной подготовки заявки для передачи в производство. Требует разбора в течение __ рабочих часов/дней (обсудить и регламентировать в зависимости от сложности заказов)
- Заказ в производстве: Отображение всех заказов, находящихся в производстве.
Требует поля "Дата изготовления", для визуального планирования готовности и других бизнес-процессов
- Заказ произведен: Отображение всех изготовленных заказов и готовых к отгрузке. Требует разбора в течение __ рабочих часов/
- Заказ отправлен: Отображение всех отгруженных заказов
2. Новые стадии для добавления (с обоснованием и расположением)
Счет отправлен
- Расположение: Добавить между стадиями «Принимают решение» и «Предоплата получена».
- Обоснование: В текущей воронке отсутствует критически важный этап - контроль оплаты счёта. Клиент может согласиться, но затянуть с оплатой. Эта стадия позволит отдельно контролировать процесс оплаты и автоматизировать напоминания.
- Логика: Сделка перемещается сразу после согласия клиента и выставления счёта. Стадия считается успешно пройденной при поступлении предоплаты.
Связаться позже (или Отложено)
- Расположение: Добавить как отдельную, заключительную стадию в этой же воронке, после «Заказ отправлен». Либо создать отдельную воронку «Отложенные сделки». Первый вариант проще для контроля.
- Обоснование: Для клиентов, которые назвали длинные сроки «размышления» по разным причинам (1-6 мес. – определить срок для стадии), но не отказали = потенциальные клиенты или «зависли» на активных стадиях после всех уведомлений. Позволяет не захламлять основные стадии и не портить конверсионную статистику, но сохраняет сделку в работе с плановой датой контакта.
- Логика: Сделка переносится вручную менеджером или автоматически по истечении лимитов на основных стадиях. Обязательно заполняется поле «Дата следующего контакта». Из этой стадии сделка может вернуться на «Взят в работу» или «Квалифицирован».
3. Автоматизация на каждой стадии (Роботы и триггеры amoCRM)
Автоматизация настраивается с помощью Роботов для сделок.
- Стадии «Новые заявки», «Взят в работу», «Квалифицирован», «Формирование ТЗ»*:
- Робот «Контроль времени - 1 уведомление»: При перемещении на стадию запускается таймер.
- Через N дней/часов (например, 1 дней) → Создать задачу ответственному менеджеру: «Проверить прогресс по сделке [Название]. Риск зависания». Добавить заметку в сделку.
*Примечание: В зависимости от бизнес-логики, можно назначить индивидуальные таймеры для конкретных стадий
- Робот «Контроль времени - эскалация РОПу»: Тот же таймер.
- Через N+M дней (например, +1, итого 2 дня) → Создать задачу РОПу и менеджеру с высоким приоритетом: «Сделка [Название] зависла на стадии [Стадия]. Требуется решение: актуализировать или перенести в 'Связаться позже'».
- Стадия «Отправлено КП»:
- Робот «Уточнить результат КП»:
- Через 1 рабочий день → Создать задачу менеджеру: «По сделке [Название] отправлено КП. Уточните у клиента результат рассмотрения».
- Через 3 рабочих дня → Создать задачу менеджеру и РОПу: «Клиент не дал обратную связь по КП [Название]».
- Стадия «Принимают решение»:
- Обязательное поле: При перемещении на эту стадию робот должен требовать заполнения кастомного поля «Дата решения клиента».
- Робот «Напоминание о дате решения»:
- В день «Даты решения клиента» → Создать задачу менеджеру и РОПу: «Уточнить решение по сделке [Название] сегодня».
- Новая стадия «Счет отправлен»:
- Робот «Контроль оплаты счета»:
- Через 1 рабочий день после входа на стадию → Создать задачу менеджеру: «Уточнить у клиента статус оплаты счета по сделке [Название]».
- Через 2 рабочих дня → Создать задачу менеджеру и РОПу: «Счет по сделке [Название] не оплачен. Требуется эскалация».
- Новая стадия «Связаться позже»:
- Обязательное поле: При перемещении на эту стадию робот должен требовать заполнения поля «Дата следующего контакта».
- Триггер/Робот: За 1 день до "Даты следующего контакта" → Создать задачу менеджеру: «Возобновить контакт по отложенной сделке [Название]».
4. Инструменты контроля отдела продаж для РОП и директора в AMO
- Дашборды (Аналитика):
- «Сделки в работе с просрочкой»: Виджет «Список сделок» с фильтром: Этап = «Воронка продаж GG заказы» + Дней на стадии > X (где X - выбранный лимит для каждой стадии). Сделки сортируются по количеству дней.
- «Задачи с просрочкой по менеджерам»: Виджет «Задачи» с фильтром Ответственный + Статус = «Просрочено». Позволяет видеть дисциплину.
- «Конверсия по этапам»: Виджет «Воронка продаж» по всей воронке «GG заказы» и индивидуально по менеджерам за выбранный период.
5. Общие советы по улучшению отдела продаж
- Запуск «недели чистоты»: Перед внедрением общей автоматизации вручную разобрать текущие «зависшие» сделки. Перенести на стадию «Связаться позже» потенциальные «отложенные» сделки (перед этим автоматизировать заполнение обязательного поля).
- Введение единых правил игры: Провести встречу, где утвердить новые правила: что такое «зависание», как заполнять «Дату решения», когда переносить в «Связаться позже». Зафиксировать в Регламенте.
- Контроль через задачи, а не через сделки: приучить РОПа и директора контролировать не столько стадии сделок, сколько исполнение задач (особенно созданных роботами). Просроченная задача - явный индикатор проблемы.
- Итеративная настройка: Запустить автоматизацию сначала с «мягкими» лимитами (например, не 1, а 2 дня). Через несколько недель собрать обратную связь от менеджеров, проанализировать отчеты и отрегулировать тайминги роботов под реальную скорость работы компании.
Мы усиливаем текущую воронку, не меняя её структуру. Основные улучшения - две новые стадии для контроля оплаты и отложенных сделок, система роботов-контролёров на каждой стадии и набор конкретных инструментов для визуализации проблем руководством. Это сделает процесс более предсказуемым и управляемым.
