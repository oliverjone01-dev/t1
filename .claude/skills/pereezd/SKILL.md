# pereezd - переезд в новую сессию

Цель: пользователь не следит за лимитами и не открывает окна руками. Длинная сессия дорогая
(каждый ход заново перечитывает весь контекст) и тупеет (важное тонет в шуме). Переезд
короткий и автоматический: пользователь видит одну строку «переезд» и ссылку на новую сессию.

## Когда

| Сигнал | Действие |
|---|---|
| Метка хука `[pereezd] ... ОБЯЗАТЕЛЕН` (контекст от 200K) | Переезд сразу. Текущий запрос пользователя уходит в новую сессию дословно |
| Метка хука о 150K и выше | Доделать текущий шаг, переехать на ближайшей точке сохранения |
| Метка хука «кэш остыл» | Переехать, если запрос начинает новую задачу |
| Закрыта крупная подзадача (PR смержен, модуль готов), дальше другая тема | Переехать |
| Пользователь сказал «переезд» или `/pereezd` | Переехать |
| Пользователь написал «без переезда» | Не переезжать в этом ходе |

Не переезжать посреди правки: сначала довести изменение до рабочего коммита.
Хука нет (сессия без репозитория)? Размер контекста: `get_session` без `session_id`,
поле `external_metadata.context_usage.used_tokens`.

## Порядок

### 1. Объявить
Одна строка: «Переезд: контекст NNNK, сохраняю и открываю <название>. Секунду.»
Разрешения не спрашивать.

### 2. Сохранить работу
- `git status`: всё несохранённое закоммитить осмысленным сообщением и запушить в текущую
  рабочую ветку. Только не-main: если сессия стоит на main, сначала завести рабочую ветку.
- Критический артефакт (Step 12.5 в CLAUDE.md) без вердикта ФЕНИКСА: в коммите префикс `WIP:`,
  в передаточном файле пометка «аудит не пройден» с перечнем таких артефактов.
- Нужные дальше файлы из `/tmp` или скрэтчпада перенести в репозиторий, иначе назвать их
  в передаточном файле как «утеряно при переезде».

### 3. Передаточный файл
Путь: `sessions/handoff/<ГГГГ-ММ-ДД>-<проект>-<задача>-v<N>.md` (латиница, дефисы),
по шаблону `sessions/handoff/_TEMPLATE.md`. Бюджет до ~4K токенов: выжимка, а не пересказ.
Разделы шаблона обязательны все. Решения, принятые с пользователем, записать в раздел
«Решения», а долгоживущие ещё и одной строкой в `knowledge/decisions.md`; проверенные
цифры с источником в `knowledge/facts.md`.

Самопроверка: сможет ли сильный специалист, не видевший этот чат, продолжить по файлу без
единого вопроса? Если нет, дописать. Коммит и пуш.

### 4. Фон старой сессии
- `list_triggers`: включённые рутины с `persistent_session_id` этой сессии. Разовые чек-ины
  удалить (`delete_trigger`). Нужна проверка - новая сессия поставит свою по правилам ниже.
- Открытые PR: `unsubscribe_pr_activity` здесь, подписку оформит новая сессия.

### 5. Новая сессия
- `get_session` без аргументов: repo URL из `session_context.sources`, ветка из `outcomes`
  или `external_metadata.current_branches`, модель из `session_context.model`.
- Название `<Проект> - <Задача> - v<N+1>` в принятом стиле («МЕА - Дашборд ОЗОН - v3»).
  Коротко, по-русски, без дат. Номер неизвестен - прошлая считается v1.
- `create_session`: `title`; `source_url` = repo URL; `source_revision` и `outcome_branch` =
  текущая ветка; `model` = та же, что сейчас (модель не понижать: экономия идёт на длине
  контекста, а не на качестве мышления); `prompt` = стартовый промпт ниже;
  `permission_mode` не передавать.

Стартовый промпт:

```
Ты продолжаешь цепочку «<Название>» (v<N+1>). Прошлая сессия: https://claude.ai/code/<старый id>.
1. Прочитай CLAUDE.md и sessions/handoff/<файл>.md целиком. Историю переписки не ищи, всё нужное в файле.
2. Раздел «Решения» не пересматривай, сделанное не переделывай.
3. Одной строкой подтверди пользователю: что за цепочка и какой следующий шаг.
4. Выполни «Следующий шаг».<если был незакрытый запрос:> Затем запрос пользователя дословно: «...»
5. Открытые PR из раздела «Фон»: subscribe_pr_activity. Чек-ины только по правилам скилла pereezd.
Работай на ветке <ветка>.
```

### 6. Отчёт
- `get_session(<новый id>)`: сессия создана.
- Старую переименовать (`set_session_title`): `<старое название> -> перенесено в v<N+1>`.
  Не архивировать: пользователь может захотеть заглянуть назад.
- Пользователю: «Готово. Продолжаем в <название>: https://claude.ai/code/<новый id>».
  В старой сессии больше ничего не делать.

## Правила чек-инов
- GitHub сам будит сессию на CI, ревью и мерж. Чек-ин только страховка.
- Первый через ~50 минут, дальше раз в 4 часа. С 23:00 до 08:00 МСК не ставить.
- После 3 пустых проверок подряд остановиться.
- Никогда не ставить шаг около 60 минут: кэш живёт час, каждое пробуждение станет полным
  промахом и перепишет весь контекст по полной цене.
- Опрос чатов и страниц каждые несколько минут запрещён: нужен webhook (`watch_url`, n8n).
- Длинная слежка (PR, деплой) живёт в отдельной маленькой сессии на Sonnet, а не в рабочей.

## Чего не делать
- Не спрашивать разрешения на переезд.
- Не понижать модель и не выключать режим мышления.
- Не класть в handoff сырые логи, дампы и выводы инструментов. Только выводы и ссылки.
- Не переезжать, если несохранённое не пушится. Сказать, в чём проблема.
