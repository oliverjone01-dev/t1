# Регламент обновления

## Раз в неделю, пятница (сверка руками)

```bash
cd kontur-dashboard

# 1. Убедиться, что свежие выгрузки keys.so приехали
#    (их кладёт .github/workflows/harvest.yml, ежедневно в 03:00 МСК;
#     keyso-collect.yml собирает другое - рынок конкурентов, раз в неделю)
ls -l ../gg-seo-geo-monster/data/genglass/keysso.json

# 2. Записать точку в дневной ряд. Это то, что не восстановится задним числом
python3 tools/snapshot.py

# 3. Пересобрать блок данных
python3 tools/build_data.py

# 4. Пересобрать страницу
python3 src/build.py

# 5. Проверить
python3 tools/check_dash.py      # сторож: цифры, палитра, запреты, ряд
python3 tools/snapshot.py --check # ряд без разрывов и не просрочен
node   tools/smoke.mjs           # все экраны в двух темах и на трёх периодах

# 6. Закоммитить data/ и public/
```

Шаги 2-5 делает и воркфлоу `kontur-snapshot.yml` по расписанию. Ручной прогон
нужен, когда выгрузка пришла вне расписания или после правок в интерфейсе.

## Что делать, если сторож упал

Он не капризничает: каждая проверка стоит за конкретной ошибкой, которая уже
случалась. Разбор по коду:

| Код | Что случилось | Что делать |
|---|---|---|
| `EMDASH` | в текст попало длинное тире | заменить на дефис |
| `NOSRC` `NODATE` | у цифры класса ДАННЫЕ нет источника или даты | заполнить конверт |
| `NULLDANN` | пустое значение помечено как ДАННЫЕ | поставить класс ДЕМО |
| `KIND` | класс не из трёх допустимых | исправить на ДАННЫЕ, ГИПОТЕЗА или ДЕМО |
| `BAN` | в текст попал запрещённый факт | убрать, список в `check_dash.py` |
| `COLOR` | цвет в графике мимо палитры | взять из `docs/PALETTE.md` |
| `CVD` | синий и голубой встали соседними сериями | переставить слоты |
| `DUALAXIS` | две оси Y на одном графике | привести ряды к индексу |
| `EMPTY` | контейнер графика без кода отрисовки | дописать в `draw.py` |
| `NOVIEW` | пункт меню без экрана | добавить экран или убрать пункт |
| `GAP` | разрыв в ряду больше двух недель | снять пропущенные точки, если ещё возможно |
| `NOHIST` `SHORTHIST` | ряда нет или в нём одна точка | `python3 tools/snapshot.py --seed` |

## Проверка сторожа

Сторож, который всегда зелёный, бесполезен. Раз в месяц:

```bash
python3 tools/tamper.py     # ждём: 18 из 18
```

Скрипт подсовывает восемнадцать заведомо испорченных версий и требует, чтобы
сторож поймал каждую. Если поймал меньше, чинить надо сторожа, а не данные.

## Добавить проект

1. Запись в `PROJECTS` в `tools/build_data.py`: код, папка выгрузки, имя, домен, план.
2. При наличии внутренних фактов - запись в `FACTS`.
3. Кнопку проекта в шапке в `src/modules/shell.py`.
4. `python3 tools/build_data.py && python3 src/build.py`.

## Публикация

`.github/workflows/deploy-pages.yml`, шаг «Build KONTUR dashboard». Копирует
`kontur-dashboard/public/` в `/kontur/` на сайте. Отдельной сборки не требует:
в `public/index.html` уже всё вшито.

## Дымовой тест вне песочницы автора

`tools/smoke.mjs` берёт зеркала tailwind и apexcharts из каталога `KONTUR_LIBS`
(по умолчанию `/tmp/claude-0`), пишет страницу в `KONTUR_TMP`, браузер берёт из
`KONTUR_CHROMIUM` или ставленный playwright. Файлы зеркал: `tw.js` (play-CDN
Tailwind или заранее скомпилированный Tailwind 3 под классы страницы) и `apex.js`
(ApexCharts 3.54.1). Код выхода проверять отдельно от вывода: тест печатает
счётчики до прохода на 390 px, а ошибки этого прохода выводит последней строкой.

## Публикация и пароль

Решение Ивана от 23.09.2026: данные на опубликованной странице шифруются, а не
прячутся за хэшем пароля. Шаг `Build KONTUR dashboard` в `deploy-pages.yml`
прогоняет `tools/seal_page.mjs`: весь основной скрипт страницы (данные, экраны,
оболочка) заменяется шифротекстом AES-256-GCM, ключ выводится из пароля через
PBKDF2-SHA256 на 600 000 итераций. Схема та же, что у академии. В открытом виде
остаются только стили, пустая разметка и окно пароля.

Пароль берётся из секрета репозитория **`KONTUR_PASS`**, не короче 12 знаков.
Общий `HUB_PASS` не используется намеренно: `/seo/` публикует его быстрый SHA-256,
и по нему пароль подбирался бы офлайн в обход PBKDF2.

- секрета нет: раздел не публикуется, в логе `::warning::`, остальной сайт уезжает;
- пароль короче 12 знаков: раздел не публикуется, причина в логе шага;
- после шифрования в файле нашлись открытые данные: `::error::`, раздел не публикуется.

Локальная сборка (`src/build.py`) не шифруется и открывается без пароля: сторож,
`tamper.py` и дымовой тест работают с ней. Проверить шифрование руками:
`KONTUR_PASS='...' node tools/seal_page.mjs <копия index.html>`.

Смена пароля: поменять секрет и перезапустить деплой. Открытые вкладки держат
ключ в `sessionStorage` до закрытия, новая вкладка спросит новый пароль.
