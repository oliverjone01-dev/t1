# ТЗ для Cowork: унифицировать фильтр периода вкладки «Реакция» с общим фильтром дашборда

## Цель
Убрать собственные кнопки периода «Реакции» (7 дней / 14 дней / 30 дней / весь период) и подчинить
вкладку **общему верхнему фильтру дашборда KATYA** (тот же ряд, что на Обзоре/Товарах/Деньгах).
Один фильтр на весь дашборд, «Реакция» на него реагирует.

## Контракт общего фильтра (как он устроен в build-katya.ts / kshell)
Верхняя панель периодов (общая для всех вкладок KATYA):
```
<div class="periods" id="periods">
  <button class="pb" data-p="today">Вчера</button>
  <button class="pb" data-p="7d">7 дн</button>
  <button class="pb act" data-p="30d">30 дн</button>
  <button class="pb" data-p="90d">90 дн</button>
  <button class="pb" data-p="year">Год</button>
  <button class="pb" data-p="all">Всё время</button>
  <button class="pb range" id="btn-range">Свой</button>  (+ range-from/range-to/#range-apply)
</div>
```
Клиентский контракт (в kshell):
- `window.__GG_MAXD` - последний день данных продаж (клампит верхнюю границу).
- `const MAXD`, `FLOOR='2026-02-06'`.
- `CURP` - текущий ключ периода (today/7d/30d/90d/year/all/range).
- `periodDates(p)` -> `{from, to}` (YYYY-MM-DD).
- `applyPeriod()` при смене периода выставляет **`window.__guruPeriod = {curFrom, curTo, cmpFrom, cmpTo}`**
  и переключает `.pb.act`. Кнопки: `document.querySelectorAll('.pb[data-p]')` + клик -> applyPeriod.
- Выбор периода запоминается в `localStorage['gg_katya_period']`.

## Что сделать (предпочтительный путь - переиспользовать общий каркас)
1. Собирать страницу «Реакция» через **тот же `kshell`**, что и остальные вкладки (build-katya.ts):
   `kshell(title, activeKey, body, pageJs)`. Тогда «Реакция» получает общий баннер + общий ряд периодов
   + контракт периода автоматически. Свою верхнюю панель 7/14/30/весь - **убрать**.
2. Приложение «Реакции» переписать так, чтобы оно бралo период из **`window.__guruPeriod.curFrom/curTo`**
   (или `periodDates(CURP)`), а не из своих кнопок. На каждое изменение периода пересчитывать фид/воронку/KPI
   за `[curFrom, curTo]`. Подписаться на клики `.pb[data-p]` (или дернуть общий `applyPeriod`), как это
   делают другие вкладки.
3. Если переиспользовать kshell нельзя (своя тяжёлая вёрстка) - как минимум читать тот же контракт
   (`__guruPeriod`, `periodDates`, `CURP`, тот же localStorage-ключ), чтобы период был сквозной.

## ОБЯЗАТЕЛЬНО - честность данных (§15, иначе ФЕНИКС вернёт)
Данные «Реакции» - ручной срез ограниченной глубины (поле `data_until` в reakciya.json, сейчас 09.09).
Общий фильтр предлагает 90 дней / Год / всё время, которых в срезе может НЕ быть. Нельзя рисовать
пустые/частичные графики как факт:
- Периоды, выходящие за пределы среза, честно гасить: «нет данных за период» ИЛИ ограничить `to` по
  фактическому покрытию среза с подписью «данные Реакции по <data_until>».
- Не смешивать: у дашборда данные продаж до `MAXD` (напр. 15.09), у «Реакции» своя `data_until` (09.09) -
  подписать расхождение, не выдавать 15.09 за покрытие «Реакции».
- Если за выбранный период в срезе нет действий/воронки - показать пустое состояние, а не нули как данные.

## Источник правды и порядок (чтобы не разъехалось)
- Правку делать в **одном** источнике сборки страницы. Уточни у Ивана/в репо: страницу «Реакция»
  собирает репозиторный `build-reakciya.ts` (+ `katya/reakciya/*`) через `npm run katya`, или твой
  пакет на маке (`build/make.py`) деплоит готовый HTML. Правь там, откуда реально берётся боевая страница,
  иначе следующий деплой перезатрёт.
- После правки: `npm run katya && npm run smoke` (8 вкладок / 20 страниц OK), проверить, что смена периода
  на «Реакции» реально меняет цифры, и что периоды без данных гаснут честно.
- Сохранить фикс `window.onerror` (глушить только на загрузочной карточке), иначе smoke даст ложный OK.
- Оформление: только дефис `-`, без длинного тире; внешних ссылок нет.

## Приёмка
1. На «Реакции» нет своих кнопок 7/14/30/весь - только общий верхний ряд периодов.
2. Переключение общего периода (7д/30д/90д/Год/всё/Свой) меняет фид/воронку/KPI «Реакции».
3. Период сквозной: выбрал на «Деньгах» 7 дней -> на «Реакции» тоже 7 дней (общий localStorage-ключ).
4. Периоды без данных в срезе - честное «нет данных за период», не пустые графики.
5. `npm run katya` 8 вкладок, `npm run smoke` 20/20, длинного тире / внешних ссылок нет.
