# TURBIUM - визуалы для сайта

Отдельный проект в общем монорепозитории. Внешний клиент, не бренд GENGROUP:
бренд-токены пяти брендов холдинга сюда не переносятся. Из корня берём только
дисциплину: anti-slop, запрет em dash, ФЕНИКС (Step 12.5) перед сдачей клиенту.

## Что делаем
Промты для генерации фото-визуалов сайта/лендинга TURBIUM в OpenAI GPT Image
(API `gpt-image-2`; id модели меняется через `OPENAI_IMAGE_MODEL`).
Графика с цифрами, схемы и текст на картинке не генерируются: они верстаются
поверх фото на сайте (резче, правится без перегенерации, ноль дрейфа).

## Структура
| Файл | Что внутри |
|---|---|
| `brief.md` | Бриф клиента: продукт, ЦА, айдентика, разделы сайта. **Заполнить первым** |
| `prompts/method.md` | Как устроен промт под GPT Image: 8 слотов, style-lock, что запрещено |
| `prompts/site.json` | Набор кадров сайта: style-lock + промт на каждый кадр с плейсхолдерами |
| `scripts/generate.py` | Подставляет бриф в промты, печатает их или генерирует через API |
| `out/` | Результаты генерации (не коммитятся, см. `.gitignore`) |

## Порядок работы
1. Заполнить `brief.md` и блок `subject` в `prompts/site.json`.
2. Проверить промты без API: `python3 turbium/scripts/generate.py --dry-run`.
   Скрипт откажется генерировать, пока в промтах остались `{{плейсхолдеры}}`.
3. Генерация: `OPENAI_API_KEY=... python3 turbium/scripts/generate.py`
   (или вставить напечатанные промты в ChatGPT Images вручную).
4. Отбор кадров, при дрейфе - правка style-lock, а не отдельных промтов.
5. ФЕНИКС-аудит набора перед отправкой клиенту.
