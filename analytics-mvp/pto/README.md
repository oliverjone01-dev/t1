# ПТО · запуски расчётов

Дашборд отдела ПТО: все входы сделок на стадию «Расчёт» воронки «GG RF Заказы»
(категория 49), что с ними стало дальше и как они распределены по дням месяца.

Собран под конкретный вопрос Ивана: правда ли, что к концу месяца в расчёт
передают больше. Страница отвечает распределением, нормированным на рабочие дни,
и перестановочным тестом, а не ощущением.

## Сборка

```bash
# снимок Bitrix берём из ветки данных РОПа (тот же, что у /rop/)
git fetch --depth=1 origin rop-dashboard-v1
git show FETCH_HEAD:analytics-mvp/rop/data/rop.json > /tmp/rop.json

cd analytics-mvp
ROP_JSON=/tmp/rop.json npx tsx src/scripts/b24/build-pto.ts
# -> public/pto-command.html, самодостаточный HTML с запечёнными данными
```

Деплой копирует `public/pto-command.html` в `_site/pto/index.html`
(шаг «Build PTO dashboard» в `.github/workflows/deploy-pages.yml` на main).

## Методическая мина, на которой я уже подорвался

Перестановочный тест считает ГПСЧ. Наивный LCG вида `seed*1103515245+12345`
в JavaScript **непригоден**: произведение выходит за 2^53, double теряет младшие
биты, и тест выдал p=0.018 вместо честных 0.063. Сейчас стоит mulberry32 на
`Math.imul`, результат сверен с независимым прогоном на Python (0.062) и
с нормальным приближением биномиального (0.055).

Любая правка этого места проверяется тем же способом: пересчёт на втором языке.
