# Классы ошибок К1-К14

Источник: ретро 337 переделок в 9 чатах аналитики (06-09.2026). Обезличено. Конкретные случаи с коммитами: `knowledge/errors/registry.jsonl`.


К1. Метрика определена после кода: формула/база дат/статусы меняются на ходу (CR1 3 определения, конверсия 5 формул за день, "Выкуплено" 3 формулы, дата доставки 4 раза, "Оборот" 3 базы).
К2. Разные базы в числителе и знаменателе: показатели >100%, несопоставимые стрелки, "стакан 36 против успех 14".
К3. Блок игнорирует выбранный период/фильтр (7 раз), или окно N дней = N+1, TZ-сдвиг (toISOString, UTC против МСК) обнуляет ячейки.
К4. Двойной учёт: пропорциональное разнесение остатка, "добор" (документ минус разнесённое на другой дате), дубли проводок без ключа, бюджет сделки по карточкам, с/с итог+компоненты, дедуп схлопывает настоящие дубли.
К5. Сверка против самого себя или того же семейства источников; "сумма сошлась" как валидация; сравнение разных срезов (месяц отчёта против месяца заказа) как ошибка данных.
К6. Контракт API/полей не проверен до кода: лимиты (1 месяц на запрос, 1 активный отчёт, 429), английские коды вместо русских названий, колонки угаданы, эндпоинт не про то (заявки на возврат вместо рефандов), deprecated эндпоинт, legacy-поле CRM пустое, поле closed = плановая дата у открытых сделок, пагинация, неактивные пользователи.
К7. Пропуск показывается нулём, пустое окно числом; сборщики fail-open (|| echo warning, exit 0), тихая заморозка данных, перезапись файла целиком пустым/дефолтным диапазоном (cron с дефолтом стёр 3 месяца), неполный день без пометки.
К8. Бизнес-контекст не выяснен до кода: удалённые стадии воронки, мигрированные из другой CRM сделки, двойные профили сотрудников, уволенные, цех в метриках продаж, отмены/возвраты в продажах, аббревиатура понята неверно, письмо заказчика прочитано неверно.
К9. Логика в нескольких копиях: нормализация SKU, поиск себестоимости, дедуп, копии шаблонов дашбордов; правка в сгенерированном HTML вместо билдера; частичный фикс (поправили в одном месте).
К10. Утверждения сильнее данных: "сошлось", "закрыто", "API не отдаёт", "нет намеренно", ложные инсайты на малой выборке, подписи на странице обещают то, чего нет.
К11. Гейт ревью формальный: мерж до аудита, поверх return/veto, без повторного аудита.
К12. Git/CI/автоматика: генерируемые данные в одной ветке с кодом (десятки мержей и конфликтов), бот пушит в рабочую ветку, squash без пересоздания ветки, трейс-коммиты и петли пробуждений, запуск пересбора не на той ветке, cron best-effort и опоздания, невалидный YAML, хендоффы не в main, тесты на литералах дат, CI без тестов.
К13. Безопасность и мутации: PII в публичном репо, деплой до гейта, секреты через input, записи в боевой API рекламного кабинета без журнала/апрува.
К14. Статистика: подгонка окна (argmin p), малые выборки, неверный тест, LCG-переполнение, выводы о причинности без контроля, мёртвый контроль в A/B.

Стек: TypeScript/Node билдеры статичных HTML-дашбордов, Python-скрипты, GitHub Actions cron-снимки в репо, источники: Ozon Seller API (finance/accrual, postings, performance ads), Яндекс Маркет Partner API, Bitrix24 REST (сделки, стадии, таймлайн), Яндекс Директ API v5 + Метрика, Google Sheets, xlsx-ведомости перевозчиков.
